# 系统负载高分析 - 知识梳理

## 第一章 系统负载概念

### 1.1 负载定义

**传统Unix系统（BSD）：**
- 负载 = 正在运行的线程数 + 可运行的线程数
- 反映CPU饱和度
- 例：4核CPU，负载持续高于4表示CPU资源饱和

**Linux扩展定义：**
- 负载 = R状态线程数 + D状态线程数 + 可运行线程数
- 反映整个系统的繁忙程度（CPU + IO）
- Linux认为D状态消耗磁盘等资源，也应计入负载

### 1.2 Load Average 指标

**uptime 与 top 命令显示的load average包含3个值：**
- 第1个值：1分钟平均负载
- 第2个值：5分钟平均负载
- 第3个值：15分钟平均负载

**趋势判断：**
- `1分钟 > 5分钟 > 15分钟` → 系统压力递增
- `1分钟 < 5分钟 < 15分钟` → 系统压力递减

## 第二章 Linux线程状态

### 2.1 关键线程状态

| 状态 | 代码 | 含义 | 对负载影响 |
|-----|------|------|----------|
| 正在运行 | R(run) | CPU正在执行线程 | **直接影响负载** |
| 可运行 | R(runnable) | 等待CPU调度 | **直接影响负载** |
| 睡眠 | S | 被阻塞等待唤醒（可中断） | 不影响负载 |
| 不可中断睡眠 | D | 等待磁盘IO完成（不可中断） | **直接影响负载** |
| 其它阻塞 | - | 网络IO、锁等待 | 不影响负载 |

### 2.2 R状态 vs D状态

**R状态（可运行/正在运行）：**
- 消耗CPU资源
- 直接反映CPU压力
- ps查看：处于`R`状态

**D状态（不可中断睡眠）：**
- 不消耗CPU资源
- 消耗磁盘/IO资源
- 线程无法被中断，持续占用系统资源
- 一般由磁盘IO操作导致（kernel_clone等内核函数）
- ps查看：处于`D`状态

## 第三章 系统负载高的原因分析

### 3.1 两类主要场景

| 场景 | 主要状态 | 表现 | 对应工具 |
|-----|--------|------|--------|
| **CPU密集** | R状态高 | CPU使用率高，可运行队列长 | top/vmstat |
| **IO密集** | D状态高 | 磁盘IO频繁，进程被IO阻塞 | iostat/ps |

### 3.2 定位D状态线程的方法

#### 方法一：ps + wchan字段
```bash
ps aux | grep D
# wchan 显示线程当前被阻塞在什么内核函数上
```
- 查看线程阻塞的内核函数
- 快速了解线程在做什么

#### 方法二：/proc伪文件查看内核栈
```bash
cat /proc/$pid/task/$tid/stack
```
- 显示线程阻塞时的内核调用栈
- 可追踪系统调用链（如vfork → kernel_clone）

#### 方法三：bcc的offcputime命令
```bash
offcputime --state 2
```
- `--state 2` 过滤仅D状态线程
- 显示offcpu栈（线程何时进入D状态）
- 精准追踪问题线程

### 3.3 案例：vfork导致负载高

**现象：**
- 负载升到接近100
- ps查看发现大量D状态线程

**根源追踪：**
1. ps查看 → D状态线程阻塞在`kernel_clone`函数
2. 查看/proc/$pid/task/$tid/stack → 发现由`vfork`系统调用发起
3. offcputime --state 2 → 确认D状态线程栈指向vfork系统调用

## 第四章 诊断工具与命令

### 4.1 uptime 命令
```bash
uptime
# 输出：11:23:45 up 10 days,  2:34,  2 users,  load average: 2.15, 1.80, 1.45
```
- 显示系统运行时长
- 显示3个load average值
- 快速判断系统负载趋势

### 4.2 top 命令
```bash
top
# 显示PID、STATE(R/S/D)、CPU%、MEM%
```
- 实时查看进程状态
- 观察R状态线程数量
- 识别CPU密集进程

### 4.3 ps 命令
```bash
ps aux
ps -eo pid,tid,stat,wchan,cmd
```
- `STAT` 列显示线程状态（R/S/D/Z）
- `WCHAN` 显示阻塞内核函数
- 静态快照，便于记录

### 4.4 vmstat 命令
```bash
vmstat 1 10  # 每秒采样，共10次
```
- 查看可运行队列长度（r列）
- 观察context switch次数
- 判断CPU竞争情况

### 4.5 /proc伪文件系统
```bash
cat /proc/$pid/task/$tid/stack
cat /proc/loadavg
```
- `stack` 显示线程内核栈
- `loadavg` 显示负载信息

### 4.6 bcc offcputime命令
```bash
offcputime -p $pid --state 2
```
- `--state 2` 仅显示D状态线程
- 显示线程离开CPU的时间和地点
- 精准定位IO等待

## 第六章 速查表

### 6.1 常用命令速查

| 任务 | 命令 | 关键输出 |
|-----|------|--------|
| 查看负载趋势 | `uptime` | load average: 2.15, 1.80, 1.45 |
| 实时进程监控 | `top` | PID, STAT(R/D/S), %CPU, %MEM |
| 查看线程状态 | `ps aux` 或 `ps -eo pid,stat,wchan,cmd` | STAT列(R/D/S), WCHAN列 |
| 查看可运行队列 | `vmstat 1 10` | r列(运行队列长度) |
| 查看内核栈 | `cat /proc/$pid/task/$tid/stack` | 完整调用栈 |
| 查看负载信息 | `cat /proc/loadavg` | 5个数值 |
| 精准追踪D线程 | `offcputime -p $pid --state 2` | D状态线程栈 |

### 6.2 故障诊断快速流程

```
第1步：判断负载类型
  $ uptime
  → 看1/5/15分钟值的大小关系

第2步：区分R状态 vs D状态
  $ ps aux | grep -E "^\s*[UD]"
  或
  $ ps -eo pid,stat,comm

第3步：定位具体进程
  R状态高：$ top -p $pid -o %CPU
  D状态高：$ ps -eo pid,stat,wchan,cmd | grep D

第4步：查看阻塞原因
  $ cat /proc/$pid/task/$tid/stack
  $ offcputime --pid $pid --state 2

第5步：制定优化方案
  R状态 → 代码优化/资源扩容
  D状态 → IO优化/磁盘替换
```

### 6.3 关键指标解读

| 指标 | 含义 | 正常范围 | 过高表现 |
|-----|------|--------|--------|
| load average (1min) | 1分钟平均负载 | 0 ~ CPU核数 | > CPU核数 |
| load average (5min) | 5分钟平均负载 | 0 ~ CPU核数 | > CPU核数 |
| load average (15min) | 15分钟平均负载 | 0 ~ CPU核数 | > CPU核数 |
| R状态线程数 | 可运行线程数 | ~CPU核数 | >> CPU核数 |
| D状态线程数 | 不可中断线程数 | 接近0 | > 5个 |
| %CPU (top) | 单进程CPU使用率 | 0-100% | > 50% |
| Context Switch | 上下文切换次数 | < 5000/s | > 10000/s |

### 6.4 常见阻塞内核函数

| 内核函数 | 表现 | 可能原因 |
|---------|------|--------|
| `kernel_clone` | D状态线程 | fork/vfork系统调用 |
| `do_wait` | D状态线程 | 等待子进程 |
| `get_page_from_freelist` | D状态线程 | 内存页分配 |
| `sys_read` | D状态线程 | 磁盘IO读等待 |
| `sys_write` | D状态线程 | 磁盘IO写等待 |
| `poll_schedule_timeout` | S状态线程 | 网络IO等待 |

## 第七章 ⚠️ 原文勘误

### 勘误1：Linux负载定义表述

**原文位置**：第3501行
```
"Linux负载由正在运行、可运行及D状态这3个部分的线程数量组成。"
```

**勘误内容**：
- 原文表述不够准确，应为"R状态（包括正在运行和可运行）及D状态"
- 第3496行已明确R状态包括"正在运行或可运行状态"
- 建议改为："Linux负载由R状态（正在运行或可运行）及D状态的线程数量组成"

**影响等级**：⚠️ 中等（易引起概念混淆）

### 勘误2：load average含义遗漏

**原文位置**：第3484-3488行
```
"关注load average后的3个值，分别代表1分钟、5分钟、15分钟的系统平均负载"
```

**勘误内容**：
- 原文未明确说明load average的第4个值
- `/proc/loadavg` 实际显示5个值，但uptime/top仅显示前3个
- 建议补充说明：第4、5个值为运行队列中的进程数和最后运行的进程PID

**影响等级**：⚠️ 低（不影响主要诊断）

### 勘误3：状态列表不完整

**原文位置**：第3495-3498行
```
"- R: 正在运行或可运行状态
- S: 睡眠状态，被阻塞等待唤醒
- D: 不可中断(uninterruptible)睡眠状态，一般是等待磁盘io完成"
```

**勘误内容**：

- 虽然在负载分析中R和D最关键，但完整性应提高

**影响等级**：⚠️ 低（本章重点已涵盖）
