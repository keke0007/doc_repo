# 03. 硬件资源观测梳理

## 1. 概述

硬件资源观测是故障定位的基础。系统有 **CPU、内存、磁盘、网络** 这 4 种常见硬件资源，需通过 USE 法观测各个资源的**使用率/饱和度/错误**指标。

---

## 2. CPU/内存资源观测

### 2.1 top 命令

#### 功能概览
- **总任务数**：正在运行/睡眠/暂停/僵尸任务数
- **系统负载**：1min/5min/15min 的平均负载
- **内存使用**：总内存、空闲内存、使用内存、buff/cache

#### CPU 时间占比指标
| 指标 | 含义 |
|------|------|
| **us** | 非 niced 进程花费的 CPU 时间占比 |
| **sy** | 内核进程花费的 CPU 时间占比 |
| **ni** | niced 进程花费的 CPU 时间占比 |
| **id** | 内核空闲进程花费的 CPU 时间占比 |
| **wa** | 等待磁盘 IO 完成花费的 CPU 时间占比 |
| **hi** | 处理硬件中断花费的 CPU 时间占比 |
| **si** | 处理软件中断花费的 CPU 时间占比 |
| **st** | 被其它虚拟机偷取的 CPU 时间占比 |

#### 内存指标
| 指标 | 含义 |
|------|------|
| **total** | 总内存大小 (MB) |
| **free** | 空闲内存大小 (MB) |
| **used** | 使用中的内存大小 (MB) |
| **buff/cache** | 用于文件缓存与系统缓存的内存大小 (MB) |
| **avail Mem** | 可用内存大小，约等于 free + buff/cache |

#### Swap 交换空间指标
| 指标 | 含义 |
|------|------|
| **total** | 总 swap 文件大小 |
| **free** | swap 空闲大小 |
| **used** | swap 使用大小 |

#### top 常用交互命令
| 命令 | 功能 |
|------|------|
| **1** | 查看各 CPU 核的 CPU 使用情况 |
| **M** 或 **Shift+M** | 进程按内存使用率倒序 |
| **P** 或 **Shift+P** | 进程按 CPU 使用率倒序 |
| **H** 或 **Shift+H** | 查看线程情况 |
| **c** | 查看进程的完整命令行 |
| **<, >, R** | 调整排序列（< 使用前一列、> 使用后一列、R 改为升序） |
| **o, =** | o 添加过滤条件、= 清除过滤条件 |
| **q** | 退出 top |

### 2.2 vmstat 命令

#### CPU 指标
| 指标 | 含义 |
|------|------|
| **us** | CPU 用户态使用率 |
| **sy** | CPU 内核态使用率 |
| **id** | CPU 空闲率 |
| **wa** | 等待 I/O，线程被阻塞等待磁盘 I/O 时的 CPU 空闲时间占比 |
| **st** | Steal 偷取，CPU 在虚拟化环境下在其他租户上的开销 |

#### 内存交换指标
| 指标 | 含义 | 单位 |
|------|------|------|
| **si** | 磁盘换入到内存的当前速度 | kB/s |
| **so** | 内存换出到磁盘的当前速度 | kB/s |
| **swpd** | 内存交换到磁盘的内存大小 | kB |
| **free** | 剩余内存大小 | kB |
| **buff** | 用于 buff 的内存大小 | kB |
| **cache** | 用于文件页面缓存的内存大小 | kB |

#### 磁盘 I/O 指标
| 指标 | 含义 | 单位 |
|------|------|------|
| **bi** | 每秒读取的磁盘块数量 | blocks/s |
| **bo** | 每秒写入的磁盘块数量 | blocks/s |

#### 中断与上下文切换
| 指标 | 含义 |
|------|------|
| **in** | 每秒中断数量 |
| **cs** | 每秒线程上下文切换次数 |

#### 队列与饱和度
| 指标 | 含义 |
|------|------|
| **r** | CPU 运行队列长度（等待 OS 调度运行的线程数），**CPU 饱和度指标**，长时间处于高值一般有问题 |
| **b** | 不可中断阻塞的线程数量（一般为阻塞于 IO 访问的线程） |

**注意**：1s 显示一次，第一行是系统启动以来的统计信息，一般可忽略，从第二行开始看。

---

### 2.3 free 命令

#### 内存分类
| 分类 | 含义 |
|------|------|
| **free** | 完全未使用的内存。注意：随着使用时间越来越长，free 会越来越小，原因是 Linux 会把访问的文件数据尽可能地缓存在内存中，以便下次读取时能快速返回 |
| **buff/cache** | 文件缓存与系统缓存内存，**可以回收后重复利用** |
| **available** | 系统真正的可用内存，约等于 free + buff/cache |

#### 经验知识
- Linux 会优先利用空闲内存进行缓存，不会浪费内存
- 有效的可用内存是 `available`，而非 `free`

---

### 2.4 slabtop 命令

#### 概念
- **Slab** 是 Linux 基于对象的一种内存分配机制，类似于对象池的概念
- 当 Linux 需要一个内核对象时，如果 slab（对象池）中有，就可以直接获取对象，而不用申请内存块

#### 使用场景
- Slab 包含在 `buff/cache` 中
- 当 `buff/cache` 占用很大时，除检查文件缓存外，还可以看看 slab 占用情况
- 帮助诊断内核对象泄漏问题

## 3. 磁盘资源观测

### 3.1 df 命令

#### 功能
- 查看磁盘整体使用情况
- **Use%** 列显示磁盘使用百分比
- 可跟文件或目录，查看当前文件/目录对应文件系统的占用情况

#### 典型输出
```
/dev/sda1 的 Use% 显示为 57%
```

---

### 3.2 iostat 命令

#### 磁盘 I/O 吞吐量指标
| 指标 | 含义 | 单位 |
|------|------|------|
| **r/s + w/s** | 当前的 IOPS（每秒 I/O 操作数） | ops/s |
| **avgrq-sz** | 当前每秒平均吞吐量 | 扇区（512B） |

#### 磁盘使用率与饱和度指标
| 指标 | 含义 |
|------|------|
| **%util** | 磁盘使用率。注意：Linux 认为磁盘只能处理一个并发，但 SSD 或 raid 实际可以超过一个，所以 100% 也不一定代表满载 |
| **avgqu-sz** | 磁盘任务队列长度。**饱和度指标**：大于磁盘的并发任务数则磁盘处于饱和状态 |

#### 延迟指标
| 指标 | 含义 |
|------|------|
| **svctm** | 平均服务时间（不包括在磁盘队列中的等待时间） |
| **r_await, w_await** | 读写延迟时间 (ms)，包括磁盘队列等待时间 + svctm。太大则磁盘饱和 |

**注意**：第一次输出结果是历史以来的统计值，一般可忽略。

---

### 3.3 iotop 命令

#### 功能
- 查看进程/线程维度的 IO 情况
- 与 `iostat` 的区别：能精确到进程级别，找出具体是哪个进程进行 I/O 操作

## 5. 全能观测命令

### 5.1 sar 命令

sar 是一个全方位的观测命令，如果背熟了可以代替前面的命令。

#### CPU 类观测
| 用法 | 描述 |
|------|------|
| `sar -u ALL 1` | CPU 使用率 |
| `sar -q 1` | 运行队列与负载 |
| `sar -I SUM 1` | 中断次数 |
| `sar -w 1` | 进程创建次数与线程上下文切换次数 |

#### 内存类观测
| 用法 | 描述 |
|------|------|
| `sar -r ALL 1` | 内存使用、脏页与 slab |
| `sar -B 1` | 缺页与内存页扫描 |
| `sar -S 1` 或 `sar -W 1` | 内存 swap 使用 |

#### 磁盘类观测
| 用法 | 描述 |
|------|------|
| `sar -dp 1` | 磁盘 IOPS |
| `sar -v 1` | 文件描述符与打开终端数 |

#### 网络类观测
| 用法 | 描述 |
|------|------|
| `sar -n DEV 1` | 网卡层使用率 |
| `sar -n TCP,ETCP 1` | TCP 层收包发包情况 |
| `sar -n SOCK 1` | Socket 使用情况 |

---

### 5.2 dstat 命令

#### 功能
- 全方位观测命令，使用上比 sar 简单一些
- 可以同时显示 CPU、内存、磁盘、网络等多种资源的实时数据

## 6. USE 观测法

### 6.1 USE 法三个维度

**USE 法**（Utilization Saturation Errors）是针对任何资源的观测方法，三个维度为：

| 维度 | 含义 | 示例 |
|------|------|------|
| **U：使用率** | 资源被使用的百分比 | CPU 使用率、内存使用率、磁盘 I/O 使用率、网卡带宽使用率 |
| **S：饱和度** | 资源等待队列的长度 | CPU 运行队列长度 (r)、磁盘任务队列长度 (avgqu-sz)、网络缓存队列 |
| **E：错误** | 资源出错的次数 | 丢包率、I/O 错误、重传次数 |

### 6.2 软件资源示例：Java 线程池

理解线程池资源的 USE 指标：
- **线程池是一个软件资源**
- **使用率**：目前正在运行任务线程数 ÷ 线程池总线程数（百分比）
- **饱和度**：目前在线程池任务队列中排队的任务数量
- **错误**：触发线程池拒绝策略的次数

### 6.3 硬件资源四要素

系统观测的四种常见硬件资源及其 USE 指标：

#### CPU
- **使用率**：(us + sy + hi + si) / 100
- **饱和度**：运行队列长度 (r)
- **错误**：上下文切换异常增多

#### 内存
- **使用率**：(total - available) / total
- **饱和度**：swap 使用速率 (si, so)
- **错误**：OOM Kill 事件

#### 磁盘
- **使用率**：%util
- **饱和度**：avgqu-sz，读写延迟 (await)
- **错误**：I/O 错误率

#### 网络
- **使用率**：网卡带宽使用率 (%Util)
- **饱和度**：网络缓存队列、丢包率
- **错误**：CRC 错误、丢包、重传

| 资源 | 关键指标 | 命令 | 阈值 | 含义 |
|------|---------|------|------|------|

## 9. 知识点总结

1. **USE 法是通用方法**：使用率/饱和度/错误，可应用于任何资源
2. **分层观测**：从系统级（top、sar）→ 资源级（iostat、nicstat）→ 进程级（iotop）
3. **关键指标**：
   - CPU：运行队列 r
   - 内存：available、swap 使用
   - 磁盘：%util、avgqu-sz、await
   - 网络：%Util、丢包率
4. **命令选择**：快速查看用 top/free/df，深度分析用 vmstat/iostat，全方位用 sar/dstat
5. **资源观测不能直接排查根因**，但能为问题排查提供方向

## 11. 扩展知识

### 11.1 内存观测的细节
- `buff/cache` 中既包含**文件缓存**（访问文件时缓存的数据）也包含**系统缓存**（内核数据结构）
- **slab 是系统缓存的一部分**，当 buff/cache 很大时，需要用 slabtop 进一步诊断是文件缓存过大还是 slab 泄漏

### 11.2 磁盘饱和度判断
- **单个指标不足以判断饱和状态**，需要综合判断：
  - %util > 70% 且 avgqu-sz > 2 且 await > 20ms → 磁盘饱和
  - %util = 100% 但 avgqu-sz = 0 → 可能是突发大 I/O，不一定饱和

### 11.3 sar 命令的强大之处
- 可以查看**历史数据**（需要系统启用 sar 数据收集，通常自动启用）
- 支持**灵活的过滤和统计**，可以按时间段、按设备查看数据
