# 第 22 章：案例与实验 - 知识点梳理

> **本章概述**：通过实际实验验证 CPU、内存等核心指标的理解，包括 CPU 各模式使用率变化、内存回收机制、swap 触发条件及 OOM 处理流程。

---

## 一、CPU 使用率各模式实验

### 1.1 用户态 CPU 使用率（us）

**现象描述**：
- 用户态进程占用 CPU，导致 us 值升高

**排查链路**：
```
高 us 值 → top/vmstat 查看 → 用户进程消耗 CPU → 识别进程号 → strace/perf 分析
```

**根因分析**：
- 应用程序执行计算密集型任务
- 业务逻辑存在死循环或低效算法

**实验方法**：
- 使用 `stress -c` 命令开启压测进程
- 该进程运行死循环使 CPU 满载，直观验证 us 值升高

**修复方案**：
- 优化应用算法，减少 CPU 密集操作
- 使用线程池降低上下文切换开销

**关键工具**：`top`、`vmstat`、`stress -c`、`perf`

---

### 1.2 Nice 优先级进程 CPU 使用率（ni）

**现象描述**：
- 设置过 nice 值的进程占用用户态 CPU，导致 ni 值升高

**排查链路**：
```
高 ni 值 → ps/top 查看 NI 列 → 识别低优先级进程 → 调整优先级或降低负载
```

**根因分析**：
- 系统中存在被设置了负 nice 值（高优先级）的进程
- 这类进程抢占普通优先级进程的 CPU 时间

**实验方法**：
- 先使用 `stress` 命令启动进程
- 用 `renice` 命令调整该进程的 nice 值
- 观察 ni 值随之升高

**修复方案**：
- 根据业务需求合理设置进程优先级
- 避免过多高优先级进程争抢 CPU

**关键工具**：`renice`、`ps`、`top`

---

### 1.3 内核态 CPU 使用率（sy）

**现象描述**：
- 内核态操作占用 CPU，导致 sy 值升高

**排查链路**：
```
高 sy 值 → vmstat 查看 cs/in → strace 追踪系统调用 → 识别缺页异常或内核线程
```

**根因分析**：
- 大量系统调用（read/write/mmap 等）
- 页面缺失（page fault）导致 kswapd 工作
- 内核线程运行（如 kswapd、kworker）

**实验方法**：
- 使用 `stress -m` 命令不断申请内存
- 进程反复读写内存造成大量缺页中断
- 观察 sy 值升高，内核频繁处理中断

**修复方案**：
- 减少系统调用频率（批处理）
- 优化内存访问模式，降低缺页率
- 使用 mmap 替代频繁 read/write

**关键工具**：`vmstat`、`strace`、`perf`、`stress -m`

---

### 1.4 IO 等待 CPU 使用率（wa）

**现象描述**：
- 等待磁盘 IO 的线程存在时，CPU 空闲但不计入 idle，导致 wa 值升高

**排查链路**：
```
高 wa 值 → iostat 查看磁盘 I/O → iotop 识别进程 → blktrace 分析 I/O 延迟
```

**根因分析**：
- 磁盘 IO 性能不足，线程阻塞等待
- 过多小 IO 请求导致磁盘忙碌
- 缓存策略不当，热数据频繁访问磁盘

**实验方法**：
- 使用 `dd` 命令读取磁盘
- 指定 directio 模式（iflag=direct）绕过缓存，直接读磁盘
- 观察 wa 值升高

```bash
dd if=/dev/sda of=/dev/null bs=1M count=1000 iflag=direct
```

**修复方案**：
- 增加磁盘 IO 吞吐或降低延迟（更换 SSD）
- 使用异步 IO 避免线程阻塞
- 优化数据库索引和查询，减少磁盘访问

**关键工具**：`iostat`、`iotop`、`blktrace`、`dd`

---

### 1.5 软中断 CPU 使用率（si）

**现象描述**：
- 软中断处理占用 CPU，导致 si 值升高

**排查链路**：
```
高 si 值 → /proc/softirq 查看软中断计数 → 网络相关中断异常 → 网络抓包分析
```

**根因分析**：
- 网络包处理过载（大量网络包到达）
- 中断绑定不当导致单核过载
- 网络驱动程序性能瓶颈

**实验方法**：
- 从另一台机器使用 `hping3` 疯狂发送网络包
- 目标机器频繁处理软中断，si 值升高

```bash
hping3 -S -i u10 target_ip  # 持续高频发送 SYN 包
```

**修复方案**：
- 调整网络中断亲和性（irqbalance）
- 使用 RPS/RFS 分散软中断处理
- 升级网络驱动或硬件

**关键工具**：`hping3`、`/proc/softirq`、`ethtool`、`irqbalance`

## 二、内存回收机制实验

### 2.1 实验场景设置

**系统配置**：
- `vm.swappiness = 1`：优先回收文件缓存，之后才使用 swap

**初始状态**：
- 生成 4GB 大文件
- 使用 `cat` 读取文件使其被缓存到内存
- 结果：buff/cache 占用 3.4GB，swap 使用量 268KB

---

### 2.2 阶段 1：第一次内存回收（文件缓存回收）

**实验操作**：
- 执行 `stress -m` 分配 3GB 内存

**现象**：
- buff/cache 从 3.4GB 下降到 389MB（被回收 3GB）
- swap 使用量从 268KB 增加到 10MB

**分析**：
- 触发 Linux 内存回收机制
- kswapd 优先回收文件缓存（符合 vm.swappiness=1 策略）
- 只有少量内存被 swap 到磁盘

**ASCII 排查流程**：
```
申请 3GB 内存
  ↓
内存不足 → 触发 kswapd
  ↓
vm.swappiness=1 → 优先回收文件缓存
  ↓
buff/cache: 3.4GB → 389MB ✓
swap 增加: 268KB → 10MB
  ↓
回收成功，内存分配完成
```

---

### 2.3 阶段 2：第二次内存回收（使用 swap）

**实验操作**：
- 在前 3GB 仍占用的情况下，再分配 2GB 内存

**现象**：
- 文件缓存基本回收完毕
- swap 使用量从 10MB 激增到 1.8GB
- 前 3GB 的 stress 进程被 swap 出 1.7GB

**分析**：
- 文件缓存已回收殆尽，无法进一步回收
- 系统开始 swap 正在运行的进程内存到磁盘
- swap 成为主要内存来源

**ASCII 排查流程**：
```
申请 2GB 内存（3GB 已占用）
  ↓
内存不足 + 文件缓存已空 → 触发 swap 回收
  ↓
kswapd 交换运行中的进程内存
  ↓
前 3GB 进程: 1.7GB 被 swap 出
swap: 10MB → 1.8GB ↑
  ↓
性能严重恶化（磁盘 IO 剧增）
```

---

### 2.4 阶段 3：OOM 杀手启动（内存溢出处理）

**实验操作**：
- swap 空间大量被占用后，再分配 2GB 内存

**现象**：
- 最初分配的 3GB stress 进程被 OOM-killer 杀死
- dmesg 日志显示：`Killed process xxxx (stress) due to out of memory`

**分析**：
- swap 也耗尽，系统无法继续回收内存
- 触发 OOM-killer，按评分杀死内存占用最多的进程
- 释放内存供新的分配使用

**ASCII 排查流程**：
```
申请 2GB 内存
  ↓
内存不足 + 文件缓存无 + swap 满
  ↓
无法继续回收 → 触发 OOM-killer
  ↓
扫描进程，计算 oom_score
  ↓
杀死评分最高的进程（通常是内存占用最多的）
  ↓
早期的 3GB stress 进程被选中
  ↓
进程信号：SIGKILL
内存释放，新分配继续
```

## 三、内存回收完整流程（总体视图）

```
系统运行
  ↓
        ┌─────────────────────────────────┐
        │ 内存充足？                      │
        └─────────────────────────────────┘
          ↙                     ↘
        NO                      YES
        ↓                       ↓
   触发回收                  正常运行
      ↓
   vm.swappiness 检查
      ↓
   ┌─────────────────────────────────┐
   │ 优先级：文件缓存 vs 进程内存    │
   │ (swappiness=1:缓存优先)         │
   └─────────────────────────────────┘
      ↙                     ↘
  有缓存                   缓存空
    ↓                       ↓
 回收缓存 → swap 0-10MB  进程 swap → 1GB+ ↓
      ↓                       ↓
  回收继续                  IO 性能↓↓
      ↓
  缓存尽 + swap 有
      ↓
  继续交换进程内存
      ↓
  缓存尽 + swap 满
      ↓
  OOM-killer 启动
      ↓
  Kill 进程释放内存
```

## 四、关键概念总结

| 概念 | 定义 | 触发条件 | 影响 |
|------|------|---------|------|
| **内存回收** | kswapd 主动释放内存 | 可用内存 < 阈值 | 自动；性能可控 |
| **文件缓存回收** | 释放磁盘数据的内存副本 | vm.swappiness 优先 | 快速；无页表修改 |
| **进程 swap** | 运行进程内存写入磁盘 | 文件缓存耗尽 | 缓慢；性能下降 |
| **OOM-killer** | 强制杀死进程释放内存 | 无法继续回收 | 进程终止；可控 |

## 七、故障排查决策树

```
性能下降投诉
  │
  ├─→ CPU 占用高？
  │    ├─→ us 高 → 优化应用算法
  │    ├─→ sy 高 → 降低缺页率、减少系统调用
  │    ├─→ wa 高 → 优化磁盘 I/O、升级硬件
  │    ├─→ si 高 → 调整网络中断亲和性
  │    └─→ ni 高 → 调整进程优先级
  │
  └─→ 内存不足？
       ├─→ 缓存充足 → 文件缓存被回收（正常）
       ├─→ 缓存耗尽 → 进程被 swap（性能↓）
       └─→ swap 也满 → OOM-killer 启动（进程死亡）
            └─→ 增加内存、优化应用、扩展 swap
```
