# Linux 日志分析完全指南

> 源文档梳理：如何正确高效的看日志（Linux 文本处理命令详解）

---

## 一、核心命令分类

### 1. 基础文件查看命令

#### cat 命令
- **用途**：文件内容输出
- **优点**：简单直接
- **缺点**：容易刷屏，不适合大文件
- **适用场景**：小文件查看（配置文件）、管道中转
- **典型用法**：`cat config.conf`

#### head 命令
- **用途**：查看文件前几行
- **默认行数**：10 行
- **典型用法**：`head -n 20 app.log`

#### tail 命令
- **用途**：查看文件后几行，实时监控
- **关键选项**：`-f` 持续显示新内容
- **典型用法**：
  - `tail -n 20 app.log` （查看末尾 20 行）
  - `tail -f app.log` （实时监控日志）

---

### 2. 文本编辑器：vim

- **用途**：文本编辑
- **缺点**：全量加载文件到内存，大文件容易内存溢出
- **不推荐场景**：日志大文件查看
- **适用场景**：配置文件编辑

---

### 3. 分页查看器：less/more

#### less 命令（推荐）

**优势**：
- 按需加载文件数据，支持大日志文件
- 功能丰富，可查看压缩包（.jar、.gz）
- 相比 more 提供更多增强功能

**基本导航操作**：

| 操作 | 描述 |
|------|------|
| `f` | 向后翻页（forward） |
| `b` | 向前翻页（backward） |
| `g` | 跳转到文件首行 |
| `G` | 跳转到文件尾行（Shift+g）|
| `/abc` | 向后搜索 abc，`n` 查找下一个，`N` 查找上一个 |
| `?abc` | 向前搜索 abc，`n` 查找上一个，`N` 查找下一个 |
| `q` | 退出 less 程序 |

**高级选项**（在 less 内部按 `-` 后输入）：

| 选项 | 描述 |
|------|------|
| `F` | 持续显示文件新内容（Shift+f），类似 tail -f |
| `-N` | 显示行号 |
| `-i` | 忽略大小写搜索 |
| `-S` | 不换行查看（横向滚动，适合宽日志） |
| `-R` | 保留颜色输出 |

**压缩包查看**：
```bash
less xxx.jar          # 查看 jar 包内容，检查打包是否正常
less xxx.gz           # 查看 gzip 压缩文件
```

**过滤显示**：
- 在 less 内支持过滤忽略某些内容
- 场景：内核日志中过滤可忽略的错误

---

### 4. 搜索过滤命令：grep

**基本用法**：
```bash
grep -i error app.log                    # 忽略大小写搜索
```

**关键选项**：
- `-i`：忽略大小写
- `-v`：反向匹配（排除）
- `-e`：多个条件（多个 -e 排除多个内容）
- `-A n`：输出匹配行后的 n 行
- `-B n`：输出匹配行前的 n 行
- `-C n`：输出匹配行前后各 n 行
- `-m n`：查到 n 条就停止

**常见组合**：

```bash
# 实时过滤错误日志
tail -f app.log | grep -i error

# 排除某些干扰错误
tail -f app.log | grep --line-buffered -i error | grep -v -e reset

# Java 异常栈处理（输出匹配行后 9 行）
tail -f app.log | grep -A 9 -i error

# 倒序搜索最近的 10 条错误
tac app.log | grep -m 10 -i error
```

**辅助命令**：
- `tac`：文件倒序输出（reverse of cat）
- 常用于从后向前搜索最近发生的错误

---

### 5. 高级文本处理：awk

**语言特性**：
- 为文本处理而生的脚本语言
- 按字段（列）处理文本
- 支持 BEGIN、pattern、action、END 流程

**基础语法**：
```bash
awk 'BEGIN{action} pattern1{action} pattern2{action} END{action}' file.log
```

**执行流程**：
1. 执行 BEGIN 块代码
2. 逐行检查是否匹配 pattern，若匹配执行对应 action
3. 所有行处理完后，执行 END 块代码

**语言特性**：
- 支持 if、while、for 等控制语句
- 支持变量、函数、正则表达式
- 类似 C、Java 语法

**常见应用场景**：

**场景 1：按段分隔搜索异常栈**
```bash
cat app.log | awk -v RS= '/Broken pipe/'
```
- `-v RS=`：指定 RS 变量为空，表示按段（段落）分隔记录
- `/Broken pipe/`：简写形式，等价于 `$0~/Broken pipe/`，判断当前记录是否正则匹配

**场景 2：时间范围过滤**
- awk 支持范围匹配，可过滤特定时间段的日志数据
- 使用 pattern1 ~ pattern2 语法

---

### 6. 统计命令：wc

**用途**：文本文件统计

**基本用法**：
```bash
wc app.log              # 输出：行数  词数  字节数
```

**主要选项**：
- 默认显示：行数、词数、字节数
- `-l`：仅显示行数（**最常用**，用于统计数量）
- `-w`：仅显示词数
- `-c`：仅显示字节数

**典型用法**：
```bash
grep error app.log | wc -l    # 统计错误日志条数
```

---

### 7. 排序命令：sort

**基本用法**：
```bash
sort app.log              # 默认以整行按字母序排序
```

**主要选项**：
- `-n`：按数值大小排序（numeric）
- `-r`：倒序排列（reverse）
- `-k n`：指定第 n 个字段排序（以空白为分隔符）
- 常用组合：`-nrk`（按第 k 字段数值倒序）

**典型用法**：
```bash
sort -nrk2 app.log        # 按第 2 字段数值倒序排列
sort -k2 app.log          # 按第 2 字段字母序排列
```

---

### 8. 去重统计命令：uniq

**用途**：去重、统计重复项

**主要选项**：
- 默认：去重（不常用）
- `-c`：统计各项数量（**最常用**）

**注意事项**：
- **必须先排序**，否则无法正确去重
- 通常跟在 sort 后面使用

**典型用法**：
```bash
sort -nrk2 app.log | uniq -c    # 先排序，再统计重复次数

# 完整例子：统计各 IP 访问次数（倒序）
cat access.log | awk '{print $1}' | sort | uniq -c | sort -nrk1
```

---

### 9. 压缩日志处理命令

#### zcat / zless / zgrep

**背景**：为节省磁盘空间，日志常被 gzip 压缩

**命令对应**：
- `zcat`：对应 `cat`，解压并显示
- `zless`：对应 `less`，分页查看压缩文件
- `zgrep`：对应 `grep`，直接在压缩文件中搜索

**典型用法**：
```bash
zcat app.log.gz           # 查看压缩日志内容
zless app.log.gz          # 分页查看压缩日志
zgrep error app.log.gz    # 搜索压缩日志中的错误
```

**注意**：无 zawk 命令，可先解压后分析
```bash
gzip -d app.log.gz && awk '...' app.log
```

## 二、日志分析典型工作流

### 场景 1：快速查看大日志文件

```
选择工具：less

操作流程：
├─ less app.log
├─ 按 g 跳转到文件首行
├─ 按 G 跳转到文件尾行
├─ 按 / 搜索关键字
├─ 按 F 实时监控新内容
└─ 按 q 退出
```

### 场景 2：查找并输出异常栈

```
命令链：
cat app.log 
  ↓ (管道)
grep -A 9 -i error
  ↓ (或使用 awk 按段搜索)
awk -v RS= '/Exception/'

说明：
- grep -A 9：输出匹配行后 9 行（包含异常栈）
- awk -v RS=：按段分隔，查找完整异常块
```

### 场景 3：实时监控并过滤日志

```
命令链：
tail -f app.log
  ↓ (管道，实时传输)
grep --line-buffered -i error
  ↓ (过滤干扰项)
grep -v -e reset -e timeout

说明：
- tail -f：实时读取新增行
- grep --line-buffered：行缓冲，立即输出
- grep -v：排除特定错误（多个 -e 条件）
```

### 场景 4：统计分析（如 TOP 错误）

```
命令链（示例：统计最常见的 10 个错误）：
cat app.log
  ↓
grep ERROR
  ↓
awk '{print $NF}' (提取错误信息)
  ↓
sort
  ↓
uniq -c
  ↓
sort -nrk1
  ↓
head -10

说明：
- awk 按列提取关键信息
- sort：排序准备
- uniq -c：计数统计
- sort -nrk1：按数值倒序
- head -10：取前 10 条
```

### 场景 5：时间范围日志过滤

```
命令链（示例：提取 14:00:00 到 15:00:00 的日志）：
cat app.log
  ↓
awk '/14:00:00/,/15:00:00/'

说明：
- 范围模式 /start/,/end/
- awk 支持此语法实现区间过滤
```

   │
   ├─→ less/more ──→ 交互式查看 (推荐首选)

       ├─ -A 异常栈      │
       └─ -v 反向排除    │
                         ↓
                       awk ─────→ 列提取、统计、按段
                       │
                       ├─ 字段分割处理
                       ├─ 按段分隔 (RS=)
                       └─ 范围过滤
                         │
                         ↓
                    sort | uniq -c ──→ 统计排序
                         │
                         ├─ sort -nrk2 (数值排序)
                         └─ uniq -c (计数)
                         │
                         ↓
                    输出结果/导出
```

### 流程图 2：less 交互式操作

```
less app.log 启动
   │
   ├─ 浏览操作
   │  ├─ f (下翻)
   │  ├─ b (上翻)
   │  ├─ g (首行)
   │  └─ G (尾行)
   │
   ├─ 搜索操作
   │  ├─ /abc (向后搜索)
   │  └─ ?abc (向前搜索)
   │     └─→ n/N (继续/反向搜索)
   │
   ├─ 特殊模式
   │  ├─ F (持续监控，如 tail -f)
   │  └─ - 进入选项模式
   │     ├─ -N (行号)
   │     ├─ -i (忽略大小写)
   │     ├─ -S (不换行)
   │     └─ -R (保留颜色)
   │
   └─ q 退出
```

### 流程图 3：grep 命令选项组合矩阵

```
grep [选项] [模式] [文件]

分类维度：

1. 匹配模式：
   ├─ 基础模式：-i (忽略大小写)
   └─ 高级模式：支持正则表达式

2. 输出行数：
   ├─ -A n (后 n 行)
   ├─ -B n (前 n 行)
   └─ -C n (前后各 n 行)

3. 多条件：
   ├─ -e (多个 -e 为 OR)
   └─ -v (反向，排除匹配)

4. 控制输出：
   └─ -m n (找到 n 条就停止)

典型组合：
tail -f | grep --line-buffered -i ERROR | grep -v -e WARN -e INFO
  ↑          ↑                 ↑          ↑     ↑ ↑
  │          │                 │          │     └─ 多个排除条件
  │          │                 │          └─ 反向匹配
  │          │                 └─ 忽略大小写
  │          └─ 行缓冲（立即输出）
  └─ 实时模式
```

### 流程图 4：awk 处理流程

```
awk 'BEGIN{...} /pattern/{...} END{...}' file

执行顺序：
        文件打开
           │
           ↓
     执行 BEGIN 块
    （初始化变量）
           │
           ↓
    ┌─ 逐行读取文件
    │  │
    │  ├─ 检查 pattern1 匹配
    │  │  └─ 是 → 执行 action1
    │  │
    │  ├─ 检查 pattern2 匹配
    │  │  └─ 是 → 执行 action2
    │  │
    │  └─ 继续下一行
    │
    └─ 所有行处理完
           │
           ↓
     执行 END 块
    （汇总统计）
           │
           ↓
     输出结果

字段处理：
行字符串被自动分割为字段
$0 = 整行
$1 = 第 1 字段
$2 = 第 2 字段
...
$NF = 最后一个字段
```

```

   │ 获取原始数据
   ↓

   │ 数据筛选

### 流程图 6：压缩文件处理

```
app.log.gz (gzip 压缩文件)
   │
   ├─ zcat app.log.gz ──→ 完整解压输出（适合管道）
   │
   ├─ zless app.log.gz ──→ 分页交互查看（推荐）
   │
   ├─ zgrep error app.log.gz ──→ 直接搜索（高效）
   │
   └─ gzip -d + awk ──→ 解压后高级处理

推荐优先级：
  1. 查看 → zless

grep --line-buffered 的作用：

### 补充 3：awk RS= 按段分隔的实际应用

**原文缺失**：未充分说明 RS= 的价值

awk -v RS= 按段分隔（段与段间以空行分隔）

- 用 RS= 可以整块提取，便于完整的异常信息处理

示例：找出包含特定异常的完整日志块

```

| `RS` | 记录分隔符（默认换行） | `-v RS=` 按段 |
| `OFS` | 输出字段分隔符 | `-v OFS=,` |

## 六、实战示例集锦

### 示例 1：实时监控应用错误并去除已知干扰

```bash
tail -f app.log | grep --line-buffered -i error | grep -v -e "connection reset" -e "timeout"
```

**说明**：
- `tail -f`：实时读取
- `grep -i error`：捕获所有错误行
- `grep -v -e`：排除已知干扰信息

---

### 示例 2：查找今天 10:00-11:00 的异常栈

```bash
awk '/2024-01-15 10:00/,/2024-01-15 11:00/' app.log | awk -v RS= '/Exception/'
```

**说明**：
- 第一个 awk：按时间范围提取
- 第二个 awk：按段分隔提取完整异常块

---

### 示例 3：TOP 10 HTTP 错误码

```bash
cat access.log | grep -v " 200 " | awk '{print $NF}' | sort | uniq -c | sort -nrk1 | head -10
```

**说明**：
- 过滤掉成功请求
- 提取最后一列（错误码）
- 统计并倒序排列

---

### 示例 4：查找最近 5 个异常

```bash
tac app.log | grep -m 5 -i exception
```

**说明**：
- `tac`：反序输出
- `-m 5`：找到 5 条就停止
- 实现"从后向前找最近的异常"

---

### 示例 5：大压缩日志中查找特定 URL 并统计访问次数

```bash
zgrep "/api/users" access.log.gz | awk '{print $1}' | sort | uniq -c | sort -nrk1
```

**说明**：
- `zgrep`：直接在压缩文件中搜索
- 管道到 awk、sort、uniq 做统计

## 七、学习总结

### 核心要点

1. **工具选择遵循原则**：
   - 小文件 → cat/vim
   - 大文件 → less
   - 搜索 → grep
   - 统计 → wc/sort/uniq
   - 复杂处理 → awk

2. **管道连接的设计**：
   - 按功能分层：获取 → 过滤 → 处理 → 统计 → 输出
   - 尽可能靠前进行过滤，减少数据量
   - 例：cat | grep | awk | sort | uniq

3. **实时监控两大法宝**：
   - `tail -f | grep --line-buffered`：管道场景
   - `less -F`：交互式监控

4. **压缩文件无缝处理**：
   - z 前缀命令可直接处理 .gz 文件
   - 优先级：zless > zgrep > zcat

### 进阶建议

- 掌握 grep -A/-B/-C 用于异常栈提取
- 深入学习 awk 的 BEGIN/END 和 pattern 匹配
- 合理使用管道符号，构建高效的文本处理流程
- 通过 `man` 命令学习更多细节：`man less`、`man awk` 等
- 多练习实战，积累常见的管道组合
