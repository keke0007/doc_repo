# 05. 软件资源观测 - 梳理笔记

## 1. 核心概念

### 什么是软件资源？

软件资源是指进程在运行过程中使用到的各类资源，包括：
- **进程与线程**：进程本身及其包含的线程信息
- **网络连接**：进程建立的TCP/UDP连接
- **文件描述符**：进程打开的文件、socket、管道等
- **工作目录**：进程当前的工作路径

### 观测的意义

通过观测软件资源，可以：
- 追踪进程的实时活动状态
- 定位资源泄漏（如文件句柄泄漏、连接泄漏）
- 诊断性能问题（如活跃连接数、线程数异常）
- 快速定位故障进程和相关资源

## 2. 核心命令详解

### 2.1 ps命令 - 进程与线程观测

**基本用途**：查看进程和线程的相关信息

**常见选项**：
| 选项 | 说明 |
|------|------|
| `ps aux` | 查看所有进程的详细信息 |
| `-o` | 自定义输出字段 (e.g., `-o pid,ppid,cmd,etime`) |
| `-e` | 显示所有进程 |
| `-L` | 显示线程信息 |
| `--sort` | 按指定字段排序 |

**获取线程数**：
```bash
# 查询单个进程的线程数
ps -eLf | grep <PID> | wc -l

# 查看所有进程的线程分布
ps -eLf | awk '{print $2}' | sort | uniq -c | sort -rn
```

**关键洞察**：
- 后端程序常使用线程池，流量低时线程多为空闲状态
- **活跃线程数**比总线程数更能准确反映问题
- 用 `top -H -i` 只显示活跃线程（-H显示线程，-i仅显示活跃）

---

### 2.2 netstat命令 - 网络连接观测

**基本用途**：查看系统网络连接状态

**常见选项**：
| 选项 | 说明 |
|------|------|
| `-an` | 显示所有连接，使用数字显示地址 |
| `-p` | 显示连接关联的进程ID和进程名 |
| `Proto` | 协议类型 |
| `State` | 连接状态 (LISTEN, ESTABLISHED, TIME_WAIT等) |

**进程与连接的关联**：
```bash
# 根据进程ID查找网络连接
netstat -anp | grep <PID>

# 根据网络连接查找进程ID
netstat -anp | grep <端口号或IP:端口>
```

---

### 2.3 ss命令 - 高性能连接查看

**相比netstat的优势**：
- 性能更高（基于netlink内核接口，而非/proc解析）
- 提供更多连接统计信息

**常见选项**：
| 选项 | 说明 |
|------|------|
| `-a` | 显示所有socket |
| `-i` | 显示额外连接信息 |
| `-p` | 显示进程信息 |
| `-n` | 显示数字地址 |

**关键字段**：
- `lastsnd`：最后一次发送包的时间
- `lastrcv`：最后一次接收包的时间
- 这两个字段可用于计算**活跃连接**

**计算活跃连接示例**：
```bash
# 显示lastsnd或lastrcv小于1000毫秒（活跃）的连接，按端口分组计数
ss -i | awk 'lastsnd < 1000 || lastrcv < 1000 {print $4}' | \
  awk -F: '{print $NF}' | sort | uniq -c | sort -rn
```

**案例输出解读**：
```
  3 3306   # MySQL有3个活跃连接
  6 6379   # Redis有6个活跃连接
```

---

### 2.4 lsof命令 - 文件描述符观测

**基本用途**：列出进程打开的所有文件和网络连接

**核心理念**：Linux中"一切皆文件"，网络连接也抽象为文件操作

**常见用法**：
```bash
# 查看进程打开的所有文件
lsof -p <PID>

# 根据文件路径查找打开它的进程
lsof <文件路径>

# 根据网络端口查找相关进程
lsof -i :<端口号>

# 查看进程的工作目录
lsof -p <PID> | grep cwd
```

**典型应用案例 - 磁盘空间未释放问题**：

**问题现象**：删除了大日志文件，但磁盘剩余空间没有增加

**原因分析**：进程仍在引用已删除的文件（文件inode未被真正释放）

**诊断方法**：
```bash
# 查找引用已删除文件的进程
lsof | grep deleted

# 确认是否是预期的进程（如PID 867）
# 显示结果中会标记 (deleted) 的文件项
```

**解决方案**：
- 重启相关进程（如PID 867），文件inode才会被真正释放
- 磁盘空间即可恢复

---

### 2.5 fuser命令 - 快速文件/端口查询

**基本用途**：lsof的简化版，根据文件或端口查找进程

**优点**：
- 相比lsof输出更简洁
- 命令更轻量级

**常见用法**：
```bash
# 根据文件查找进程
fuser <文件路径>

# 根据端口查找进程
fuser <端口号>/tcp    # TCP
fuser <端口号>/udp    # UDP
```

---

### 2.6 其他辅助命令

| 命令 | 功能 |
|------|------|
| `pwdx <PID>` | 查看进程工作目录（简化版lsof）|
| `pslog` | 查找进程日志文件 |
| `prtstat` | 查看进程基本信息 |

## 3. 实战案例：查找进程日志

### 场景

部署情况不熟悉，已知某端口（如3306）运行了一个服务，但不清楚其日志文件位置。

### 操作步骤

1. **根据端口查找进程**
   ```bash
   lsof -i :3306
   # 或
   fuser 3306/tcp
   ```
   得到进程PID

2. **查看进程打开的所有文件**
   ```bash
   lsof -p <PID>
   ```

3. **筛选日志相关文件**
   ```bash
   lsof -p <PID> | grep -i log
   ```

4. **获得日志文件路径**
   - 从输出中找到 `*.log` 等日志文件的完整路径
   - 即可用 `tail -f` 等命令监控日志

## 4. 流程图解

### 4.1 从PID到打开文件/Socket的链路

```
┌─────────────────────────────────────────────────────┐
│              进程资源观测完整链路                       │
└─────────────────────────────────────────────────────┘

1. ps命令链路
   ┌──────────┐
   │ ps aux   │──> 获取PID、进程名、内存、CPU等
   └──────────┘
        │
        ▼
   ┌──────────────────────┐
   │ ps -eLf | grep PID   │──> 查看线程数
   └──────────────────────┘

2. 网络连接链路
   ┌────────────────────┐
   │ netstat -anp | grep│ 
   │ PID或端口号        │──> 找到进程的所有网络连接
   └────────────────────┘
           或
   ┌────────────┐
   │ ss -anp    │
   │ (性能更优) │──> 同上 + 更多统计信息
   └────────────┘

3. 文件描述符链路
   ┌──────────────┐
   │ lsof -p PID  │
   └──────────────┘
        │
        ├──> 打开的文件 (/path/to/log)
        ├──> socket连接 (IPv4 UDP)
        ├──> 工作目录 (cwd)
        └──> 管道、device等其他资源
```

### 4.2 ps命令 → /proc → lsof 的关系

```
┌─────────────────────────────────────────────────────────┐
│             系统信息查询的三层体系                          │
└─────────────────────────────────────────────────────────┘

第一层：进程基础信息
    ┌────────────────────┐
    │ ps <options>       │  查询命令行参数、状态、资源使用
    │ cat /proc/PID/stat │  内核直接数据结构
    └────────────────────┘

第二层：进程文件系统视图
    ┌──────────────────┐
    │ /proc/PID/      │  进程虚拟文件系统
    │  ├─ fd/          │  打开的文件描述符链接
    │  ├─ cwd          │  当前工作目录
    │  ├─ exe          │  执行文件
    │  ├─ cmdline      │  命令行参数
    │  └─ stat         │  进程统计信息
    └──────────────────┘

第三层：文件描述符完整查询
    ┌────────────────────┐
    │ lsof -p PID        │  高层命令行工具
    │ (解析 /proc/PID/fd)│  读取fd目录下的链接
    └────────────────────┘
         │
         ├──> 解析fd目录中的符号链接
         ├──> 读取socket信息
         └──> 输出统一格式
```

### 4.3 资源泄漏诊断流程

```
┌──────────────────────────────────┐
│   磁盘空间未释放问题排查流程       │
└──────────────────────────────────┘

1. 现象确认
   ┌──────────────────────┐
   │ 删除文件后df显示     │
   │ 空间没变少           │
   └──────────────────────┘
         ▼
2. 问题诊断
   ┌──────────────────────────────────┐
   │ lsof | grep deleted              │

   └──────────────────────────────────┘
         │
         ├─> 有进程持有 ───> 看到进程PID和文件路径
         │
         └─> 无进程持有 ───> 其他原因（如inode泄漏）

3. 确认进程
   ┌──────────────────────┐
   │ 是否是预期的进程     │
   │ (通常是java/mysql等) │
   └──────────────────────┘
         ▼
4. 解决方案
   ┌──────────────────────┐
   │ 重启进程             │

   └──────────────────────┘
         ▼
   ┌──────────────────────┐
```

**问题**：
- 表述不够准确："有进程引用" 应为 "进程仍持有该文件的文件描述符"
- 未提到inode的概念

**建议补充**：
```

重启进程后，该进程打开的所有文件描述符被关闭，
inode才会被释放，磁盘空间得以真正回收。
```

## 6. 速查表

### 6.1 进程线程观测

| 需求 | 命令 |
|------|------|
| 查看所有进程 | `ps aux` |
| 查看特定进程信息 | `ps -o pid,ppid,cmd,etime -p <PID>` |
| 查看进程线程数 | `ps -eLf \| grep <PID> \| wc -l` |
| 显示活跃线程 | `top -H -i -p <PID>` |
| 按内存排序 | `ps aux --sort=-%mem` |
| 按CPU排序 | `ps aux --sort=-%cpu` |

### 6.2 网络连接观测

| 需求 | 命令 |
|------|------|
| 查看所有连接 | `netstat -an` |
| 根据PID查连接 | `netstat -anp \| grep <PID>` |
| 根据端口查连接 | `netstat -anp \| grep :<端口>` |
| 统计连接数 | `netstat -an \| wc -l` |
| 显示活跃连接(netlink) | `ss -an` |
| 显示连接统计 | `ss -s` |
| 统计端口活跃度 | `ss -i \| awk 'lastsnd<1000 {print $4}' \| cut -d: -f2 \| sort \| uniq -c` |

### 6.3 文件描述符观测

| 需求 | 命令 |
|------|------|
| 查看进程打开的文件 | `lsof -p <PID>` |
| 查看进程工作目录 | `lsof -p <PID> \| grep cwd` |
| 查看打开文件的进程 | `lsof <文件路径>` |
| 查看占用端口的进程 | `lsof -i :<端口>` |
| 根据端口查进程 | `fuser <端口>/tcp` |
| 找已删除但被引用的文件 | `lsof \| grep deleted` |
| 查找进程日志 | `lsof -p <PID> \| grep log` |

### 6.4 故障排查场景

| 场景 | 步骤 | 命令 |
|------|------|------|
| **定位进程日志** | 1.找进程PID | `lsof -i :<端口>` 或 `fuser <端口>/tcp` |
| | 2.查看文件 | `lsof -p <PID>` |
| | 3.筛选日志 | `lsof -p <PID> \| grep -i log` |
| **排查磁盘满** | 1.找大文件 | `find / -size +100M` |
| | 2.查引用情况 | `lsof \| grep <文件名>` |
| | 3.确认进程 | `ps -p <PID>` |
| | 4.重启进程 | `kill -9 <PID> && systemctl restart ...` |
| **检查端口占用** | 1.快速查询 | `lsof -i :<端口>` |
| | 2.查连接数 | `netstat -anp \| grep :<端口> \| wc -l` |
| | 3.看活跃度 | `ss -i -p \| grep :<端口>` |

## 7. 知识点总结

### 核心命令的使用场景

| 命令 | 主要功能 | 最佳用途 |
|------|--------|--------|
| **ps** | 进程信息快照 | 进程状态、资源使用、命令行 |
| **netstat** | 网络连接统计 | 连接数、状态统计、协议分析 |
| **ss** | 高性能网络查询 | 实时连接、活跃度分析（性能优于netstat） |
| **lsof** | 文件描述符查询 | 深度诊断、文件泄漏、进程依赖关系 |
| **fuser** | 快速文件/端口查询 | 轻量级查询、脚本自动化 |

### 故障排查三问

| 问题 | 对应工具 |
|------|---------|
| "这个进程打开了什么文件？" | `lsof -p <PID>` |
| "这个端口被哪个进程占用？" | `lsof -i :<端口>` 或 `fuser <端口>/tcp` |
| "这个文件被哪些进程引用？" | `lsof <文件路径>` 或 `fuser <文件路径>` |

### 关键思维

- **进程 = 一个PID** → 用ps获取
- **PID → 打开资源** → 用lsof解析/proc/PID/fd
- **资源 → 持有进程** → 用lsof/fuser反向查询
- **网络连接** → 特殊的"文件"，用netstat/ss或lsof -i
- **活跃度** → 用lastsnd/lastrcv时间戳或线程状态判断
