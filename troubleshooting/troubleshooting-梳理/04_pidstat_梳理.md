# pidstat 进程资源观测详解

## 一、pidstat 基本用途

**pidstat** 是用于查看**进程/线程级别**的资源使用情况的命令行工具。相比 `vmstat`、`top` 等宿主机级别的观测工具，pidstat 的优势在于提供**准确的进程级指标**，在容器化环境（Docker 等）中特别有价值，因为 top 等工具观测到的是宿主机指标，而非容器内部指标。

---

## 二、pidstat 常用参数

| 参数 | 功能描述 |
|-----|--------|
| `-u` | 查看 CPU 使用率（默认选项），1秒输出一次 |
| `-r` | 查看内存使用情况 |
| `-d` | 查看磁盘 I/O 情况 |
| `-w` | 查看上下文切换情况 |
| `-v` | 查看线程数与文件描述符数量 |
| `-t` | 查看线程层面的情况 |
| `-p <pid>` | 指定查看的进程 ID |
| `-G <name>` | 指定查看的进程名称 |
| `-h` | 所有指标一行显示 |

---

## 三、CPU 使用率观测（-u 选项）

### 输出字段解释

| 字段 | 含义 | 单位 |
|-----|-----|-----|
| `%usr` | 用户态 CPU 使用率 | % |
| `%system` | 内核态 CPU 使用率 | % |
| `%guest` | 虚拟机占用的 CPU 使用率 | % |
| `%wait` | **空闲 CPU 使用率**（⚠️ 原文有歧义，见勘误） | % |
| `%CPU` | 总 CPU 使用率 | % |
| `CPU` | 进程运行所在的 CPU 编号 | - |

### 线程级观测补充

通过 `-t` 选项可查看线程层面的情况，配合 `-G` 指定进程名称：

| 字段 | 含义 |
|-----|-----|
| `TGID` | 进程 ID，也叫线程组 ID |
| `TID` | 线程 ID；主线程 ID 等于进程 ID |

---

## 四、内存使用情况观测（-r 选项）

### 输出字段解释

| 字段 | 含义 | 单位 |
|-----|-----|-----|
| `minflt/s` | 每秒轻微缺页次数，自动分配物理内存 | 次/秒 |
| `majflt/s` | 每秒严重缺页次数，分配内存后需从磁盘加载数据 | 次/秒 |
| `VSZ` | 进程虚拟内存大小 | KB |
| `RSS` | 进程物理内存大小（常驻内存） | KB |
| `%MEM` | 进程物理内存使用率 | % |

### 缺页故障深层理解

- **轻微缺页（Minor Fault）**：页表中有该页的记录，但页面不在内存中，只需从磁盘读入
- **严重缺页（Major Fault）**：页表中没有该页的记录，需要分配新物理内存并从磁盘加载数据

---

## 五、磁盘 I/O 观测（-d 选项）

### 输出字段解释

| 字段 | 含义 | 单位 |
|-----|-----|-----|
| `kB_rd/s` | 每秒从磁盘读取的数据量 | KB/秒 |
| `kB_wr/s` | 每秒向磁盘写入的数据量 | KB/秒 |
| `kB_ccwr/s` | 每秒被取消写入的数据量 | KB/秒 |
| `iodelay` | 进程 I/O 操作的延迟时间 | ticks |

### 取消写入场景

`kB_ccwr/s` 指标说明：当一个数据页被写入但尚未刷盘时，又有新的写入请求覆盖该页，则之前的写入请求被取消。此时这个取消的数据不会被写入磁盘。

---

## 六、上下文切换观测（-w 选项）

### 输出字段解释

| 字段 | 含义 | 单位 |
|-----|-----|-----|
| `cswch/s` | 每秒自愿上下文切换次数 | 次/秒 |
| `nvcswch/s` | 每秒非自愿上下文切换次数 | 次/秒 |

### 自愿 vs 非自愿切换

- **自愿切换**：进程主动放弃 CPU 的行为，如 `sleep`、获取锁失败、等待 I/O 完成等
- **非自愿切换**：内核强制切换，时间片用完时发生

### 线程/文件描述符观测（-v 选项）

| 字段 | 含义 |
|-----|-----|
| `threads` | 当前进程的线程数 |
| `fd-nr` | 文件描述符数量，包括打开的文件和网络连接 |

## 八、⚠️ 原文勘误

### 勘误 #1：第 869 行 `%wait` 字段描述有歧义

**原文表述：**
```
%wait：空闲cpu使用率
```

**问题分析：**
- `%wait` 并非"空闲 CPU 使用率"，而是**"I/O 等待时间占 CPU 时间的百分比"**
- "空闲 CPU 使用率"通常用 `%idle` 表示
- 原文用词不当，容易误导使用者

**正确表述：**
```
%wait（或 %iowait）：I/O 等待占总 CPU 时间的比例
- 表示 CPU 在等待 I/O 完成期间的时间占比
- 高 %wait 值表示进程因 I/O 操作而阻塞
```

---

### 勘误 #2：第 918-921 行 容器环境适用性描述不够精确

**原文表述：**
```
在云计算的背景下，大量进程被部署在Docker等容器中，
这导致top等观测到的指标，一般是宿主机的指标，而非容器，
导致这些指标参考意义变小。
```

**改进建议：**
- 更准确的说法是：top、vmstat 等观测的是**宿主机全局视角**，看不到容器内部的隔离情况
- pidstat 观测的是**特定进程**的资源使用，不受容器隔离的影响
- 容器的资源限制应该通过 `docker stats`、cgroup 相关工具查看

## 九、速查表

### 常用命令组合

```bash
# 1. 查看进程 CPU 使用率（1秒刷新，共10次）
pidstat -u 1 10

# 2. 查看特定进程的所有资源使用
pidstat -u -r -d -w -v -p <pid> 1

# 3. 查看进程的线程级 CPU 使用情况
pidstat -u -t -G <进程名> 1

# 4. 查看内存分页情况
pidstat -r -p <pid> 1

# 5. 查看磁盘 I/O
pidstat -d -p <pid> 1

# 6. 查看上下文切换
pidstat -w -p <pid> 1

# 7. 所有指标一行显示
pidstat -u -r -d -w -v -h -p <pid> 1
```

### 性能分析决策树

```
进程运行缓慢？
  │
  ├─ 检查 CPU 使用率 (pidstat -u)
  │  ├─ %CPU 很低 → 进程未充分利用 CPU，可能：
  │  │  ├─ I/O 等待中（%wait 高）→ 优化 I/O
  │  │  ├─ 上下文切换频繁 → 减少锁争用
  │  │  └─ 进程阻塞 → 检查依赖服务
  │  │
  │  └─ %CPU 很高 → 进程 CPU 密集，可能：
  │     ├─ 算法优化
  │     ├─ 并行化
  │     └─ 用更快的硬件
  │
  ├─ 检查内存使用 (pidstat -r)
  │  ├─ RSS 接近限制 → 内存泄漏或配置不当
  │  ├─ majflt/s 高 → 频繁缺页，可能需要扩容
  │  └─ VSZ >> RSS → 大量虚拟内存未使用
  │
  ├─ 检查 I/O (pidstat -d)
  │  ├─ kB_rd/s 或 kB_wr/s 高 → I/O 瓶颈
  │  ├─ iodelay 高 → I/O 延迟严重
  │  └─ kB_ccwr/s 高 → 写入冲突频繁
  │
  └─ 检查上下文切换 (pidstat -w)
     ├─ cswch/s 高 → 自愿切换多（I/O、锁等）
     └─ nvcswch/s 高 → 非自愿切换多（CPU 抢占）
```
