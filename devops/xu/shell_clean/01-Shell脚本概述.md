## 二、Shell 脚本的作用

核心思想:**标准化 → 工具化**,以简化操作、提升效率、减少人为故障。

| 场景 | 举例 |
|------|------|
| 自动化基础配置 | 系统初始化、内核/网络/时区/SSH 优化 |
| 自动化安装程序 | LNMP、LAMP、MySQL、Nginx、Redis |
| 自动化配置文件管理 | nginx.conf、my.cnf |
| 自动化部署/回退 | PHP/Java 秒级回退 |
| 自动化备份恢复 | MySQL 全量+增量+binlog + crond |
| 自动化信息采集 | Zabbix + Shell 监控硬件/服务/网络 |
| 自动化日志分析 | 取值 → 排序 → 去重 → 统计 |
| 自动化扩缩容 | CPU 高 → 调云 API 开机 → 加入集群 |

## 三、Shell 脚本是什么

1. 是若干系统命令的有序堆积
2. **特定格式 + 特定语法 + 系统命令 = Shell 脚本文件**
3. 不会手工搭建/执行的程序,写脚本必然写不会

---

## 四、脚本的基本格式

```bash
#!/bin/bash               # Shebang,声明解释器
# Author: foo             # 注释
echo "Hello world"        # 命令体
```

> Shebang 位置必须**在文件第一行第一列**,否则会被当作普通注释。

---

## 五、脚本的执行方式

| 方式 | 命令 | 是否需要执行权限 | 是否新建子 Shell |
|------|------|------|------|
| 1. 解释器执行 | `bash test.sh` | 否 | 是 |
| 2. 路径执行 | `./test.sh` | 是 (chmod +x) | 是 |
| 3. source/`.` | `source test.sh` 或 `. test.sh` | 否 | **否**(当前 Shell 执行) |

```
执行方式差异示意
┌─────────────────────────────────────────────┐
│ 当前 Shell                                  │
│                                             │
│  bash test.sh   ──fork──▶  ┌──────────┐    │
│                            │ 子 Shell │    │
│  ./test.sh      ──fork──▶  │ 执行脚本 │    │
│                            └──────────┘    │
│  source test.sh ──同进程──▶ 当前 Shell 执行 │
└─────────────────────────────────────────────┘
```

## 六、Bash 常用特性

1. **命令/路径补全**:`Tab` 键 (单击补全,双击列举可选项)
2. **历史命令**:`history`、`!n`、`!str`、`Ctrl+R` 搜索
3. **别名**:`alias`、`unalias`,永久写入 `~/.bashrc`
4. **常用快捷键**

   | 快捷键 | 含义 |
   |--------|------|
   | Ctrl+A / Ctrl+E | 行首 / 行尾 |
   | Ctrl+U / Ctrl+K | 删到行首 / 删到行尾 |
   | Ctrl+W | 删除前一个单词 |
   | Ctrl+L | 清屏 (= `clear`) |
   | Ctrl+C / Ctrl+Z | 中断 / 挂起 |
   | Ctrl+D | 退出当前 Shell / EOF |
   | Ctrl+R | 历史搜索 |
   | Ctrl+Y | 粘贴最近删除的内容 |

5. **作业控制**:`&` 后台、`jobs`、`fg`、`bg`、`screen`、`nohup`
6. **输入输出重定向**

   | 符号 | 含义 |
   |------|------|
   | `>` / `>>` | 标准输出覆盖 / 追加 |
   | `1>` / `2>` | 标准输出 / 标准错误 |
   | `2>&1` | 错误重定向到标准输出 |
   | `&>` | 标准输出与错误都重定向 |
   | `<` | 标准输入重定向 |
   | `<<EOF ... EOF` | here-document |

7. **管道与 tee**:`cmd1 | cmd2`、`cmd | tee file`
8. **命令排序**

   | 操作符 | 含义 |
   |--------|------|
   | `;` | 顺序执行,无逻辑关系 |
   | `&&` | 前者成功才执行后者 |
   | `\|\|` | 前者失败才执行后者 |

9. **Shell 通配符 (Globbing)**

   | 通配符 | 含义 |
   |--------|------|
   | `*` | 匹配任意多个字符 |
   | `?` | 匹配任意单个字符 |
   | `[abc]` / `[a-z]` | 匹配集合中任意一个字符 |
   | `[^abc]` | 取反 |
   | `(cmd1; cmd2)` | 在子 Shell 中执行 |
   | `{1..9}` 或 `{a,b,c}` | 集合扩展,如 `touch f{1..5}` |
   | `\` | 转义符 |

10. **echo 颜色 与 printf**

```bash
# echo -e 启用转义;\033[<前景色>m 文本 \033[0m 还原
echo -e "\033[31m 红色字 \033[0m"   # 31=红 32=绿 33=黄 34=蓝 35=紫 36=青 37=白

# printf 格式化
printf "%-10s %5d\n" "name" 99
```

> 颜色代码:30 黑 / 31 红 / 32 绿 / 33 黄 / 34 蓝 / 35 紫 / 36 青 / 37 白。

## 七、原文档错误订正

| # | 原文 | 问题 | 正确写法 |
|---|------|------|----------|
| 1 | `# ./tmp/test` | 当前目录下应使用 `./test`,`./tmp/test` 表示当前目录的 `tmp/test` 子路径,与实际不符 | `./test` 或绝对路径 `/tmp/test` |
| 2 | "[] 匹配 a-z,0-9,A-Z,a-Z" | `a-Z` 不是合法字符类范围 | `[a-zA-Z0-9]` |
| 3 | "命令补全 …… table" | 键名拼写错误 | **Tab** 键 |
| 4 | "&> 输出重定向" 未提 `2>&1` | 缺少错误流重定向到标准流的写法 | 补充 `2>&1` 与 `&>` 是等价(bash) |
| 5 | echo 颜色未说明 `-e` 必加 | 不加 `-e` 转义字符不生效 | `echo -e "\033[31m...\033[0m"` |
