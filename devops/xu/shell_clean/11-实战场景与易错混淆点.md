### 场景 1:服务健康检查 + 自愈

**业务背景**:Nginx/PHP-FPM/MySQL 等关键进程偶尔会因 OOM 或代码 BUG 挂掉,需要 1 分钟级别自愈,并发短信/邮件告警。

**涉及知识点**:进程/端口检测(条件测试)、`if`/`elif`、函数封装、crontab。

```
┌────────────────────────────────────────────────────┐
│ 1 分钟一次 (crontab)                                │
│         │                                          │
│         ▼                                          │
│   ┌─ ss -lnt 端口在监听? ─ 是 ─▶ exit 0            │
│   │                                                │
│   └─ 否 ── pgrep 进程存在? ─ 是 ─▶ reload         │
│                              └ 否 ─▶ start         │
│                                       │            │
│                                       ▼            │
│                                  mail/钉钉告警      │
└────────────────────────────────────────────────────┘
```

```bash
#!/usr/bin/bash
# /usr/local/bin/health_nginx.sh
# crontab: * * * * * /usr/local/bin/health_nginx.sh

PORT=80
LOCK=/var/run/health_nginx.lock
LOG=/var/log/health_nginx.log

# 防止重叠执行(flock 文件锁)
exec 9>"$LOCK"
flock -n 9 || exit 0

notify() {
    echo "[$(date '+%F %T')] $*" | tee -a "$LOG" | \
        mail -s "Nginx Alert on $(hostname)" ops@example.com
}

if ss -lnt | awk -v p=":$PORT" '$4 ~ p"$"{found=1} END{exit !found}'; then
    exit 0    # 端口正常,什么都不做
fi

if pgrep -x nginx &>/dev/null; then
    /usr/sbin/nginx -s reload && notify "nginx 端口异常,已 reload"
else
    /usr/sbin/nginx          && notify "nginx 未运行,已启动"
fi
```

**关键技巧**:

- `flock -n 9` 防止脚本被同一秒触发多次同时跑(典型坑:cron 每分钟跑一次,但脚本耗时 70 秒)。
- 用 `ss` 而非 `netstat`(新系统已废弃 netstat)。
- 告警与日志同时输出,便于事后排查。

### 场景 2:Nginx 访问日志分析(三连击)

**业务背景**:线上突然慢 / 5xx 飙升,需要 10 秒内拿到 "谁在攻击我"、"哪些 URL 是热点"、"状态码分布"。

**涉及知识点**:awk 数组、模式动作、`sort | uniq -c`、`printf` 格式化。

```bash
LOG=/var/log/nginx/access.log

# (1) TOP 10 来源 IP
awk '{ip[$1]++} END{for(k in ip) print ip[k], k}' "$LOG" | sort -rn | head

# (2) TOP 10 热点 URL(只看 200)
awk '$9==200 {u[$7]++} END{for(k in u) print u[k], k}' "$LOG" | sort -rn | head

# (3) 状态码分布
awk '{c[$9]++} END{for(k in c) printf "%-5s %d\n", k, c[k]}' "$LOG" | sort

# (4) 找慢请求(假设 $11 是 $request_time)
awk '$11+0 > 1 {print $11, $1, $7}' "$LOG" | sort -rn | head

# (5) 时段过滤 + 状态码联合统计(凌晨高峰 02:00-03:00 的 5xx)
awk '$4 ~ /:02:/ && $9 >= 500 {c[$9]++} END{for(k in c) print k, c[k]}' "$LOG"
```

**封装为可复用脚本**

```bash
#!/usr/bin/bash
# nlog.sh — Nginx 日志快速分析
LOG=${1:-/var/log/nginx/access.log}
DATE=${2:-$(date +%d/%b/%Y)}    # 默认今天,格式 22/May/2026

echo "===== TOP 10 IP ====="
awk -v d="$DATE" '$4 ~ d {ip[$1]++} END{for(k in ip) print ip[k],k}' "$LOG" \
    | sort -rn | head

echo "===== Status Code ====="
awk -v d="$DATE" '$4 ~ d {c[$9]++} END{for(k in c) print k,c[k]}' "$LOG" \
    | sort -k1

echo "===== TOP 10 URL ====="
awk -v d="$DATE" '$4 ~ d {u[$7]++} END{for(k in u) print u[k],k}' "$LOG" \
    | sort -rn | head
```

> 用 `-v` 传变量比拼接字符串安全得多 —— 避免单引号嵌套地狱。

### 场景 3:批量远程操作(免密 + 并发 + 错误收集)

**业务背景**:50 台机器同时执行升级脚本,要求统计成功/失败,失败的列出主机名。

**涉及知识点**:expect 分发秘钥、`{} &` 并发、`wait`、临时文件聚合、参数化。

```
┌──────────────┐       ┌──────────────────┐
│ hosts.txt    │       │ run_remote.sh    │
│ 1 主机/行    │  ───▶ │  并发 ssh        │
└──────────────┘       │  结果写 /tmp/$$/  │
                       └────────┬─────────┘
                                ▼
                       汇总输出 OK / FAIL
```

```bash
#!/usr/bin/bash
# run_remote.sh hosts.txt "命令"
HOSTS=$1
CMD=$2
[ -z "$HOSTS" ] || [ -z "$CMD" ] && { echo "Usage: $0 hosts.txt 'cmd'"; exit 1; }

WORKDIR=$(mktemp -d)
trap 'rm -rf "$WORKDIR"' EXIT

run_one() {
    local host=$1
    if ssh -o BatchMode=yes -o ConnectTimeout=5 "$host" "$CMD" \
           &> "$WORKDIR/$host.log"; then
        echo "$host" >> "$WORKDIR/ok.list"
    else
        echo "$host" >> "$WORKDIR/fail.list"
    fi
}

# 并发,但限制并发数 = 10
N=10
i=0
while read -r host; do
    [ -z "$host" ] && continue
    run_one "$host" &
    (( ++i % N == 0 )) && wait        # 每 N 个等一次
done < "$HOSTS"
wait

ok=$(wc -l < "$WORKDIR/ok.list"   2>/dev/null || echo 0)
fail=$(wc -l < "$WORKDIR/fail.list" 2>/dev/null || echo 0)
echo "OK=$ok  FAIL=$fail"
[ "$fail" -gt 0 ] && { echo "失败主机:"; cat "$WORKDIR/fail.list"; }
```

**关键技巧**:

- `mktemp -d` + `trap ... EXIT` 自动清理临时目录,避免泄露。
- `ssh -o BatchMode=yes`:不交互密码,失败直接退出(适合脚本)。
- `(( ++i % N == 0 )) && wait`:限制并发,避免一次性 fork 几百个进程把跳板机打爆。

### 场景 4:MySQL 备份(全量+保留 N 天)

**业务背景**:每天凌晨备份,保留 7 天,失败要告警。

**涉及知识点**:`date` 格式化、`find -mtime`、`set -e`、退出码 trap。

```bash
#!/usr/bin/bash
set -euo pipefail
set -o errtrace

BACKUP_DIR=/data/backup/mysql
KEEP_DAYS=7
DATE=$(date +%F)
FILE="$BACKUP_DIR/all-${DATE}.sql.gz"

mkdir -p "$BACKUP_DIR"

on_error() {
    echo "Backup FAILED at line $1" | mail -s "MySQL Backup FAILED $(hostname)" ops@x.com
}
trap 'on_error $LINENO' ERR

# 1. 备份
mysqldump --defaults-file=/etc/my-backup.cnf \
          --single-transaction --master-data=2 --routines --events \
          --all-databases | gzip > "$FILE"

# 2. 校验(0 字节 = 失败)
[ -s "$FILE" ] || { echo "empty backup file"; exit 1; }

# 3. 清理过期
find "$BACKUP_DIR" -name 'all-*.sql.gz' -mtime +"$KEEP_DAYS" -delete

echo "Backup OK: $FILE ($(du -h "$FILE" | cut -f1))"
```

**关键技巧**:

- `set -e` 任一命令失败立即退出;`set -u` 引用未定义变量报错;`set -o pipefail` 管道中任一段失败都算失败。
- 把密码写到 `/etc/my-backup.cnf`(chmod 600),用 `--defaults-file`,避免命令行 `-p密码` 被 `ps` 看到。
- `find -mtime +N -delete`:**+N 是大于 N 天**,严格意义上 `-mtime +6` ≈ "7 天前的"。

### 场景 5:资源监控告警(CPU / 内存 / 磁盘 / inode)

**业务背景**:磁盘满 90%、内存使用 85% 时邮件告警,inode 用尽更隐蔽,常被忽略。

**涉及知识点**:`awk` 算术、关联数组聚合、阈值判断、`printf`。

```bash
#!/usr/bin/bash
THRESH_DISK=85
THRESH_INODE=85
THRESH_MEM=85

ALERTS=()

# 1. 磁盘容量
while read -r mount used; do
    used=${used%\%}
    [ "$used" -ge "$THRESH_DISK" ] && \
        ALERTS+=("DISK $mount 已用 ${used}%")
done < <(df -P | awk 'NR>1 && $1 !~ /tmpfs|devtmpfs/ {print $6, $5}')

# 2. inode
while read -r mount used; do
    used=${used%\%}
    [ "$used" -ge "$THRESH_INODE" ] && \
        ALERTS+=("INODE $mount 已用 ${used}%")
done < <(df -iP | awk 'NR>1 && $1 !~ /tmpfs|devtmpfs/ {print $6, $5}')

# 3. 内存(用 MemAvailable,而非 free+buffers)
read total avail < <(awk '/^MemTotal/{t=$2} /^MemAvailable/{a=$2} END{print t,a}' /proc/meminfo)
pct=$(( (total - avail) * 100 / total ))
[ "$pct" -ge "$THRESH_MEM" ] && ALERTS+=("MEM 已用 ${pct}%")

# 4. 推送
if [ ${#ALERTS[@]} -gt 0 ]; then
    printf '%s\n' "${ALERTS[@]}" | \
        mail -s "[ALERT] $(hostname) 资源告警" ops@x.com
fi
```

**关键技巧**:

- 内存判断**用 `MemAvailable`**(内核 3.14+ 提供),它是真正"应用还能用的内存",比 `free -m` 里 `used` 准确。
- `< <(cmd)` 进程替换,避免 `cmd | while` 在管道里跑 → 数组无法保留到外层。**这是大坑,见易错点 6**。

### 场景 6:发布部署(回滚友好的"软链切换"模式)

**业务背景**:Java/前端代码每次发布,要求 < 1 秒完成切换 + 出问题立刻回滚。

**涉及知识点**:目录结构设计、软链、参数解析、回滚命令。

```
/opt/app/
├── releases/
│   ├── 20260601-101530/   <- 新版本
│   ├── 20260531-180000/   <- 旧版本
│   └── 20260530-093015/
├── current  ─symlink─▶ releases/20260601-101530/
└── shared/                <- logs / uploads 不随版本切换
```

```bash
#!/usr/bin/bash
set -euo pipefail
APP=/opt/app
ART=$1                   # 新版本 tar 包路径
TS=$(date +%Y%m%d-%H%M%S)
NEW="$APP/releases/$TS"

deploy() {
    mkdir -p "$NEW"
    tar xzf "$ART" -C "$NEW"

    # 链接共享目录
    ln -snf "$APP/shared/logs"    "$NEW/logs"
    ln -snf "$APP/shared/uploads" "$NEW/uploads"

    # 原子切换:rm + ln 不原子,改用 mv
    ln -sfn "$NEW" "$APP/current.new"
    mv -Tf  "$APP/current.new" "$APP/current"

    systemctl reload app

    # 只保留最近 5 个版本
    cd "$APP/releases" && ls -1t | tail -n +6 | xargs -r rm -rf
}

rollback() {
    cd "$APP/releases"
    prev=$(ls -1t | sed -n '2p')   # 倒数第二新
    ln -sfn "$APP/releases/$prev" "$APP/current.new"
    mv -Tf  "$APP/current.new" "$APP/current"
    systemctl reload app
    echo "Rolled back to $prev"
}

case "${1:-}" in
    rollback) rollback ;;
    *)        [ -f "$ART" ] && deploy || { echo "artifact not found"; exit 1; }
esac
```

**关键技巧**:

- `ln -sfn` + `mv -Tf` 才能**原子地**切换符号链接(`rm -f && ln -s` 中间有零点几毫秒的真空期,高并发会 404)。
- 用时间戳命名版本目录,天然按字典序就是时间序。
- `xargs -r`:输入为空时不执行命令(GNU 扩展)。

### 场景 7:文件批处理(按时间归档 + 清理)

**业务背景**:日志按天滚动 + 7 天前的打包到 S3 / 删除。

```bash
#!/usr/bin/bash
DIR=/var/log/app
KEEP_DAYS=7

# 1. 把昨天的日志压缩
YDAY=$(date -d 'yesterday' +%F)
find "$DIR" -maxdepth 1 -name "app-${YDAY}*.log" \
    -exec gzip -9 {} +

# 2. 上传 30 天前的到对象存储(可选)
find "$DIR" -name '*.log.gz' -mtime +30 -print0 | \
    while IFS= read -r -d '' f; do
        aws s3 cp "$f" "s3://archive/$(basename "$f")" && rm -f "$f"
    done

# 3. 删除超过保留期的本地文件
find "$DIR" -name '*.log.gz' -mtime +"$KEEP_DAYS" -delete
```

**find 常用模式速查**:

| 需求 | 命令 |
|------|------|
| 大于 100M 的文件 | `find . -size +100M` |
| 7 天没访问 | `find . -atime +7` |
| 名字含空格也安全的循环 | `find ... -print0 \| xargs -0 ...` 或 `while IFS= read -r -d ''` |
| 防止符号链接被跟随 | `find . -maxdepth 1 -type f` |

## Part B. Shell 易错混淆点(分类清单)

### B1. 空格陷阱

| 错误 | 报错 / 现象 | 正确 |
|------|------------|------|
| `a =1` | `command not found: a` | `a=1` (等号两侧**禁止空格**) |
| `[ -z $a ]` 当 a 为空 | `[: =: unary operator expected` | `[ -z "$a" ]` (变量加引号) |
| `[-d /tmp]` | `[-d: command not found` | `[ -d /tmp ]` (中括号内左右各加空格) |
| `if [ $a == "x"]` | 语法错 | `if [ "$a" = "x" ]` |
| `$(( a +b ))` | 通常 OK | 推荐 `$(( a + b ))` 风格统一 |

**口诀**:`=` 两侧无空格,`[ ]` 两侧有空格,变量加双引号。

---

### B2. 引号陷阱

```bash
name="Tom Cat"

echo $name         # Tom Cat — 但分词成 2 个参数
echo "$name"       # Tom Cat — 1 个参数(推荐)
echo '$name'       # 字面量 $name

# awk/sed 内的 $ 容易和 shell 抢
awk "{print $1}"   file    # ✗ $1 被 shell 先展开为空
awk '{print $1}'   file    # ✓ 单引号保留 awk 的 $1

# 但单引号内**不能再有单引号**,只能用拼接:
echo 'it'\''s ok'           # → it's ok
```

**规则**:

- 默认就用**双引号**包变量,**单引号**包正则 / awk / sed 模板。
- 单引号内不能再用 `'`,必须 "断开-转义-拼接"。

---

### B3. 变量陷阱

```bash
# 1. 未定义变量不会报错 → 静默灾难
rm -rf "$DIR/"          # 如果 $DIR 未定义,变成 rm -rf /
# 解决:set -u 或 ${DIR:?DIR is required}

# 2. $$ vs $? vs $!
echo $$        # 当前 shell PID
echo $?        # 上一条命令退出码
echo $!        # 最近一个后台进程 PID

# 3. $* vs "$@"
fn() { for i in "$@"; do echo "[$i]"; done; }
fn "a b" c
# "$@" → [a b] [c]    (推荐)
# "$*" → [a b c]      (合并成一个串)

# 4. 命令替换会去掉行尾换行
files=$(ls)        # 末尾换行被吃掉,中间换行保留 → 用 mapfile 更安全

# 5. local 必须在函数内,且要单独一行
fn() {
    local x=$(false || echo 1)   # x="1" 但 $? = 0 (local 本身成功)
}
# 正确:
fn() {
    local x
    x=$(false || echo 1)         # 现在 $? 反映命令真实结果
}
```

### B4. 比较运算陷阱

| 操作符位置 | 数值比较 | 字符串比较 |
|------------|----------|------------|
| `[ ]` 内 | `-eq -ne -gt -lt -ge -le` | `=` `!=` `-z` `-n` |
| `[[ ]]` 内 | 同上,也可 `((a > b))` | `=`/`==` `!=` `=~` `<` `>` |
| `(( ))` 内 | `> < == != >= <=` | 不适用 |

**典型坑**:

```bash
# ① 字符串比较用 -gt 报错或得到意外结果
[ "1.5" -gt "1.0" ]      # error: integer expression expected

# ② 把字符串当数字
ver="3.10"
[ "$ver" = "3.1" ] && echo eq    # eq?——字符串当然不等,但写法对
# 真要比较版本号,用 sort -V

# ③ 整数前导 0 在 (( )) 中被当 8 进制
n=08
echo $(( n + 1 ))     # ✗ value too great for base
echo $(( 10#$n + 1 )) # ✓ 强制 10 进制
```

### B5. 退出码 / 返回值

```bash
# ① 函数 return 只能 0-255
fn() { return 1000; }
fn
echo $?    # 232,不是 1000(1000 mod 256)
# 真要返数据用 echo + $()

# ② 管道中 $? 是最后一段的状态
false | true
echo $?      # 0 ← 容易被骗
# 解决:set -o pipefail   或   ${PIPESTATUS[0]}

echo "${PIPESTATUS[@]}"   # 0 0 ... 每段的退出码

# ③ if 判断的是退出码,不是布尔值
if grep -q foo file; then ...   # ✓ grep 找到返回 0,if 成立
# if [ $(grep -c foo file) -gt 0 ]; then ...   # 啰嗦,易错
```

### B6. 管道与子 shell(最容易踩的坑)

```bash
# 问题:while 在管道里,运行在子 shell,外层看不到变量变化
count=0
ls | while read f; do
    (( count++ ))
done
echo "$count"     # 始终是 0 !

# 解法 1:进程替换(推荐)
count=0
while read f; do
    (( count++ ))
done < <(ls)
echo "$count"     # 正确

# 解法 2:bash 4.2+ 设置 lastpipe
shopt -s lastpipe
ls | while read f; do (( count++ )); done   # 在交互式可能仍异常,脚本里 OK
```

```
                  ┌── 主 shell ──┐
ls │ while …       │              │
─►──┼─管道─►──┐    │   count=0    │
              ▼    │              │
        ┌── 子 shell ──┐          │
        │ count++ 在这边│          │
        └──────────────┘          │
                  ▲ 退出时变量丢失 │
                  └────────────────┘
```

**记忆**:**管道的每一段都是子 shell** → 修改变量不会带回主 shell。

### B7. 数组陷阱

```bash
# ① arr=(*.txt) 当没有 txt 文件时,会得到字面字符串 "*.txt"
shopt -s nullglob       # 让通配符无匹配时返回空
arr=(*.txt)
echo "${#arr[@]}"

# ② "${arr[@]}" vs "${arr[*]}" 加双引号才有差异
arr=("a b" "c d")
for x in "${arr[@]}"; do echo "[$x]"; done   # [a b] [c d]
for x in "${arr[*]}"; do echo "[$x]"; done   # [a b c d]  ← 合并成一个

# ③ 关联数组必须 declare -A,否则被当作普通数组(键变成 0)
declare -A m
m[name]=tom
echo "${m[name]}"

# ④ 删除元素 vs 删除整个数组
unset 'arr[1]'      # 删除第 1 个元素(下标 1)
unset arr           # 删除整个数组
# 注意:unset arr[1] 不加引号在某些 shell 会被通配符展开
```

### B8. 重定向陷阱

```bash
# ① 顺序很关键:>file 2>&1  ≠  2>&1 >file
cmd >file 2>&1      # ✓ stderr 跟着 stdout 都进 file
cmd 2>&1 >file      # ✗ stderr 还在终端(2>&1 时 stdout 还指向终端)

# 简写
cmd &>file          # = >file 2>&1

# ② 追加 vs 覆盖
>file               # 立即清空 file(危险!)
echo x > file       # 也是覆盖
echo x >> file      # 追加

# ③ Here-Doc 的 - 用法
cat <<EOF
    缩进会保留
EOF

cat <<-EOF
	行首 Tab 会被去掉(必须是 Tab,不是空格)
	EOF
```

### B9. 命令替换陷阱

```bash
# ① 反引号嵌套需要转义,$() 可以裸嵌套
a=`echo \`whoami\``      # 反引号,可读性差
a=$(echo $(whoami))      # 推荐

# ② 命令替换会吃掉末尾换行符,中间保留
text=$(printf "a\nb\n")
echo "$text"             # a\nb (末尾 \n 被吃)

# ③ 把 read 的结果保留到外层 → 用进程替换
read a b < <(echo "1 2")
echo "$a $b"             # 1 2
```

### B10. 通配符 vs 正则的混淆

| 通配符(glob) | 正则(regex) |
|----------------|----------------|
| `*` = 任意字符串 | `*` = 前一项 0 次或多次 |
| `?` = 1 个字符 | `?` = 前一项 0 或 1 次 |
| `[abc]` = 集合 | `[abc]` = 集合(相同) |
| `{a,b,c}` = 集合扩展 | 无(awk 等不支持 brace expansion) |
| 没有 `+` `\|` | 有 `+` `\|` |

**使用场所**:

- `ls *.log`、`for f in *.txt`、`case $x in *.gz)` ← **glob**
- `grep`、`sed`、`awk`、`[[ $x =~ ... ]]` ← **regex**

**血泪教训**:`if [[ $f == *.log ]]`(glob) ≠ `if [[ $f =~ .*\.log ]]`(regex);记住语境。

### B11. set 选项速查(写脚本必加)

```bash
#!/usr/bin/bash
set -e            # 任一命令失败立即退出
set -u            # 引用未定义变量报错
set -o pipefail   # 管道中任一段失败 → 整管道失败
set -x            # 调试:每条命令打印出来(发布前关掉)

# 一行写法:
set -euo pipefail
```

> 一句话:**严肃脚本头三行就该写 `set -euo pipefail`**。绝大多数静默灾难都能在这一行被拦下。

### B12. 路径与目录陷阱

```bash
# ① 脚本里的相对路径相对的是"调用者的 CWD",不是脚本目录
SELF_DIR=$(cd "$(dirname "$0")" && pwd)    # 始终是脚本所在目录
source "$SELF_DIR/lib.sh"

# ② cd 失败仍继续,可能在错的目录干活
cd /opt/foo && rm -rf *     # ✓ 用 && 链接
# 危险:
cd /opt/foo
rm -rf *                    # 如果 cd 失败,在当前目录 rm !

# ③ 用 mktemp 而不是 /tmp/xxx
tmp=$(mktemp)               # 自动唯一,不可预测,防符号链接攻击
trap 'rm -f "$tmp"' EXIT
```

## 附:工作中"先这样写"模板(粘贴即用)

```bash
#!/usr/bin/bash
#
# 用途:xxx
# 用法:$0 [options] args
#

set -euo pipefail
trap 'echo "ERROR at line $LINENO" >&2' ERR

SELF_DIR=$(cd "$(dirname "$0")" && pwd)
LOCK="/var/run/$(basename "$0" .sh).lock"
LOG="/var/log/$(basename "$0" .sh).log"

# 单实例
exec 9>"$LOCK"
flock -n 9 || { echo "another instance running"; exit 1; }

log() { printf '[%s] %s\n' "$(date '+%F %T')" "$*" | tee -a "$LOG"; }

main() {
    log "begin"
    # ... 业务 ...
    log "end OK"
}

main "$@"
```

把这段当骨架,**任何严肃脚本**都该有这 7 件事:
1. shebang
2. `set -euo pipefail`
3. `trap ERR`
4. `SELF_DIR` 自定位
5. `flock` 单实例
6. `log` 函数 + 日志文件
7. `main "$@"` 入口
