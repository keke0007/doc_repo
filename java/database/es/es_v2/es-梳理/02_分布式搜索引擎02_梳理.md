## 一、DSL 查询体系完全梳理

### 1.1 查询类型五分类

Elasticsearch 提供的查询类型按功能分为五大类：

| 类型 | 代表方法 | 使用场景 | 分词处理 |
|------|--------|--------|---------|
| **查询所有** | match_all | 测试/全量检索 | 否 |
| **全文检索** | match, multi_match | 搜索框、文本搜索 | 是(分词后匹配) |
| **精准查询** | term, range | keyword/数值/日期/布尔字段 | 否(精确匹配) |
| **地理查询** | geo_distance, geo_bounding_box | 附近地点、范围查询 | 否(坐标) |
| **复合查询** | bool, function_score | 多条件组合、自定义算分 | 混合 |

---

### 1.2 全文检索查询详解

#### 定义与原理
全文检索是对用户输入内容先分词，然后去倒排索引库中匹配的过程：
1. 分词：用分词器(如 IK)将输入内容分解为词条
2. 倒排索引匹配：找出包含这些词条的文档 ID
3. 返回文档：根据相关度打分后返回

#### match 查询 (单字段)

**DSL 语法：**
```json
GET /hotel/_search
{
  "query": {
    "match": {
      "name": "如家酒店"
    }
  }
}
```

**Java RestHighLevelClient 实现：**
```java
SearchRequest request = new SearchRequest("hotel");
request.source().query(QueryBuilders.matchQuery("name", "如家酒店"));
SearchResponse response = client.search(request, RequestOptions.DEFAULT);
```

**易混淆点：**
- match 会对输入分词，然后用分词后的任何词条匹配都可以
- 只适用于 text 类型字段(可分词字段)

#### multi_match 查询 (多字段)

**DSL 语法：**
```json
GET /hotel/_search
{
  "query": {
    "multi_match": {
      "query": "外滩如家",
      "fields": ["name", "business"]
    }
  }
}
```

**Java 实现：**
```java
request.source().query(QueryBuilders.multiMatchQuery("外滩如家", "name", "business"));
```

**性能对比与优化建议：**
- multi_match 查询多个字段会降低性能
- 优化方案：使用 copy_to 将多字段值复制到单个 all 字段，然后单字段查询
- 效果相同但性能更优

---

### 1.3 精准查询详解

精准查询对搜索条件**不分词**，需要精确匹配。仅用于 keyword、数值、日期、布尔等不分词字段。

#### term 查询 (词条精确匹配)

**DSL 语法：**
```json
GET /hotel/_search
{
  "query": {
    "term": {
      "brand": {
        "value": "如家"
      }
    }
  }
}
```

**Java 实现：**
```java
request.source().query(QueryBuilders.termQuery("brand", "如家"));
```

**易混淆点：**
- term 不分词，输入内容必须与字段值完全匹配
- 若输入多词语(短语)，无法匹配(这是与 match 的本质区别)

#### range 查询 (范围查询)

**DSL 语法：**
```json
GET /hotel/_search
{
  "query": {
    "range": {
      "price": {
        "gte": 100,   // 大于等于
        "lte": 500    // 小于等于
      }
    }
  }
}
```

**Java 实现：**
```java
request.source().query(QueryBuilders.rangeQuery("price").gte(100).lte(500));
```

**范围操作符说明：**
| 符号 | 含义 | 符号 | 含义 |
|------|------|------|------|
| gte | 大于等于 | gt | 大于 |
| lte | 小于等于 | lt | 小于 |

### 1.4 地理坐标查询详解

地理坐标查询根据经纬度进行空间位置查询，适用场景：携程附近酒店、滴滴附近出租车。

#### geo_bounding_box 查询 (矩形范围)

**原理：** 指定矩形的左上、右下两个顶点坐标，落在矩形内的文档符合条件。

**DSL 语法：**
```json
GET /hotel/_search
{
  "query": {
    "geo_bounding_box": {
      "location": {
        "top_left": {
          "lat": 31.24,
          "lon": 121.4
        },
        "bottom_right": {
          "lat": 31.19,
          "lon": 121.55
        }
      }
    }
  }
}
```

#### geo_distance 查询 (圆形范围/附近查询)

**原理：** 以指定坐标为圆心，以距离值为半径，画一个圆，圆内的坐标符合条件。

**DSL 语法：**
```json
GET /hotel/_search
{
  "query": {
    "geo_distance": {
      "distance": "15km",
      "location": "31.03,121.6"
    }
  }
}
```

**Java 实现：**
```java
request.source().query(QueryBuilders.geoDistanceQuery("location")
    .point(31.03, 121.6)
    .distance(15, DistanceUnit.KILOMETERS));
```

### 1.5 复合查询 (进阶)

#### 1.5.1 相关性算分体系

**算分演变历史：**
- ES 5.1 版本前：TF-IDF 算法
- ES 5.1 版本后：BM25 算法(现行标准)

**BM25 vs TF-IDF 的优势：**
- TF-IDF：词条频率越高得分越高，单词影响过大
- BM25：单个词条有算分上限，曲线更平滑，更符合实际

**match 查询中的算分：**
```json
// 查询返回示例
{
  "hits": [
    {
      "_score": 17.850193,
      "_source": {"name": "虹桥如家酒店真不错"}
    },
    {
      "_score": 12.259849,
      "_source": {"name": "外滩如家酒店真不错"}
    }
  ]
}
```

#### 1.5.2 function_score 查询 (算分函数)

**核心概念：** 允许自定义改变文档的相关性算分。

**四部分组成：**

1. **原始查询** (query)：基础查询条件，得到初始 query score
2. **过滤条件** (filter)：决定哪些文档要修改算分
3. **算分函数** (functions)：计算 function score 的方法
4. **运算模式** (boost_mode)：query score 与 function score 如何运算

**常用算分函数：**
| 函数 | 说明 | 使用场景 |
|------|------|--------|
| weight | 固定常量 | 简单加权(广告/推荐) |
| field_value_factor | 文档字段值 | 按热度加权 |
| random_score | 随机数 | 随机排序 |
| script_score | 自定义脚本 | 复杂算法 |

**运算模式选项：**
```
multiply  (默认): score_new = query_score * function_score
replace:          score_new = function_score  (替换原分)
sum/avg/max/min:  四则运算组合
```

**DSL 示例：给"希尔顿"品牌酒店加权**
```json
GET /hotel/_search
{
  "query": {
    "function_score": {
      "query": {
        "match": {"name": "如家酒店"}
      },
      "functions": [
        {
          "filter": {"term": {"brand": "希尔顿"}},
          "weight": 1000000
        }
      ],
      "boost_mode": "multiply"
    }
  }
}
```

**Java 实现：**
```java
FunctionScoreQueryBuilder functionScoreQuery = QueryBuilders.functionScoreQuery(
    // 原始查询
    QueryBuilders.matchQuery("name", "如家酒店"),
    // function score 数组
    new FunctionScoreQueryBuilder.FilterFunctionBuilder[]{
        new FunctionScoreQueryBuilder.FilterFunctionBuilder(
            QueryBuilders.termQuery("brand", "希尔顿"),
            ScoreFunctionBuilders.weightFactorFunction(1000000)
        )
    }
);
request.source().query(functionScoreQuery);
```

#### 1.5.3 bool 查询 (布尔组合)

**核心概念：** 将多个子查询用逻辑关系组合。

**四种逻辑关系：**

| 子句 | 含义 | 参与打分 | 应用场景 |
|------|------|--------|--------|
| must | 必须匹配(与) | **是** | 核心搜索条件 |
| should | 选择匹配(或) | **是** | 可选条件，提高相关度 |
| must_not | 必须不匹配(非) | **否** | 排除条件 |
| filter | 必须匹配 | **否** | 过滤条件，缓存友好 |

**query vs filter 执行路径对比：**
```
┌─────────────────────────────────────────┐
│           Bool 查询执行流程              │
├──────────────┬────────────────────────┤
│   must/should│  1. 找出匹配文档      │
│  (参与打分)  │  2. BM25 算分        │
│              │  3. 按 _score 排序   │
├──────────────┼────────────────────────┤
│ filter/must_│  1. 找出匹配文档      │
│  not(不打分) │  2. 结果缓存         │
│              │  3. 不排序(快)       │
└──────────────┴────────────────────────┘
```

**DSL 示例：搜索上海的非低价酒店，优先皇冠假日或7天**
```json
GET /hotel/_search
{
  "query": {
    "bool": {
      "must": [
        {"match": {"name": "如家酒店"}}
      ],
      "should": [
        {"term": {"brand": "皇冠假日"}},
        {"term": {"brand": "7天酒店"}}
      ],
      "must_not": [
        {"range": {"price": {"lte": 500}}}
      ],
      "filter": [
        {"term": {"city": "上海"}}
      ]
    }
  }
}
```

**Java 实现：**
```java
BoolQueryBuilder boolQuery = QueryBuilders.boolQuery();
// must: 参与打分
boolQuery.must(QueryBuilders.matchQuery("name", "如家酒店"));
// should: 参与打分(提升相关度)
boolQuery.should(QueryBuilders.termQuery("brand", "皇冠假日"));
boolQuery.should(QueryBuilders.termQuery("brand", "7天酒店"));
// must_not: 不参与打分
boolQuery.mustNot(QueryBuilders.rangeQuery("price").lte(500));
// filter: 不参与打分，可缓存
boolQuery.filter(QueryBuilders.termQuery("city", "上海"));

request.source().query(boolQuery);
```

**易混淆点：**
- must 和 filter 都是"必须"，但 filter 不参与打分(更快)
- 多条件查询时，搜索字段用 must，过滤字段用 filter

## 二、搜索结果处理

### 2.1 排序 (sort)

#### 普通字段排序

**原理：** 默认按 _score (相关度)降序排列，可指定其他字段排序。

**DSL 语法：**
```json
GET /hotel/_search
{
  "query": {"match_all": {}},
  "sort": [
    {"score": "desc"},  // 第一排序:评分降序
    {"price": "asc"}    // 第二排序:价格升序
  ]
}
```

**Java 实现：**
```java
request.source()
    .sort("score", SortOrder.DESC)
    .sort("price", SortOrder.ASC);
```

#### 地理坐标排序

**原理：** 计算每个文档的地理坐标到目标点的距离，按距离排序。

**DSL 语法：**
```json
GET /hotel/_search
{
  "query": {"match_all": {}},
  "sort": [
    {
      "_geo_distance": {
        "location": "31.034,121.612",  // 目标坐标
        "order": "asc",                  // 升序(最近在前)
        "unit": "km"                     // 单位
      }
    }
  ]
}
```

**Java 实现：**
```java
request.source().sort(SortBuilders.geoDistanceSort("location", 
    new GeoPoint("31.034,121.612"))
    .order(SortOrder.ASC)
    .unit(DistanceUnit.KILOMETERS));
```

### 2.2 分页 (from & size)

#### 基本分页

**DSL 语法：**
```json
GET /hotel/_search
{
  "from": 0,      // 起始位置(第一页从0开始)
  "size": 10,     // 每页条数
  "query": {"match_all": {}}
}
```

**Java 实现：**
```java
int page = 1, size = 10;
request.source()
    .from((page - 1) * size)
    .size(size);
```

#### 深度分页问题

**问题描述：**
- 用户要查 990~1000 的数据，`from=990, size=10`
- ES 内部需要先查出 0~1000，再截取 990~1000 的结果
- 在集群模式：5 个节点的集群要从每个节点查出 TOP1000，汇总后重新排序

**性能影响：**
- 深度分页导致内存和 CPU 消耗极大
- **ES 默认禁止 from + size > 10000 的请求**

**三种分页方案对比：**

| 方案 | 优点 | 缺点 | 场景 |
|------|------|------|------|
| from + size | 支持随机翻页 | 深度分页问题，上限10000 | 百度、京东等需要随机翻页 |
| search_after | 无分页上限(size限10000) | 只能逐页向后，不支持随机跳页 | 手机向下滚动的流式分页 |
| scroll | 无分页上限 | 内存消耗大，结果非实时，ES7.1后弃用 | 海量数据导出迁移 |

### 2.3 高亮 (highlight)

#### 原理

高亮是对搜索结果中的关键字添加 HTML 标签，前端用 CSS 样式渲染。

#### 实现方式

**DSL 语法：**
```json
GET /hotel/_search
{
  "query": {
    "match": {"all": "如家酒店"}  // 必须是全文检索查询
  },
  "highlight": {
    "fields": {
      "name": {
        "pre_tags": "<em>",
        "post_tags": "</em>",
        "require_field_match": false  // 允许对非搜索字段高亮
      }
    }
  }
}
```

**Java 实现：**
```java
request.source()
    .query(QueryBuilders.matchQuery("all", "如家"))
    .highlighter(new HighlightBuilder()
        .field("name")
        .requireFieldMatch(false));
```

**结果解析：**
```java
private void handleResponse(SearchResponse response) {
    SearchHits searchHits = response.getHits();
    for (SearchHit hit : searchHits) {
        // 获取非高亮结果
        String json = hit.getSourceAsString();
        HotelDoc hotelDoc = JSON.parseObject(json, HotelDoc.class);
        
        // 获取高亮结果
        Map<String, HighlightField> highlightFields = hit.getHighlightFields();
        if (!CollectionUtils.isEmpty(highlightFields)) {
            HighlightField highlightField = highlightFields.get("name");
            if (highlightField != null) {
                // 高亮值中已包含 <em> 标签
                String highlightedName = highlightField.getFragments()[0].string();
                hotelDoc.setName(highlightedName);  // 覆盖原值
            }
        }
        System.out.println(hotelDoc);
    }
}
```

**关键要点：**
- 高亮必须配合**全文检索查询**(match/multi_match)
- 默认只能对搜索字段高亮，用 `require_field_match=false` 可对其他字段高亮
- 高亮结果在响应中单独存放，需要手动合并

## 三、RestHighLevelClient 查询实战

### 3.1 查询完整流程 (四步)

```
1. 创建 SearchRequest
   └─ new SearchRequest("indexName")
   
2. 构建 DSL (request.source())
   ├─ query():      查询条件 (QueryBuilders)
   ├─ sort():       排序条件 (SortBuilders)
   ├─ from/size():  分页条件
   ├─ highlighter():高亮条件
   └─ fetchSource():字段过滤
   
3. 发送请求
   └─ client.search(request, RequestOptions.DEFAULT)
   
4. 解析响应
   └─ SearchHits → SearchHit[] → _source
```

### 3.2 各类查询的 Java 实现

#### match_all 查询

```java
void testMatchAll() throws IOException {
```

### 3.3 响应解析

```java
private void handleResponse(SearchResponse response) {
    // 获取 hits 对象
    SearchHits searchHits = response.getHits();
    
    // 获取总条数
    long total = searchHits.getTotalHits().value;
    System.out.println("共搜索到 " + total + " 条数据");
    
    // 获取文档数组
    SearchHit[] hits = searchHits.getHits();
    
    // 遍历每个文档
    List<HotelDoc> hotels = new ArrayList<>();
    for (SearchHit hit : hits) {
        // 获取 _source (文档原始数据)
        String json = hit.getSourceAsString();
        
        // 反序列化为对象
        HotelDoc hotelDoc = JSON.parseObject(json, HotelDoc.class);
        
        // 获取排序值 (如果有排序)
        Object[] sortValues = hit.getSortValues();
        
        hotels.add(hotelDoc);
    }
    
    return new PageResult(total, hotels);
}
```

## 四、黑马旅游实战案例

### 4.1 案例架构

需要实现的功能：
1. 酒店搜索 + 分页
2. 多条件过滤 (品牌、城市、星级、价格)
3. 附近酒店排序 (基于地理坐标距离)
4. 竞价排名 (广告置顶)

### 4.2 核心实体类

**请求参数类：**
```java
@Data
public class RequestParams {
    private String key;           // 搜索关键字
    private Integer page;         // 页码
    private Integer size;         // 每页大小
    private String sortBy;        // 排序方式
    private String city;          // 城市过滤
    private String brand;         // 品牌过滤
    private String starName;      // 星级过滤
    private Integer minPrice;     // 最低价格
    private Integer maxPrice;     // 最高价格
    private String location;      // 我的位置(经纬度)
}
```

**返回结果类：**
```java
@Data
public class PageResult {
    private Long total;                 // 总条数
    private List<HotelDoc> hotels;      // 酒店列表

    public PageResult(Long total, List<HotelDoc> hotels) {
        this.total = total;
        this.hotels = hotels;
    }
}
```

**文档类：**
```java
@Data
@NoArgsConstructor
public class HotelDoc {
    private Long id;
    private String name;
    private String address;
    private Integer price;
    private Integer score;
    private String brand;
    private String city;
    private String starName;
    private String business;
    private String location;      // "纬度,经度"
    private String pic;
    private Object distance;      // 排序距离值(可选)
    private Boolean isAD;         // 是否是广告(竞价排名)
}
```

### 4.3 分步实现

#### Step 1: 基础搜索 + 分页

```java
@Override
public PageResult search(RequestParams params) {
    try {
        // 1. 创建 SearchRequest
        SearchRequest request = new SearchRequest("hotel");
        
        // 2. 构建 DSL
        // 2.1 查询条件
        String key = params.getKey();
        if (key == null || "".equals(key)) {
            request.source().query(QueryBuilders.matchAllQuery());
        } else {
            request.source().query(QueryBuilders.matchQuery("all", key));
        }
        
        // 2.2 分页
        int page = params.getPage();
        int size = params.getSize();
        request.source().from((page - 1) * size).size(size);
        
        // 3. 发送请求
        SearchResponse response = client.search(request, RequestOptions.DEFAULT);
        
        // 4. 解析响应
        return handleResponse(response);
    } catch (IOException e) {
        throw new RuntimeException(e);
    }
}
```

#### Step 2: 加入多条件过滤 (bool 查询)

```java
private void buildBasicQuery(RequestParams params, SearchRequest request) {
    // 1. 构建 BoolQueryBuilder
    BoolQueryBuilder boolQuery = QueryBuilders.boolQuery();
    
    // 2. 关键字搜索(must - 参与打分)
    String key = params.getKey();
    if (key == null || "".equals(key)) {
        boolQuery.must(QueryBuilders.matchAllQuery());
    } else {
        boolQuery.must(QueryBuilders.matchQuery("all", key));
    }
    
    // 3. 城市过滤(filter - 不参与打分)
    if (params.getCity() != null && !params.getCity().equals("")) {
        boolQuery.filter(QueryBuilders.termQuery("city", params.getCity()));
    }
    
    // 4. 品牌过滤
    if (params.getBrand() != null && !params.getBrand().equals("")) {
        boolQuery.filter(QueryBuilders.termQuery("brand", params.getBrand()));
    }
    
    // 5. 星级过滤
    if (params.getStarName() != null && !params.getStarName().equals("")) {
        boolQuery.filter(QueryBuilders.termQuery("starName", params.getStarName()));
    }
    
    // 6. 价格范围过滤
    if (params.getMinPrice() != null && params.getMaxPrice() != null) {
        boolQuery.filter(QueryBuilders.rangeQuery("price")
            .gte(params.getMinPrice())
            .lte(params.getMaxPrice()));
    }
    
    // 7. 放入 request
    request.source().query(boolQuery);
}
```

```java
private PageResult handleResponse(SearchResponse response) {
    SearchHits searchHits = response.getHits();
    long total = searchHits.getTotalHits().value;
    SearchHit[] hits = searchHits.getHits();
    
    List<HotelDoc> hotels = new ArrayList<>();
    for (SearchHit hit : hits) {
        String json = hit.getSourceAsString();
        HotelDoc hotelDoc = JSON.parseObject(json, HotelDoc.class);
        
        // 获取排序值 (第一个是距离值)
        Object[] sortValues = hit.getSortValues();
        if (sortValues.length > 0) {
            hotelDoc.setDistance(sortValues[0]);  // 距离(km)
        }
        
        hotels.add(hotelDoc);
    }
    return new PageResult(total, hotels);
}
```

## 五、关键易混淆点速查表

### 5.1 query vs filter 对比表

| 维度 | query | filter |
|------|-------|--------|
| 参与打分 | **是** | **否** |
| 执行速度 | 较慢(需计算分数) | **快**(缓存友好) |
| 缓存效果 | 不缓存 | 缓存结果 |
| 使用场景 | 全文检索、相关性搜索 | 精确过滤条件 |
| 布尔位置 | must/should | filter/must_not |

### 5.2 match vs term vs range 对比表

| 查询类型 | 是否分词 | 适用字段类型 | 示例 |
|--------|--------|-----------|------|
| **match** | **是** | text | "搜索 iPhone" → ["搜索", "iPhone"] |
| **term** | **否** | keyword | "杭州" → 精确匹配 |
| **range** | **否** | 数值/日期 | price: [100~500] |

### 5.3 bool 子句使用规则

```
must    → 搜索框关键字、核心条件(参与打分)
should  → 可选条件、增强相关度
filter  → 品牌、城市、价格等过滤(不参与打分) ★推荐
must_not→ 排除条件
```

### 5.4 function_score 三要素

```
function_score = {
  query:        原始查询 → query_score,
  functions: [{
    filter:     过滤条件 → 哪些文档加分,
    weight:     权重值 → function_score
  }],
  boost_mode:   multiply → 最终分 = query_score × function_score
}
```

### 5.5 aggregation 中的 size=0 含义

```json
{
  "query": {...},
  "size": 0,    // 不返回具体文档(只要聚合结果)
  "aggs": {
    "brand_count": {
      "terms": {"field": "brand"}
    }
  }
}
```

## 八、核心知识点速查表

### DSL 查询速查

| 查询需求 | DSL 方法 | Java API |
|--------|--------|---------|
| 查所有文档 | match_all | QueryBuilders.matchAllQuery() |
| 全文搜索(单字段) | match | QueryBuilders.matchQuery("field", "text") |
| 全文搜索(多字段) | multi_match | QueryBuilders.multiMatchQuery("text", "f1", "f2") |
| 精确匹配 | term | QueryBuilders.termQuery("field", value) |
| 范围查询 | range | QueryBuilders.rangeQuery("field").gte(x).lte(y) |
| 地理范围 | geo_bounding_box | (不常用,选择 geo_distance) |
| 附近查询 | geo_distance | QueryBuilders.geoDistanceQuery("field").point(lat, lon).distance(dist, unit) |
| 布尔组合 | bool | QueryBuilders.boolQuery().must/filter/should/mustNot(...) |
| 算分控制 | function_score | QueryBuilders.functionScoreQuery(query, functions) |

### 结果处理速查

| 功能 | DSL 参数 | Java 方法 |
|------|---------|---------|
| 排序(普通字段) | sort: [{field: desc}] | request.source().sort("field", SortOrder.DESC) |
| 排序(地理) | sort: [{_geo_distance: {...}}] | request.source().sort(SortBuilders.geoDistanceSort("field", point)) |
| 分页 | from, size | request.source().from(0).size(10) |
| 高亮 | highlight: {fields: {...}} | request.source().highlighter(new HighlightBuilder().field("field")) |
| 字段过滤 | _source: [...] | request.source().fetchSource(includes, excludes) |

### 性能优化速查表

| 场景 | 优化方案 | 理由 |
|------|--------|------|
| 多字段搜索 | 用 copy_to 复制到 all 字段 + 单字段 match | 避免 multi_match 的性能开销 |
| 大量过滤条件 | 用 filter 而非 must | filter 结果可缓存，速度快 |
| 深度分页 | 用 search_after 而非 from+size | 避免汇总 TOP10000 的内存压力 |
| 需要广告排名 | 用 function_score 而非重排 | 在查询时直接改分，避免应用层重排 |
