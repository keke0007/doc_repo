requirements.txt用法

写python程序的时候，我们经常的会下载很多外部模块，当我们编写完成后，准备在其他设备上部署的时候，那么新设备上需要安装我当前环境下的所有包，如果一个个找显然是挖坑埋自己，于是乎我们可以通过pip生成一个requirements.txt的文件，在新环境中通过读取这个文件中的模块名称进行安装环境

1）文件生成与使用

1.生成requirements.txt 
  • cmd切换至项目根目录(这个文件通常在最外层)执行pip freeze > requirements.txt
    注意：使用pip freeze会把整个python环境的依赖都生成出来，如需只生成项目用到的模块可用pipreqs模块
  • 例如：
        生成requirements.txt
这时候项目根目录就会多一个requirements.txt文件,里面会记录我们项目需要的所以模块信息(里面是什么内容我们不用管，如果你有这个心情可以去研究一下),将项目拷贝到新环境中的时候连这个文件一起带上
2.新环境中通过此文件可以直接安装模块（注:需要先切换到 requirements.txt的上级目录，也就是项目根目录）
  • 在项目根目录下执行pip install -i https://pypi.doubanio.com/simple/ -r requirements.txt(国内镜像安装)
2）安装至虚拟环境中命令，使用国内镜像安装命令
pip install -i https://pypi.doubanio.com/simple -r E:\apitest\pythonproject\requirements.txt
-i 参数表示更换镜像源 有时候当你下载一些库的时候，下载特别慢、有时候甚至报错了 这是因为 默认使用的是国外的镜像源, So 当我们改成国内镜像源时，速度就起飞了~
-r 遍历并安装requestment.txt中的包
3）******如果想只生成项目所需的依赖时，可以考虑使用pipreqs模块
pipreqs，这个工具的好处是可以通过对项目目录扫描，将项目使用的模块进行统计，生成依赖清单即requirements.txt文件。
安装pipreqs
pip install pipreqs

在项目的根目录下 使用（或者在pycharm的terminal命令窗口执行）   pipreqs ./
pipreqs ./ --encoding=utf8
如项目下已存在该文件，会报个错误提示，可以使用--force参数来覆盖它
requirements.txt already exists, use --force to overwrite it
pipreqs ./ --encoding=utf8 --force
亦或者，只生成不带版本号的库名
pipreqs ./ --encoding=utf8 --no-pin
--no-pin 表示参数用于生成不带版本号的requirements.txt文件
根据依赖清单安装模块
pip install -r requirements.txt
