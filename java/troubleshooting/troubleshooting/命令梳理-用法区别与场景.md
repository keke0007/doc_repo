# 命令梳理：用法、区别与应用场景

本文基于 [ppt-merged.md](/c:/Users/ke/Desktop/learn_document/web/ppt/ppt-merged.md:1) 中涉及的命令整理，目标不是罗列所有参数，而是帮助快速判断：

- 这条命令是干什么的
- 它和相近命令有什么区别
- 遇到什么问题时优先用它

## 1. 先建立选型思路

可以先把这些命令分成 6 组：

- 文本与日志：`cat`、`head`、`tail`、`less`、`grep`、`awk`、`sort`、`uniq`、`wc`
- 资源观测：`top`、`vmstat`、`free`、`slabtop`、`df`、`iostat`、`iotop`、`nicstat`、`iftop`、`sar`、`dstat`
- 进程与连接：`pidstat`、`ps`、`netstat`、`ss`、`lsof`、`fuser`
- 内核/原生追踪：`ftrace`、`trace-cmd`、`perf`、`bcc`、`bpftrace`、`strace`、`peekfd`、`gdb`
- JVM / Java 诊断：`jps`、`jstack`、`jstat`、`jmap`、`jinfo`、`jcmd`、`arthas`
- 网络排障与抓包：`dig`、`ping`、`mtr`、`hping3`、`curl`、`tcpdump`、`wireshark`、`ngrep`、`tshark`

一个简单原则：

- 不知道发生了什么：先用资源观测命令
- 知道是哪个进程但不知道它在干什么：用进程与连接命令
- 知道卡在系统调用、内核、网络栈：用原生追踪
- 知道问题在 Java 进程内部：先 `jcmd` / `arthas`
- 知道是网络问题：先分层检查，最后抓包

## 2. 文本与日志命令

### 2.1 `cat` / `head` / `tail`

`cat`

- 用法：直接输出文件全部内容，常用于小文件或管道输入
- 适合：看配置文件、拼接文本、给 `grep` / `awk` 提供输入
- 不适合：大日志，容易刷屏

`head`

- 用法：看文件前几行
- 适合：快速确认文件格式、表头、启动日志开头

`tail`

- 用法：看文件后几行；`tail -f` 持续追踪新日志
- 适合：实时看应用日志、错误日志

区别：

- `cat` 是“全量输出”
- `head` / `tail` 是“局部查看”
- 看运行中的日志，几乎总是优先 `tail -f`

常见例子：

```bash
head -n 20 app.log
tail -n 100 app.log
tail -f app.log
```

### 2.2 `vim` vs `less` / `more`

`vim`

- 用法：编辑器
- 适合：改配置、小文件临时编辑
- 不适合：查看超大日志，通常会把文件整体加载进内存

`less`

- 用法：分页查看器，按需加载
- 适合：大日志、jar 包、压缩文件、带搜索的阅读
- 常用交互：
  - `f` / `b`：翻页
  - `g` / `G`：首行 / 末行
  - `/xxx`：向后搜索
  - `?xxx`：向前搜索
  - `Shift+F`：类似 `tail -f`

`more`

- 用法：更老的分页查看器
- 适合：基础分页
- 不如 `less`：功能弱，交互差

结论：

- 编辑文件：`vim`
- 看大日志：`less`
- 除非环境里没有 `less`，一般不优先 `more`

常见例子：

```bash
less app.log
less -N app.log
less -i app.log
less xxx.jar
```

### 2.3 `grep`

用途：

- 按关键字筛选行
- 实时过滤 `tail -f` 输出
- 输出匹配行前后上下文

常用能力：

- `-i`：忽略大小写
- `-v`：排除匹配行
- `-A/-B/-C`：输出上下文
- `--line-buffered`：配合实时流更稳

适合场景：

- 搜错误关键字
- 追实时错误日志
- 取异常栈上下文

典型例子：

```bash
grep -i error app.log
tail -f app.log | grep --line-buffered -i error
tail -f app.log | grep --line-buffered -i error | grep -v -e reset
tail -f app.log | grep -A 9 -i error
tac app.log | grep -m 10 -i error
```

和 `awk` 的区别：

- `grep` 更适合“按行找关键字”
- `awk` 更适合“按列取值、统计、编程式处理”

### 2.4 `awk`

用途：

- 按列处理文本
- 做过滤、聚合、计数、时间范围筛选
- 处理多行异常栈、段落日志

特点：

- 比 `grep` 强
- 比 `sort` / `uniq` 灵活
- 更像一个轻量脚本语言

适合场景：

- 从日志中抽字段
- 按端口、IP、SQL 类型做统计
- 搜索异常栈段落
- 过滤某个时间区间的数据

典型例子：

```bash
awk 'BEGIN{...} /pattern/{...} END{...}' app.log
cat app.log | awk -v RS= '/Broken pipe/'
```

和 `grep` 的区别：

- `grep`：找到“哪些行匹配”
- `awk`：找到后还能继续拆列、算数、条件判断、聚合

### 2.5 `wc` / `sort` / `uniq`

`wc`

- 用法：统计行数、词数、字节数
- 最常用：`wc -l`
- 场景：日志量统计、请求数粗略计数

`sort`

- 用法：对行排序
- 常用：
  - `-k`：按字段排序
  - `-n`：按数字排序
  - `-r`：倒序
- 场景：把统计结果按次数倒序排

`uniq`

- 用法：去重或计数
- 常用：`uniq -c`
- 注意：通常需要先排序，否则无法正确聚合

组合关系：

- `sort` 负责“排好”
- `uniq -c` 负责“合并并计数”
- `wc -l` 负责“数一数”

典型例子：

```bash
sort -nrk2 stat.txt
sort app.log | uniq -c
cat app.log | wc -l
```

### 2.6 `zcat` / `zless` / `zgrep`

用途：

- 直接查看 `.gz` 压缩日志

场景：

- 日志滚动后被 gzip 压缩
- 不想先解压再查

结论：

- 查压缩日志优先这一组
- 如果要做复杂分析，没有对应 `zawk` 时再先解压

## 3. 资源观测命令

### 3.1 `top` vs `vmstat` vs `free`

`top`

- 看整体 CPU、内存、负载、进程排行
- 支持交互排序、线程查看、过滤
- 最适合“先全局扫一眼”

常用交互：

- `P`：按 CPU 排序
- `M`：按内存排序
- `H`：看线程
- `c`：看完整命令行

`vmstat`

- 看系统运行队列、阻塞线程、上下文切换、中断、swap、IO
- 最适合“判断 CPU 忙还是 IO 堵、是否在频繁换页”

`free`

- 专注内存
- 最适合快速确认“可用内存到底还剩多少”

区别：

- `top`：交互式总览
- `vmstat`：系统行为与调度视角
- `free`：内存视角

经验：

- `free` 小不一定有问题，关键看 `available`
- `vmstat` 第一行通常是历史平均值，重点看后续实时行

### 3.2 `slabtop`

用途：

- 看 slab，也就是内核对象缓存

适合场景：

- `buff/cache` 很大
- 想知道是不是文件缓存以外，还有大量内核对象占用内存

和 `free` 的区别：

- `free` 只告诉你缓存大
- `slabtop` 告诉你缓存里到底是什么对象在占

### 3.3 `df` / `iostat` / `iotop`

`df`

- 看文件系统空间占用
- 适合：磁盘满没满、哪个挂载点爆了

`iostat`

- 看磁盘设备整体 IOPS、延迟、队列、利用率
- 适合：判断磁盘是否饱和

关注指标：

- `%util`
- `avgqu-sz`
- `r_await` / `w_await`
- `r/s` / `w/s`

`iotop`

- 看进程 / 线程维度磁盘 IO
- 适合：已经知道“磁盘忙”，继续找“谁在忙”

区别：

- `df`：空间
- `iostat`：设备整体性能
- `iotop`：进程级责任归属

### 3.4 `nicstat` / `iftop`

`nicstat`

- 看网卡维度带宽使用率
- 适合：判断某块网卡是否打满

`iftop`

- 看连接维度当前网速
- 适合：判断是哪些连接在占带宽

区别：

- `nicstat`：网卡总体
- `iftop`：连接明细

### 3.5 `sar` vs `dstat`

`sar`

- 全能型系统观测命令
- CPU、负载、中断、上下文切换、内存、swap、磁盘、网络、socket 都能看

常见例子：

```bash
sar -u ALL 1
sar -q 1
sar -r ALL 1
sar -dp 1
sar -n DEV 1
sar -n TCP,ETCP 1
```

`dstat`

- 也是全能型，但展示更直接
- 适合临时综合观察

区别：

- `sar` 更系统化，适合背熟后长期用
- `dstat` 更轻快，适合临时看

## 4. 进程、线程与连接命令

### 4.1 `pidstat`

用途：

- 看进程 / 线程级别的 CPU、内存、磁盘 IO、上下文切换、线程数、FD 数

常用选项：

- `-u`：CPU
- `-t`：线程维度
- `-r`：内存
- `-d`：磁盘 IO
- `-w`：上下文切换
- `-v`：线程数 / 文件描述符
- `-p <pid>`：指定进程
- `-G <name>`：按进程名过滤

适合场景：

- `top` 已经看到进程异常，但还想看更细颗粒度
- 想找“哪个线程 CPU 高”
- 想看进程是不是在频繁切换、FD 是否泄露

和 `top` 的区别：

- `top` 更偏总览
- `pidstat` 更偏单进程精查

### 4.2 `ps`

用途：

- 查看进程 / 线程信息
- 定制输出字段、排序字段

适合场景：

- 想看线程状态、线程数、命令行、`wchan`
- 想做脚本化筛选和排序

和 `top` 的区别：

- `top` 动态
- `ps` 静态、可脚本化

### 4.3 `netstat` vs `ss`

`netstat`

- 查看网络连接、TCP 状态、协议统计
- 适合：统计连接状态、看 `TIME_WAIT` / `CLOSE_WAIT`

`ss`

- 用途和 `netstat` 相近
- 性能更高，基于 netlink
- 还能通过 `-i` 看更多连接细节，比如 `lastsnd` / `lastrcv`

结论：

- 老经验或脚本兼容：`netstat`
- 新环境、性能更好、细节更多：`ss`

典型场景：

- `TIME_WAIT` 多：考虑连接池或内核参数
- `CLOSE_WAIT` 多：优先查应用连接没关

### 4.4 `lsof` / `fuser` / `pwdx`

`lsof`

- 查看进程打开的文件 / socket
- 也能反查“这个端口 / 文件是谁占着”

适合场景：

- 根据端口找进程
- 根据文件找进程
- 删除日志后磁盘不释放，查谁还持有已删除文件

`fuser`

- 可以看作 `lsof` 的简版
- 适合快速根据文件或端口找进程

`pwdx`

- 查看进程工作目录
- 适合排查部署结构不熟时，顺着进程找目录

区别：

- `lsof` 功能最全
- `fuser` 更轻量
- `pwdx` 只做工作目录

## 5. 原生与内核追踪命令

### 5.1 `strace`

用途：

- 追踪系统调用
- 看程序到底在做哪些文件 / 网络 / 进程 / 内存操作

常见能力：

- 过滤文件相关系统调用
- 过滤网络相关系统调用
- `-yy` 解码 FD
- `-k` 打印调用栈
- `-c` 统计系统调用热点

适合场景：

- 命令卡住但不知道卡在哪
- 怀疑 DNS / 文件 / 网络系统调用慢
- 想研究某条命令底层实现

例子：

- 看 `free` 命令从哪里取数据，可发现它读的是 `/proc/meminfo`
- 追 SQL 调用端耗时，可对 `sendto` / `recvfrom` 之间时间差做分析

注意：

- 基于 `ptrace`
- 开销不小，高流量系统慎用

### 5.2 `peekfd`

用途：

- 读取进程某个文件描述符上的读写内容

适合场景：

- 想直接看 socket 或文件 FD 上流动的数据

和 `strace` 的区别：

- `strace` 更通用
- `peekfd` 在“看 FD 内容”这件事上可读性更好

### 5.3 `gdb`

用途：

- 原生断点调试器
- 能打断点、看寄存器、执行脚本、拿原生栈、做原生堆转储

适合场景：

- C/C++ / native 问题
- JVM native 层、大对象分配、段错误、原生内存问题

优点：

- 能做到非常深的原生层调试

代价：

- 仍然基于 `ptrace`
- 对性能有影响
- 使用门槛高

### 5.4 `ftrace` / `trace-cmd`

`ftrace`

- Linux 内核原生追踪机制
- 适合：看内核函数、调度、事件

`trace-cmd`

- 对 `ftrace` 的封装
- 更适合实际操作与结果管理

结论：

- 想直接玩底层追踪：`ftrace`
- 想更好用：`trace-cmd`

### 5.5 `perf` / `perf-tools`

`perf`

- Linux 标准性能剖析工具
- 可列事件、做统计、采样、火焰图

适合场景：

- CPU 热点
- 内核 / 用户态热点
- 性能瓶颈总览

`perf-tools`

- 对一些常见场景做了封装

区别：

- `perf` 是基础能力
- `perf-tools` 是便捷工具集

### 5.6 `bcc` vs `bpftrace`

`bcc`

- 基于 eBPF 的工具集
- 常用于 `offcputime`、`stackcount` 等
- 更偏“预制工具 + 工具脚本”

`bpftrace`

- eBPF 的高级脚本语言
- 更适合快速写追踪脚本

区别：

- `bcc`：像工具箱，成品多
- `bpftrace`：像脚本语言，定制强

适合场景：

- `offcputime`：看 off-CPU 调用栈
- `stackcount`：统计某内核点的调用栈分布
- 慢 SQL、丢包、调度、内核函数热点等

## 6. JVM 基础诊断命令

### 6.1 `jps`

- 用途：查 Java 进程 ID
- 场景：后续一切 JDK 命令的起点

### 6.2 `jstack`

- 用途：获取 Java 线程栈
- 场景：CPU 高、线程卡住、锁等待、死锁、耗时高排查

和 `arthas thread/stack` 的区别：

- `jstack`：JDK 原生命令，静态快照
- `arthas`：更动态、更适合在线交互分析

### 6.3 `jstat`

- 用途：看 GC、类加载、JIT
- 场景：怀疑频繁 GC、类加载异常、编译行为异常

### 6.4 `jmap`

- 用途：看堆、看对象分布、转储 heap dump
- 场景：堆内存高、对象泄露、OOM 后分析

注意：

- dump 可能导致较长暂停
- 生产环境建议谨慎操作，必要时先摘流

### 6.5 `jinfo`

- 用途：看 / 改 JVM 参数，查看系统属性

### 6.6 `jcmd`

- 用途：统一入口，逐步替代 `jps` / `jstack` / `jmap` / `jinfo` / `jstat`
- 优点：扩展性强，新能力通常先进 `jcmd`

典型替代关系：

- `jcmd 0 Thread.print` 对应 `jstack`
- `jcmd 0 GC.heap_dump` 对应 `jmap -dump`
- `jcmd 0 PerfCounter.print` 对应 `jstat`

结论：

- 新系统优先把 `jcmd` 当主入口
- 老命令仍然值得会，因为资料更多、记忆成本低

## 7. Arthas 命令梳理

### 7.1 概览类

`help`

- 看命令帮助

`dashboard`

- 类似 JVM 版 `top`
- 适合先全局扫线程、内存、JVM 状态

`thread`

- 看线程信息
- 适合线程异常、热点线程分析

`memory`

- 看内存概览

### 7.2 类与代码确认类

`sc`

- 查类是否存在、从哪里加载
- 很适合查 jar 冲突

`sm`

- 查看类的方法

`jad`

- 反编译类
- 适合确认线上代码是否最新

区别：

- `sc`：找类
- `sm`：找方法
- `jad`：看代码

### 7.3 方法调用观测类

`monitor`

- 看方法 QPS、RT、异常数等整体指标
- 适合做“宏观观察”

`watch`

- 看参数、返回值、异常
- 适合确认实际 SQL、入参、出参
- 可用 `#cost` 做耗时过滤

`trace`

- 看方法耗时拆解到下一层子方法
- 适合找“哪一层慢”

`stack`

- 看调用栈入口
- 适合找“谁调用了它”

区别：

- `monitor`：整体统计
- `watch`：看值
- `trace`：看耗时拆分
- `stack`：看调用路径

### 7.4 `profiler`

用途：

- 封装 `async-profiler`
- 做 on-CPU / off-CPU / 火焰图 / JFR 采集

模式理解：

- on-CPU：CPU 真正在执行什么
- off-CPU / wall：线程虽然没占 CPU，但为何整体耗时长
- JFR：适合 case by case 分析偶现慢请求

适合场景：

- CPU 热点
- 整体耗时高
- P99 偶发慢请求
- native 方法 / 堆外内存分析

### 7.5 对象与配置类

`vmtool`

- 查对象、触发 GC、看连接池 / 线程池对象

`mbean`

- 看暴露为 JMX MBean 的组件状态

`logger`

- 查看或调整日志级别

`getstatic`

- 读取静态变量

`ognl`

- 执行表达式、调用方法、修改变量
- 功能很强，也要谨慎

`jvm`

- 看类加载、GC、内存、线程、FD

`sysenv` / `vmoption` / `sysprop`

- 看环境变量、JVM 选项、系统属性

`perfcounter`

- 看 JVM 运行中的性能计数器

## 8. 网络排障命令

### 8.1 连通性分层检查

`dig`

- 看 DNS 解析结果与耗时
- 适合：怀疑 DNS 慢或解析错

`ping`

- 看 IP 层连通性与 RTT
- 适合：判断主机是否 reachable、网络抖动

`mtr`

- 看路由路径和每跳质量
- 适合：网络慢，需要给网络团队证据

`hping3`

- 看 TCP 端口连通性
- 适合：判断端口是否能握手
- 注意：它反映的是 TCP 层，不能代表业务处理快慢

`curl`

- 看 HTTP 接口连通性
- 也能拆 DNS、连接、首包、总耗时

关键耗时：

- `time_namelookup`
- `time_connect`
- `time_starttransfer`
- `time_total`

结论：

- DNS：`dig`
- IP：`ping`
- 路由：`mtr`
- TCP 端口：`hping3`
- HTTP / 整链路：`curl`

### 8.2 连接与丢包

`netstat`

- 统计 socket 状态、看协议重传和丢包

`ifconfig`

- 看网卡层丢包

`ethtool -S`

- 看网卡详细统计

`nstat -a`

- 看 IP/TCP 层详细统计

`dropwatch`

- 跟踪丢包

`bcc stackcount`

- 追 `kfree_skb` 等内核丢包路径

### 8.3 抓包与分析

`tcpdump`

- 线上抓包主力
- 适合：在目标机器抓，下载到本地分析

`wireshark`

- 图形化分析抓包
- 适合：协议解析、过滤、排序、时延分析、案例分析

`ngrep`

- 文本化抓包
- 适合：HTTP / MySQL 这种带明文或可读字符串的场景
- 比如确认应用真正发出的 SQL

`tshark`

- `wireshark` 的命令行版
- 适合：实时分析、脚本化处理

区别：

- `tcpdump`：负责抓
- `wireshark`：负责深度看
- `ngrep`：负责快速看文本内容
- `tshark`：负责命令行实时分析

## 9. 常见组合打法

### 9.1 看日志

```bash
less app.log
tail -f app.log | grep --line-buffered -i error
tac app.log | grep -m 20 -i exception
```

### 9.2 统计热点错误

```bash
grep -i error app.log | awk '{print $NF}' | sort | uniq -c | sort -nr
```

### 9.3 看系统资源方向

```bash
top
vmstat 1
free -m
iostat 1
```

### 9.4 找异常进程 / 线程

```bash
top -H -p <pid>
pidstat -t -p <pid> 1
ps -Lp <pid> -o pid,tid,pcpu,stat,wchan:32,comm
```

### 9.5 查连接与文件占用

```bash
ss -antpi
lsof -p <pid>
lsof -i :3306
fuser -n tcp 3306
```

### 9.6 Java 进程排查

```bash
jcmd <pid> Thread.print
jcmd <pid> GC.heap_info
jcmd <pid> GC.class_histogram
arthas dashboard
arthas thread
arthas trace xxx
```

### 9.7 网络慢排查

```bash
dig example.com
ping <ip>
mtr <host>
curl -w 'dns=%{time_namelookup} connect=%{time_connect} start=%{time_starttransfer} total=%{time_total}\n' -o /dev/null -s http://host/path
tcpdump -i any -w out.pcap host <ip>
```

## 10. 最容易混淆的命令对

### `less` vs `vim`

- 看大日志用 `less`
- 改小文件用 `vim`

### `grep` vs `awk`

- 简单搜索用 `grep`
- 拆列、统计、编程式处理用 `awk`

### `top` vs `pidstat`

- 系统总览用 `top`
- 单进程细查用 `pidstat`

### `iostat` vs `iotop`

- 设备整体用 `iostat`
- 进程归因用 `iotop`

### `netstat` vs `ss`

- 两者都能看连接
- 新环境更推荐 `ss`

### `jstack` vs `arthas trace`

- `jstack` 看线程栈快照
- `arthas trace` 看方法耗时拆分

### `perf` vs `bcc` / `bpftrace`

- `perf` 是通用基础剖析
- `bcc` / `bpftrace` 更适合内核与事件追踪、定制脚本

## 11. 一页结论

- 看日志：`less` 起手，`grep` / `awk` 深挖
- 看资源：`top` + `vmstat` + `free` + `iostat`
- 找责任进程：`pidstat` / `ps` / `ss` / `lsof`
- 看系统调用：`strace`
- 看内核热点：`perf` / `bcc` / `bpftrace`
- 看 Java 内部：优先 `jcmd` + `arthas`
- 看网络：先 `dig/ping/mtr/curl` 分层，再 `tcpdump + wireshark`
