# 机器学习应用学习路线(14 周 · 业务落地向)

> 适用画像:已有编程基础、数学基础一般、目标是**用 AI 解决实际业务问题**、每周可投入 20 小时以上。
> 总时长约 3.5 个月,共 4 个阶段 + 3 个贯穿项目。

---

## 一、五条核心原则

先把方法论定下来,比选课程重要得多。

**1. 项目驱动,而不是课程驱动。** 每个阶段结束都要有一个能跑、能给别人演示的东西。看完课但没写过完整项目,等于没学。

**2. 数学按需补,不要提前补。** 你的目标是应用,不需要先花两个月啃线性代数。遇到不懂的概念(梯度下降、正则化、协方差)再去补对应那一小块,补的是**直觉**而不是证明。

**3. 结构化数据优先,深度学习靠后。** 真实业务里 70% 以上的问题是表格数据的预测/分类/排序,GBDT 类模型(XGBoost / LightGBM)才是主力。先把这块吃透,收益最高。

**4. 先有基线,再谈优化。** 任何问题先用规则或逻辑回归做一个基线,再上复杂模型。没有基线就没法判断复杂模型是否值得。

**5. 数据处理能力 > 调模型能力。** 业务场景里模型效果的差距,绝大多数来自特征工程、数据泄漏、标签定义,而不是模型选型。

## 二、每周 20 小时怎么分配

| 内容 | 时长 | 说明 |
|---|---|---|
| 课程 / 阅读 | 6h | 只看一门主线课程,不要平行开多门 |
| 动手编码 | 10h | 项目 + 复现,这是主要产出时间 |
| 复盘与笔记 | 2h | 用自己的话写清楚学到的概念 |
| 补概念 / 查资料 | 2h | 补数学直觉、查文档、读源码 |

笔记建议:每个模型只记三件事——**它假设了什么、什么场景适合用、失败时长什么样**。不要抄公式。

## 阶段 0 · 第 1 周:先跑通一个完整闭环

目的不是学会,而是**建立全局感**。一周内让数据从 CSV 走到评估指标,后面所有内容都是在给这条链路的某一环加深度。

要掌握的:

- 环境:Python 3.11+、`uv` 或 conda 管理环境、Jupyter Notebook / VS Code
- 数据栈:`numpy` 基本运算、`pandas` 读写与筛选、`matplotlib` 画基本图
- `scikit-learn` 的标准套路:`train_test_split` → `fit` → `predict` → 指标
- 三个必须搞清的概念:训练集/验证集/测试集为什么要分、什么叫过拟合、准确率为什么经常是个坏指标

本周产出:用 Kaggle 的泰坦尼克或加州房价数据集,写一个从加载数据到输出评估结果的完整 notebook,并用文字写下"我这个模型好不好、为什么"。

主线资源:吴恩达 Machine Learning Specialization(Coursera,中文字幕)第 1 门课的前两周,只看不做完整作业,目的是建立词汇量。

---

## 阶段 1 · 第 2-4 周:数据能力 + 经典监督学习

这是**投入产出比最高的三周**,业务落地的主力技能都在这里。不要着急跳到深度学习。

### 数据处理(第 2 周)

- `pandas` 进阶:`groupby`、`merge`、时间序列处理、透视
- 缺失值策略:删除 / 均值 / 模型填充,各自什么时候用
- 类别特征编码:one-hot、target encoding、以及它们何时会引发泄漏
- **数据泄漏(data leakage)**:这是新手最致命的坑,务必专门花时间理解。典型形式是用了预测时刻拿不到的信息、或在划分数据前就做了标准化
- 特征工程:比值、差分、时间窗口聚合、类别频次

### 模型(第 3 周)

按这个顺序学,每个都亲手跑一遍并对比效果:

1. 线性回归 / 逻辑回归 —— 理解系数含义,它是你永远的基线
2. 决策树 —— 理解分裂逻辑和为什么容易过拟合
3. 随机森林 —— 理解 bagging 的直觉
4. **梯度提升树(XGBoost / LightGBM)** —— 表格数据的默认答案,重点投入
5. 聚类(KMeans)与降维(PCA)—— 做用户分群和探索性分析时用

### 评估与调优(第 4 周)

- 交叉验证:K-fold、分层抽样、时间序列的正确切分方式
- 分类指标:混淆矩阵、精确率/召回率的取舍、ROC-AUC vs PR-AUC(样本不平衡时后者更可靠)
- **阈值选择**:业务上真正决定成本收益的往往是阈值,而不是模型
- 类别不平衡处理:重采样、类别权重
- 超参搜索:网格 / 随机 / Optuna
- 可解释性:特征重要性、SHAP —— 业务方一定会问"为什么这么判",这是必修不是选修

主线资源:《Hands-On Machine Learning with Scikit-Learn, Keras & TensorFlow》(Géron)前半部分,是应用向最好的一本;概念不懂时配 StatQuest 视频看直觉。

---

## 阶段 2 · 第 5-8 周:深度学习与 PyTorch

到这里再学深度学习,你会发现它只是换了个建模工具,而评估、泄漏、基线那套方法论完全通用。

### PyTorch 基础(第 5 周)

- 张量运算与广播、`autograd` 自动求导的直觉
- `Dataset` / `DataLoader` 的写法
- 手写完整训练循环:前向 → 损失 → 反向 → 更新
- 优化器与学习率:Adam 是默认选择,学习率是最重要的超参
- 常见故障排查:loss 不降、loss 变 NaN、train 好 val 差

### 网络与迁移学习(第 6-7 周)

- 全连接网络、激活函数、Dropout、BatchNorm 各自解决什么问题
- CNN 的直觉(卷积在干什么)+ 用 `torchvision` / `timm` **微调**预训练模型
- Transformer 与注意力机制的概念性理解:不推公式,但要能说清"每个词看其他词"这件事
- 用 Hugging Face `transformers` 做文本分类,以及用 embedding 做相似度检索

**关键心态:业务场景里几乎永远是微调预训练模型,而不是从零训练。** 把精力放在数据和微调流程上。

### 选一个方向深入(第 8 周)

挑离你实际业务最近的一个,其他的只保留概念:

- 表格/时序预测 —— 大多数业务问题,深入 LightGBM + 时序特征 + Prophet/NeuralForecast
- NLP —— 分类、抽取、语义检索
- CV —— 分类、检测(YOLO 系列)、OCR
- 推荐/排序 —— 召回与排序两阶段架构

主线资源:《动手学深度学习》(李沐,PyTorch 版,中文免费在线)是最匹配你情况的教材;偏实践可以配 fast.ai 的 Practical Deep Learning。

---

## 阶段 3 · 第 9-12 周:LLM 应用

如今"用 AI 解决业务问题"很大一部分落到这一层,而且见效最快。但**前两个阶段的基本功决定了你能不能评估效果**,别跳过。

### 基础用法(第 9 周)

- Prompt 工程:结构化指令、few-shot、思维链在什么场景真有用
- 结构化输出:JSON schema / function calling,这是工程集成的关键
- 上下文窗口、token 计费、延迟与成本的权衡
- 主流 API 的调用与错误处理、流式输出

### RAG 检索增强(第 10-11 周)

这是企业落地最常见的形态,值得重点投入两周:

- 文档切分策略(按语义 vs 固定长度)、embedding 模型选择
- 向量库:先用 Chroma 或 pgvector 理解原理,不要一上来就上重型方案
- **混合检索 + 重排(rerank)**:纯向量检索效果通常不够,这一步提升最明显
- **RAG 评估**:检索命中率、答案忠实度、幻觉率——没有评估的 RAG 等于没做完
- 框架:LangChain / LlamaIndex 了解即可,先手写一遍最小 RAG 再用框架

### Agent 与微调决策(第 12 周)

- 工具调用循环、多步任务拆解、失败重试,以及 Agent 的可靠性边界
- **决策树:能用 prompt 解决就别做 RAG,能用 RAG 解决就别微调。** 微调解决的是风格与格式稳定性,补充知识请用 RAG
- LoRA / QLoRA 概念与轻量实践,知道成本量级即可

---

## 阶段 4 · 第 13-14 周:工程化与上线

会训练模型但不会上线,在业务场景里价值折半。这两周补齐从 notebook 到线上服务的链路。

- 服务化:用 FastAPI 把模型包成接口,注意输入校验和超时处理
- 容器化:Docker 打包与依赖固定(锁版本,别用浮动版本)
- 实验与版本管理:MLflow 记录参数、指标、模型版本
- 特征一致性:训练用的特征逻辑必须和线上推理完全一致,这是线上效果暴跌的头号原因
- 监控:数据漂移、预测分布漂移、指标衰减,以及什么时候该重训
- **离线指标 ≠ 线上收益**:线上要看业务指标,要会做 A/B 实验的基本设计
- 安全提醒:任何对外暴露的模型接口都要加鉴权和限流,不要裸奔

## 四、三个贯穿项目(比课程更重要)

每个项目都要写一份简短的说明文档:问题定义、数据来源、基线、最终效果、失败尝试。这份文档同时也是你之后跟业务方或面试沟通的材料。

**项目一(第 4 周完成)· 结构化数据预测**
客户流失预测或信贷风险评分。要求:含完整特征工程、有规则基线对比、用 SHAP 解释 Top 特征、明确说明选了什么阈值以及背后的成本考量。

**项目二(第 8 周完成)· 微调一个预训练模型**
文本分类(如工单自动分类)或图像分类。要求:数据集自己整理、记录训练曲线、对比零样本 LLM 与微调小模型的效果和成本。

**项目三(第 12-14 周完成)· RAG 知识助手并部署**
拿一批真实文档(产品手册、内部制度、论文)做问答助手。要求:有评估集和量化指标、做了 rerank 前后对比、用 FastAPI + Docker 跑起来、记录单次问答的 token 成本与延迟。

## 五、容易被跳过、但真正决定成败的能力

技术之外,这部分是"用 AI 解决业务问题"和"会调模型"的分界线,建议每个阶段都刻意练习。

**问题翻译能力。** 把"我们想减少客户流失"翻译成"预测未来 30 天流失概率,标签定义为连续 30 天无活跃,成功标准是召回率 60% 时精确率不低于 30%"。做不到这一步,后面全是白做。

**判断该不该用 ML。** 规则能解决的、数据量不足的、标签拿不到的、错误代价极高的场景,往往不该用 ML。能说"这个不建议上模型"是很值钱的能力。

**数据与标签质量意识。** 标签定义模糊、正负样本口径不一致,比模型选错严重得多。

**沟通与预期管理。** 给业务方讲清楚模型会犯错、错误率大概多少、错了怎么兜底。

## 六、数学补课清单(按需查,不要提前系统学)

| 遇到什么 | 补什么 | 到什么程度 |
|---|---|---|
| 梯度下降、反向传播 | 导数与链式法则 | 知道"沿斜率下坡"的直觉 |
| 模型权重、embedding、注意力 | 向量、矩阵乘法、点积与相似度 | 能手算小矩阵乘法 |
| AUC、置信度、朴素贝叶斯 | 条件概率、贝叶斯公式、常见分布 | 能算简单条件概率 |
| 正则化、损失函数 | 范数、凸性的直觉 | 知道 L1 稀疏、L2 平滑 |
| A/B 测试、指标显著性 | 假设检验、置信区间 | 能判断差异是否可信 |

直觉类资源:3Blue1Brown 的线性代数与微积分系列、StatQuest 的统计与机器学习系列。真要系统补时再看 MIT 18.06。

## 八、七个常见坑

1. 先花两个月补数学再开始 —— 大概率半途而废
2. 收藏了几十份教程但没写完一个项目
3. 一上来就微调大模型,没有数据基本功
4. 只看准确率,在不平衡数据上自我感觉良好
5. 无意中造成数据泄漏,离线 0.95 上线暴跌
6. 没做基线,分不清是模型有效还是问题本来就简单
7. 模型停在 notebook 里,从未上线
