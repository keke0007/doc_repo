## 1. 核心概念

| 概念 | 说明 |
| --- | --- |
| 爬虫 | 模拟浏览器发送 HTTP(S) 请求、按规则自动抓取数据的程序 |
| 通用爬虫 | 搜索引擎类(百度、Google),抓取面广 |
| 聚焦爬虫 | 针对特定网站抓取特定字段(本课程主线) |
| 数据来源思路 | ① HTML 直出 ② 接口(XHR/Fetch)返回 JSON ③ 异步动态加载 |

**核心方法论**:数据获取思路 > 代码本身。优先用浏览器 DevTools(Network 面板)抓包定位真实数据接口。

## 2. 聚焦爬虫执行流程

```
+----------+      +------------+      +----------+      +----------+
| 起始 URL | ───▶ | 发请求/收响应 | ───▶ | 数据提取 | ───▶ | 保存数据 |
+----------+      +------------+      +----┬-----+      +----------+
                                          │
                                  发现新 URL  │ 是
                                          ▼
                                  回到"发请求/收响应"
```

## 3. HTTP / HTTPS

- HTTP:超文本传输协议,默认端口 **80**
- HTTPS:HTTP + **TLS/SSL**,默认端口 **443**(原文写"SSL"不严谨,实际现代协议是 TLS,SSL 早已废弃)

### 常用请求头(爬虫必关注)

`Host`、`Connection`、`User-Agent`、`Accept`、`Referer`、`Accept-Encoding`、`Cookie`、`X-Requested-With: XMLHttpRequest`(标记 Ajax)。

### 响应状态码

```
2xx  成功      200 OK
3xx  重定向    301 永久 / 302 临时(方法常被改成 GET) / 307 临时(保持原方法)
4xx  客户端错  403 禁止 / 404 不存在 / 429 请求过频
5xx  服务端错  500 内部错误 / 502 网关错 / 503 不可用(常见反爬)
```

### 浏览器一次请求过程

```
浏览器 ──域名──▶ DNS 服务器
浏览器 ◀──IP─── DNS 服务器
浏览器 ──HTTP──▶ Web 服务器(IP)
浏览器 ◀──HTML/JSON── Web 服务器
```

## 4. robots 协议

仅道德约定,**非强制**。Scrapy 默认会读取并遵守,做学习/采集时一般在 `settings.py` 里设 `ROBOTSTXT_OBEY = False`。

## 5. 编码(Python 3)

| 类型 | 含义 |
| --- | --- |
| `str` | Unicode 字符序列(代码点) |
| `bytes` | 字节序列,网络/磁盘传输的原始数据 |

```python
'abc'.encode('utf-8')   # str  → bytes
b'abc'.decode('utf-8')  # bytes → str
```

**规则**:`encode` 用什么字符集,`decode` 就必须用同一个,否则乱码或 `UnicodeDecodeError`。

## 6. 原文需要纠正/补充的点

| # | 原文说法 | 问题 | 正确/建议 |
|---|---------|------|-----------|
| 1 | "HTTPS = HTTP + SSL(安全套接字层)" | SSL 协议自 2015 年起被 RFC 7568 弃用,现代 HTTPS 实际使用 TLS(1.2/1.3) | 准确说法:**HTTPS = HTTP over TLS**(TLS 是 SSL 的后继者) |
| 2 | 状态码 302 描述"一般会用 GET" | 302 在 RFC 中并未要求改方法,但大多数浏览器**事实上**会把 POST 改成 GET;严格"POST→POST"的是 **307**,"必须保持原方法的永久重定向"是 **308** | 建议补充:301/302 行为不确定,严格需求用 307/308 |
| 3 | "只要能发 HTTP(S) 请求的语言都能写爬虫,Python 效率最高" | 表述偏主观 | Python 高效是因为生态(requests/scrapy/lxml/playwright)成熟,语言本身并无独门优势 |
| 4 | "503 一般是被反爬" | 不全面 | 503 = Service Unavailable,可能是服务过载、维护、或被 CDN/WAF 拦截;反爬更常见状态码是 **403、412、429、418** |
| 5 | `Upgrade-Insecure-Requests` 释义"升级为 HTTPS 请求" | 不严谨 | 它是浏览器告诉服务器"我支持把站内 http 资源升级到 https 加载",并非主动把当前请求升级 |

---

## 7. 速记

- 抓不到数据先抓包,别先写代码。
- 动态页面找 XHR/Fetch,大概率返回 JSON。
- 看到 403/503,先想反爬:UA、Cookie、Referer、频率。
- `str` ⟷ `bytes` 的桥梁是 `encode/decode`,字符集要一致。
