# 第 6 章 并发爬虫 — 知识点梳理

> 对应 6.1 ~ 6.7。本章是并发架构的合集,涉及多模块协作,附流程图。

---

## 1. 并发模型对比(爬虫场景)

| 模型 | 适用 | 关键库 | 优点 | 注意 |
|---|---|---|---|---|
| 多线程 | I/O 密集(爬虫主战场) | `threading`、`queue`、`concurrent.futures.ThreadPoolExecutor` | 简单,GIL 不挡 I/O | 线程数太多会反噬 |
| 多进程 | CPU 密集 / 绕开 GIL | `multiprocessing`、`ProcessPoolExecutor` | 真并行 | 进程间通信成本高,连接对象不能跨进程序列化 |
| 协程 | 高 I/O 并发(数百~数千) | `asyncio`+`aiohttp`+`aiomysql`+`motor` | 单线程极高并发 | 全链路必须异步,有任意同步阻塞就退化 |

GIL 本质:Python 解释器进程内同一时刻只有一个线程执行字节码;但 I/O 时释放 GIL,故多线程对爬虫仍然有效。

## 2. asyncio + requests(线程池桥接)

`requests` 是同步库,放进 asyncio 必须委托线程池:

```python
loop = asyncio.get_event_loop()
await loop.run_in_executor(None, partial(requests.get, url, headers=h))
```

`functools.partial` 用来预绑定关键字参数(`run_in_executor` 不支持直接传 kwargs)。

⚠️ Py3.10+ 不推荐 `get_event_loop()`,改用 `asyncio.run(main())` + 在 `main` 里 `asyncio.get_running_loop()`。

## 3. aiohttp 标准写法

```python
import aiohttp, asyncio

async def fetch(session, url):
    async with session.get(url, headers=H) as resp:
        return await resp.text()         # 注意 await

async def main():
    async with aiohttp.ClientSession() as session:    # Session 复用连接
        tasks = [asyncio.create_task(fetch(session, u)) for u in urls]
        return await asyncio.gather(*tasks)

asyncio.run(main())
```

要点:

- **一个事件循环里共享一个 `ClientSession`**,不要每个请求开一个(原文 6.2 案例为每个任务都开新 session,效率差,真实项目不要这样)。
- `await response.text()` 是协程,必须 await。
- `asyncio.gather` 比 `asyncio.wait` 更常用(直接得到结果列表)。

## 5. 多线程版

```python
import threading
ts = [threading.Thread(target=worker, args=(p,)) for p in pages]
for t in ts: t.start()
for t in ts: t.join()
```

线程池(推荐):

```python
from concurrent.futures import ThreadPoolExecutor, as_completed

with ThreadPoolExecutor(max_workers=5) as pool:
    futures = [pool.submit(work, p) for p in pages]
    for f in as_completed(futures):       # 完成一个返回一个,不阻塞顺序
        print(f.result())
```

`as_completed(futures)`:无序但及时;直接 `for f in futures: f.result()`:有序但被慢任务阻塞。

## 6. 生产者-消费者(队列)模型

经典三段式:`url_queue → json_queue → content_queue`,每段一组线程/进程。

```
[get_url] ─▶ url_queue ─▶ [get_api_json] ─▶ json_queue ─▶ [parse] ─▶ content_queue ─▶ [save] ─▶ DB
```

关键 API:`q.put(x)` 计数 +1,`q.get()` 拿出,`q.task_done()` 计数 -1,`q.join()` 阻塞直到计数清零。

- 线程内用 `queue.Queue`(线程安全)。
- 跨进程用 `multiprocessing.JoinableQueue`(普通 `queue` 跨进程不安全)。
- 守护设置:无限循环消费者 `t.daemon = True`,生产者非守护并 `join`。

---

## 7. 多进程注意点

- **数据库连接对象不能放在 `__init__` 里**(进程序列化时会失败),应放在**类属性**或 worker 进程内部创建。
- `multiprocessing.JoinableQueue` 替代 `queue.Queue`。
- Windows 上必须 `if __name__ == '__main__':` 保护启动入口(否则递归 spawn)。
- 推荐 `concurrent.futures.ProcessPoolExecutor`,API 与 ThreadPool 一致。

## 8. 异步文件写入(`aiofile`)

```python
import aiofile

async with aiofile.async_open(path, 'wb') as f:
    await f.write(content)
```

适合下载图片/视频的场景,与 `aiohttp` 流式响应组合使用。

⚠️ 现行更常用的是 **`aiofiles`**(注意复数,API 与原生 `open` 更像);二者并存,知道两个名字即可。

## 9. 原文需要纠正/补充的点

| # | 原文 | 问题 | 正确做法 |
|---|------|------|---------|
| 1 | aiohttp 案例里**每个协程都新建 `ClientSession()`** | 浪费连接、违反 aiohttp 官方"会话应像一个全局对象"指导 | 应在外层创建一个 session,作为参数传入每个 task |
| 2 | `asyncio.get_event_loop()` + `loop.run_until_complete()` | Py3.10+ DeprecationWarning,3.12+ 行为变化 | 用 `asyncio.run(main())`;循环用 `asyncio.get_running_loop()` |
| 3 | `await asyncio.wait(tasks)` | 不返回结果直接拿,需通过 `.result()` | 推荐 `await asyncio.gather(*tasks, return_exceptions=True)` |
| 4 | aiomysql `connect(loop=loop)` | 1.x 之后 `loop` 参数已弃用,自动用当前 loop | 删掉 `loop=` |
| 5 | "在某些页面中不存在当前的 json 数据会抛出异常 ... 用 try/except TypeError" | 实际可能 `KeyError`/`TypeError` 都有 | 用 `try/except Exception as e` 或先 `.get()` |
| 6 | `insert into car_info(id, ...) values (0, ...)` 然后让 id 自动递增 | id 字段值给 0 会真的写 0,然后下一条主键冲突 | 要么显式不写 id 列,要么传 `None` 由数据库自增 |
| 7 | "汽车之家被反爬时编码会变 utf-8" | 反爬识别只是经验,不一定可靠 | 仍建议双 UA+代理+频控+chardet 嗅探多手段 |
| 8 | 6.4 多线程示例没有 `join`,主线程立刻退出 | 子线程可能没机会跑完(此例因为不是守护,故能跑完),不严谨 | 显式 `for t in ts: t.join()` |
| 9 | 6.5 描述"future.result() 会造成主线程堵塞" | 实质是按 futures **提交顺序**等待 | 准确说法:有序但被慢任务阻塞;`as_completed` 是按完成顺序 |
| 10 | 6.6 注释"queue 模块在多进程下会阻塞" | 不严谨,实际是**进程间不能共享 `queue.Queue`** | 多进程应使用 `multiprocessing.Queue` / `JoinableQueue` |
| 11 | "GIL 锁导致无法利用多核" | 表述不完整 | 准确:CPython 解释器内一次只允许一个线程执行字节码;I/O 释放 GIL,所以多线程对 I/O 密集任务仍有效 |
| 12 | 6.7 进程池版本 `executor.submit(self.get_movie_info, params)` | 进程池 worker 会序列化 `self`(含 redis/mongo client 类属性),pymongo 客户端对 fork/spawn 不安全 | 进程内首次使用时创建 client,或用 `initializer=` 在 worker 启动时建客户端 |
| 13 | `aiofile` 与 `aiofiles` 两个不同包 | 原文示例用 `aiofile`(单数) | 注意拼写;`aiofiles` API 更接近内置 `open` |
| 14 | `__del__` 中关闭 redis | `__del__` 不可靠(GC 时机不定) | 用 `close_spider()` 显式调用,或 `atexit.register` |

---

## 10. 速记

- 爬虫 = I/O 密集 → 协程或多线程,不要无脑上多进程。
- 全异步链:`aiohttp + aiomysql + motor + aiofiles`,任意环节 `time.sleep` / `requests.get` 都会毁掉并发。
- 多进程下:DB client 别放 `__init__`,放类属性或 worker 内创建。
- 队列模型:`put` 计数 +1,`get` 之后必须 `task_done` 才会 -1,`join` 等待清零。
- `as_completed` ≠ `gather`,前者按完成序,后者按提交序。
