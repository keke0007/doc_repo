## 1. 数据分类

| 类型 | 例子 | 提取方式 |
|---|---|---|
| 结构化 | JSON、XML | `json` 模块 / `jsonpath` / `xmltodict` |
| 半结构化 | HTML | XPath(lxml)、CSS Selector(bs4)、正则 |

## 3. JSON 提取

```python
import json
json.dumps(obj, indent=2, ensure_ascii=False)   # py → 字符串
json.loads(s)                                   # 字符串 → py
requests.get(url).json()                        # 一步到位(等价 loads(text))
```

`ensure_ascii=False` 保留中文字符;`indent` 控制缩进美化。

## 4. XPath 速查

| 表达式 | 作用 |
|---|---|
| `nodename` | 选当前层名为 nodename 的元素 |
| `/` | 从根 / 父子关系 |
| `//` | 任意层级后代 |
| `.` / `..` | 当前 / 父节点 |
| `@attr` | 属性 |
| `text()` | 文本节点 |
| `[n]` | 第 n 个(从 1 起) |
| `[last()]` / `[last()-1]` | 最后 / 倒数第二 |
| `[@k='v']` | 按属性过滤 |
| `[position()>1 and position()<5]` | 区间过滤 |
| `[contains(@class,'item')]` | 模糊匹配属性 |
| `[starts-with(@id,'name')]` | 前缀匹配 |

### lxml 用法

```python
from lxml import etree
tree = etree.HTML(html_text)          # bytes 用 etree.HTML(bytes)
items = tree.xpath('//div[@class="item"]')
for li in items:                      # 子节点上继续 xpath 必须以 . 开头
    title = li.xpath('./a/text()')
    href  = li.xpath('./a/@href')
```

**返回值永远是 list**;空列表代表未匹配。常用三段式:

```python
val = (li.xpath('./a/text()') or [None])[0]
```

## 5. JSONPath 速查

| 语法 | 含义 |
|---|---|
| `$` | 根 |
| `.` 或 `[]` | 子节点 |
| `..` | 递归后代 |
| `*` | 通配 |
| `[n]` / `[n1,n2]` / `[start:end]` | 索引 / 多选 / 切片 |
| `[?(@.price<10)]` | 过滤器 |
| `[(@.length-1)]` | 表达式 |

```python
import jsonpath
jsonpath.jsonpath(data, '$..name')          # 失败返回 False(注意!)
jsonpath.jsonpath(data, '$.store.book[?(@.price < 10)].title')
```

⚠️ `jsonpath` 库匹配失败返回 **False** 而不是空列表,使用前判断 `result is False`。

## 6. BeautifulSoup4

```python
from bs4 import BeautifulSoup
soup = BeautifulSoup(html, 'lxml')   # 解析器推荐 lxml(快),备选 html.parser、html5lib
```

| 方法 | 返回 |
|---|---|
| `soup.find(name, attrs, string)` | 第一个匹配的 Tag,无则 None |
| `soup.find_all(...)` | list[Tag] |
| `soup.select('css 选择器')` | list[Tag] |
| `tag.get('href')` / `tag['href']` | 属性 |
| `tag.get_text(strip=True)` | 文本(含子) |
| `tag.string` | 直接文本(只有当 tag 内仅一个文本子节点时有值) |

CSS 选择器语法和前端一致:`.cls`、`#id`、`tag1 tag2`(后代)、`tag1 > tag2`(直接子)、`[attr=val]`。

`find_all` 关键参数:

- `name`:标签名 / 正则 / list
- `attrs={'class': 'x'}` 或 `class_='x'`(`class` 是关键字,加下划线)
- `string=...`:按文本筛选
- `limit=n`:最多取 n 个
- `recursive=False`:只看直接子级

## 7. lxml vs bs4 vs 正则

| 维度 | lxml(XPath) | bs4 | 正则 |
|---|---|---|---|
| 速度 | 最快 | 中(底层可用 lxml) | 看情况 |
| 语法 | 简洁,生态成熟 | Pythonic,API 友好 | 通用,但 HTML 易翻车 |
| 容错 | 好 | 视解析器(html5lib 最容错) | 差 |
| 推荐场景 | 大量数据、固定结构 | 临时小活、初学者 | JSON/嵌入式字符串内提取 |

## 8. 原文需要纠正/补充的点

| # | 原文 | 问题 | 正确版本 |
|---|------|------|---------|
| 1 | "`Beautiful Soup` 也是一个 HTML/XML 的解析器" | 严格说 bs4 是**解析包装器**,底层调用 lxml/html.parser/html5lib;它本身不是解析器 | 描述为"基于其它解析器的 DOM 操作 API" |
| 2 | 3.5 中很多代码段的 HTML 模板渲染丢失(变成了 Markdown 列表),导致 `text='''...'''` 里其实没有 `<li>` 标签,运行结果与注释对不上 | 原文模板损坏 | 实际使用时 `text` 应包含真实 HTML,例如 `<ul><li class="item-1"><a href="link1.html">first item</a></li>...</ul>` |
| 3 | jsonpath 示例 `$..name` 注释为返回 list | 没问题,但**未匹配时返回 False(而非空 list)** | 用前判 `if res is False: res = []` |
| 4 | 3.8 中代码包含明显的非法 jsonpath: `?(@.price =5 && @.price10)` | 是文档转写时的语法残缺 | 正确写法应为 `?(@.price >= 5 && @.price < 10)`,且 `&&` 在多数 Python jsonpath 实现里写法不一,推荐换 jsonpath-ng |
| 5 | 3.8 末尾 `jsonpath(info, '$.*')`、`jsonpath(info, '$..*')` 直接调用 `jsonpath` | 应为 `jsonpath.jsonpath(...)`,且 `res` 未定义(用了 `res` 实际只赋了 `ret`) | 改为 `jsonpath.jsonpath(info, '$.*')`,循环里用 `ret` |
| 6 | "string 参数" | bs4 4.4 以前叫 `text=`,新版本叫 `string=`,二者别名 | 现行版本推荐 `string=`,`text=` 仍可工作但已不推荐 |
| 7 | `soup.select('p #link1')` | 是空格分隔的**后代选择器**,不是层级运算 | 强调和 `p>#link1`(直接子)的区别 |
| 8 | "lxml 性能高于 bs4" | bs4 用 lxml 解析器时性能差距主要在 API 层 | 描述为"lxml 直接调用 C 库,bs4 多一层 Python 封装,故略慢" |
| 9 | XPath 中 `[position()>1 and position()<5]` 部分行被截断 | 原文丢字符 | 完整应为 `[position()>1 and position()<5]` |

## 9. 速记

- 接口型:`r.json()` + `jsonpath`。
- 静态 HTML:`etree.HTML` + `xpath`(快),或 `BeautifulSoup`(易读)。
- xpath 子节点再 xpath **必须以 `.` 开头**,否则会从根重新匹配。
- jsonpath 匹配失败返回 `False`,记得防御。
- bs4 的 `class` 关键字冲突,用 `class_=`。
