# Max Ma | AI+HR | AI重建新秩序 (@MaxMa_27)

AI产品经理 面试题拆解 手撕焚决二  
  
问：如果 Agent 需要连续调用多个系统，执行到第 6 步才失败，你会怎么做错误定位、重试和状态恢复？  
  
这道题考察的不是简单的异常处理，而是你是否具备复杂 Agent 工作流的工程化思维、故障排查能力，以及对业务连续性的理解。  
  
1.包过模版  
  
如果 Agent 需要连续调用多个系统，在执行到第 6 步时失败，我不会直接让 Agent 从头重新执行，而是会把整个任务看成一个有状态的工作流，重点解决三个问题：失败原因是什么、哪些操作已经成功、如何在不产生副作用的情况下恢复执行  
  
我会从错误定位、重试策略和状态恢复三个方面处理。  
  
第一，错误定位。 我会通过 Trace ID 查看 Agent 前 6 步的执行日志，包括输入输出、接口响应、耗时和异常信息，判断问题究竟出在 Agent 的推理决策、参数传递，还是外部系统的接口调用。  
  
第二，制定重试策略。 我不会对所有错误都进行无差别重试。对于网络超时、服务端 5xx 等临时性问题，可以采用指数退避策略；对于参数错误、权限不足等问题，则需要先修正问题再执行。同时，通过幂等机制避免重复创建订单等副作用。  
  
第三，进行状态恢复。 我会引入 Checkpoint 机制，在每个关键步骤完成后保存执行状态和结果。发生故障时，先读取最近一次成功的检查点，再判断第 6 步是否实际执行成功，避免从头执行或重复调用。  
  
另外，如果涉及多个系统，还需要考虑业务一致性。例如订单创建成功但支付失败，可以通过 Saga 补偿机制取消订单或释放库存。  
  
我认为，企业级 Agent 不仅要关注任务能否执行成功，更要关注出现异常后能否准确定位、可靠恢复，以及避免对业务造成重复操作或数据不一致。  
  
2. Max的面试建议  
面试的是 AI 产品经理，回答时需要体现三个层次，这非常关键：  
  
技术理解力： 知道 Trace、Checkpoint、幂等、Saga 分别解决什么问题  
  
产品抽象力： 能把复杂的多系统调用抽象成有状态、可恢复的工作流  
  
业务意识： 知道重复扣款、重复下单、数据不一致比 Agent 单纯报错严重得多
