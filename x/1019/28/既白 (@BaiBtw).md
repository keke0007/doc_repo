# 既白 (@BaiBtw)

日志、链路追踪和指标，都能帮助理解系统运行状况，但保留的信息不同。  
  
日志记录一件件发生过的事，比如收到一次请求、访问了一次数据库。统一字段和格式后，可以从大量记录里按关键词查找。常见的 ELK 组合用 Logstash 采集处理日志，Elasticsearch 做存储与检索，Kibana 提供查询和展示。  
  
链路追踪围绕一次请求，把它经过的环节串起来。例如请求从 API 网关到负载均衡器，再经过服务 A、服务 B 和数据库。把这条路径及各段耗时放在一起，更容易定位时间花在哪里。  
  
指标把系统表现记录成随时间变化的数值，适合汇总和比较，例如每秒请求数、接口响应时间、服务延迟。Prometheus 可以拉取应用暴露的指标，存储成时间序列，按规则生成告警；Grafana 用来展示，Alertmanager 负责后续告警通知。  
  
OpenTelemetry 把这些数据的生成、采集和导出放进统一框架。应用通过埋点、API 或 SDK 产生数据，Collector 可以接收、处理，再发给对应后端。它本身不负责把数据长期存储并做成查询面板，这部分仍由其他工具承担。  
  
三类数据也有交集：一次请求里的事件可以写成日志，日志里的数值可以汇总成指标，追踪则保留请求经过各个环节的关系。

一批异步任务里，有一个失败了，剩下的还要不要等？选 Promise 方法前，先把这个问题说清楚。  
  
比如一个页面要同时拿到商品信息和库存，缺一份就无法继续展示，可以用 Promise.all。它在全部成功后给出结果数组；只要有一个拒绝，整体就会拒绝。数组里的位置按传入顺序排列，不按谁先完成排列。
