# 工业聚 (@guyingjie129)

这个案例就是我上一篇提到的——Agent 应该让人容易做的事情有更大价值——的范例。  
  
不过，与其说是 Goal Engineering，不如说是 Goal-Driven Loop Engineering，核心行动力引擎是 Loop 而不是 Goal。  
  
目标是驱动和指引，是关键因素，但不负责承担工作载荷。  
  
体系化的循环工程包含几个核心模块——  
  
- 持续工作代理：行动力引擎，没有行动力就没有一切  
- 长程目标驱动：行动力兑现，短目标放到永动机里也会陷入停滞或空转  
- 最终交付物导向：减少中间交付物，让行动力/算力，更多投入在最终结果上，而非中间对齐环节。  
  
其中，【最终交付物导向】是关键，它可以衍生出前两个。  
  
当你面向最终交付物（ouput）提供其必要上下文输入（input）时，它已经包含长程目标了（给定结果需要出现），它已经要求着持续工作代理了（没出现之前不要停下来）。  
  
剩下的是体力活儿、技术活儿，agent 停下来了，你说“继续”手动驱动，循环递进，直到最终交付结果出现。Super Agents， Always-on Agents 主要让人省力了，减少人工驱动，但它们是工具属性，而非本质属性。  
  
本质是【聪明的模型+足够的工具+可达的最终交付结果】包含着实现路径的展开潜力，如果你愿意，你可以在最朴素的一问一答里，手动维持 Agent Loop 转发工具调用，走完全程（它只是慢）。  
  
理解了这个 nullshell 形态，构建 agent product 时，便拥有了纲领性认知。
