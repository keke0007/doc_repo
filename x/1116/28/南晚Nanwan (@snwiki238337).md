# 南晚Nanwan (@snwiki238337)

来自 Google Research 与特拉维夫大学的研究团队发表了一篇关于多 agent 自动优化的研究MultiLoop: Evolving Multi-Agent Harnesses for Complex Information-Seeking Tasks  
  
大家现在都在用 Coding Agent 去自动优化 Harness，但是研究团队作者想要看看把这套思路用在多 agent 系统上效果如何。  
  
作者搭了一个叫 MultiLoop 的极简自动化演化闭环，用 Gemini-3.1-Pro 充当优化器，在 Google 的 DeepSearchQA 复杂多步检索基准上，挑出 10 道所有基线全军覆没的难题作为训练集，让它看每一步的运行轨迹并直接修改多智能体的代码与提示词，最后在剩下的 890 道留出测试题上检验泛化效果。  
  
工程上的对比结果很有意思。在未优化前，单 agent 正确率是 68.69%，而多 agent 反而降到了 67.27%。  
  
经过 10 轮 MultiLoop 全量演化后，多智能体的完全正确率提升到了 71.88%，高出原始多智能体 4.61 个百分点，也反超了最好的单智能体 3.19 个百分点。  
  
有意思的是两个反向的对照，如果用同样的方法去优化单智能体，分数跌到 65.54%，因为优化器在 10 道题上加了个工具输出截断 3 万字符的规则。  
  
而如果只允许修改多智能体的提示词、不准动代码和工具，分数同样跌到 64.62%，子智能体的平均步数被拉长到 20.6 步，属于典型的在极小训练集上过拟合。  
  
作者对演化前后错误轨迹的逐一拆解。这种效果分数上涨几乎不是靠改好多 agent 如何协同做到的。编码优化器唯一做的架构级改动，只是给沙盒新加了一个联网下载文件工具，再配合更严格的提示词约束。  
  
结果确实消灭了不少错误和检索漂移，但多 agent 最核心的编排和工具执行错误基本没有修复，甚至有原本做对的题在改完后陷入了 agent 二次核验的死循环。  
  
而且演化后的系统派出的子智能体更多、总步数大幅膨胀，单轮测试成本从 7300 美元涨到了 12900 美元，部分涨分其实是用更高的测试时算力换来的。  
  
现在的自动化 Harness 演化在面对多 agent 协同失败时，它倾向于往系统里加入新的工具或是优化提示词，而不是去重构任务拆解逻辑或重新设计主从智能体之间传递信息的协议。  
  
如果我们真想让多 agent 系统通过自我演化解决协同问题，我认为需要在演化目标和搜索空间里显式约束去重构图和上下文接口。

一篇拆解现代大模型位置编码的文章，可以当做一篇综述看看，挺不错的，推荐阅读。是机器学习研究者 Sebastian Raschka 发布的。  
  
这篇文章要讲透的核心问题是 Transformer 的自注意力机制天生是个不分先后顺序的词袋，如果不额外注入位置信息，把红狐狸追灰狐狸调换词序，模型看到的词向量是完全一样的。  
  
虽然现在的解码器都有因果掩码，能隐约提供一点先后顺序，但掩码只能管看不看得见，分不清两个词中间到底是隔了 1 个词还是 100 个词。  
  
早期像 GPT-2 的做法是在进网络第一层之前，直接按绝对位置编号（1, 2, 3...）查表加一个位置向量。  
  
但这种绝对编码有个问题就是位于第 2 和第 5 位的两个词，如果前面加了一段话被整体推到了第 102 和第 105 位，虽然它们之间还是隔着 3 个词，但因为绝对编号变了，算出来的注意力得分也会变，导致模型一旦遇到超出训练长度的文本就容易出现问题。  
  
为了解决绝对位置平移就失效的问题，现在主流的 RoPE彻底放弃了在输入端加位置向量的做法，而是把位置信息改到了每一层注意力机制内部，只对 Query 和 Key 做旋转。  
  
Raschka 用一个极简的几何例子把它的原理讲得很清楚。把一个注意力头里的特征两两配成一对，看作二维平面上的一根箭头，不改变箭头的长度，只按词所在的位置乘以固定角度去旋转。  
  
假设每个位置转 20 度，第 2 位的 Key 就转 40 度，第 5 位的 Query 就转 100 度，两根箭头夹角是 60 度；当这两个词因为前面加了前缀整体平移到第 102 和第 105 位时，两根箭头虽然各自多转了 2000 度，但它们之间的夹角依然是 60 度，算出来的内积得分分毫不差。  
  
在手写 PyTorch 代码时，他还专门指出了一个跨框架迁移权重时的问题，原版论文和早期 LLaMA 是把相邻的两个特征配成一对，即 `(1,2), (3,4)` 这种交错配对（Interleaved）。  
  
而现在包括 Qwen3 在内的大多数实现，为了向量化计算正余弦更简单，改成了前半截和后半截对应配对，即 `(1,5), (2,6)` 这种对半切分配对。  
  
两者在数学上完全等价，但如果训练和推理框架用的配对顺序不一致又没重排权重，最后的出来的结果就会错乱。  
  
顺着这套基础逻辑，文章盘点了 2026 年最新一批开源权重模型在位置编码上的三个明显演变。  
  
第一是只转一部分维度的 Partial RoPE，比如 MiniMax-M3 在每个注意力头的 128 个维度里只拿 64 维出来做旋转，其余一半维度不动。  
  
按 Raschka 的测算，在 100 万 Token 上下文、BF16 精度下，少转一半维度能省下约 128 MiB 的正余弦查表显存，但 KV Cache 并不会减少，如果不是在超长上下文里极限抠显存，往往并不划算。  
  
第二是越来越流行的 RoPE 与 NoPE 混搭，比如 SmolLM3 每连续用三层 RoPE，到第四层就去掉位置编码只留因果掩码，Kimi K3 等前沿架构也大量采用了这种设计。  
  
原因是前几层已经把位置信息揉进了特征，而且因果掩码本身在前缀变长时会自然产生类似的统计特征供后层读取，每隔几层拿掉一次旋转，反而能减轻超长距离下的注意力衰减，让长文本外推更稳。  
  
第三则是像 Thinking Machines 的 Inkling 模型那样，完全不用旋转，而是回到类似早期 T5 的思路，根据词间距和隐藏状态直接在算好的注意力得分矩阵上加一个可学习的相对位置偏置。
