AI 工程面试深挖题 + 解决思路  
  
一、AI 方向  
  
1. 向量检索的底层逻辑是什么？  
- 文本用 Embedding 模型转成向量，语义相近的文本向量距离也近  
- 相似度常用余弦相似度或点积  
- 数据量大时用近似最近邻索引（HNSW、IVF），牺牲一点召回率换速度  
- 实战优化：合理切块（chunk 大小和重叠）、混合检索（向量 + 关键词 BM25）、检索后用 Reranker 重排  
  
2. 上下文溢出怎么处理？  
- 先算 token，超限前就处理，不等报错  
- 截断：保留系统提示和最近几轮对话  
- 摘要压缩：把旧对话压成摘要再放回上下文  
- 只检索相关片段（RAG），不把整份文档塞进去  
- 长期记忆存到外部（数据库或向量库），需要时再取  
  
3. Agent 状态机怎么设计？  
- 把 Agent 流程拆成明确状态：规划 → 调用工具 → 观察结果 → 判断是否完成  
- 每个状态定义清楚进入和退出条件  
- 设最大步数和超时，防止死循环  
- 状态持久化，中断后可以恢复  
  
4. 重试机制怎么做？  
- 先分清错误类型：网络超时、限流可以重试；参数错误、权限错误不该重试  
- 用指数退避加随机抖动（1s、2s、4s……）  
- 设重试上限，超过后降级：换模型、返回兜底答案或转人工  
- 有副作用的操作要做幂等（比如带唯一请求 ID），避免重试时重复执行  
  
5. Function Calling 死循环怎么调？  
- 记录每一步调用了哪个工具、传了什么参数、拿到什么结果  
- 常见原因：工具描述不清、返回结果模型看不懂、缺少“已完成”的判断条件  
- 解决：改清楚工具描述、规范返回格式、设最大调用次数、检测连续重复调用就中断  
  
二、基础工程  
  
6. 并发  
- 分清线程、进程、协程  
- 知道竞态条件、锁、死锁是什么  
- Agent 场景：多个请求同时调用模型 API，用异步加并发上限（信号量）控制，避免被限流  
  
7. 数据库索引  
- B+ 树索引原理：为什么能加速查询  
- 索引失效的常见情况：对字段用函数、模糊查询以 % 开头、联合索引不满足最左前缀  
- 会用 EXPLAIN 看查询计划  
  
8. 计算机网络  
- TCP 三次握手、HTTP 请求和响应、常见状态码（429 限流、5xx 服务端错误）  
- 网络抖动时：设合理超时、重试、熔断，流式输出要能处理中途断开  
  
三、面试官常用问法  
  
挑简历上的一个项目，让你讲一次具体的排错过程：  
- 当时怎么发现问题、怎么判断原因  
- 试过哪些方法  
- 为什么最后这样改  
- 基础题会穿插在这个过程里追问  
  
准备建议：至少亲手跑通一个 Agent 项目，并准备 1–2 个真实踩坑和修复的故事。
