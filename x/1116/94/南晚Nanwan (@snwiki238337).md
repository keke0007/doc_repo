# 南晚Nanwan (@snwiki238337)

OpenAI 发了一篇数据分析公司 Amplitude 的落地案例。  
  
这篇文章中主要是为了解决一个问题，就是现在很多研发团队都用上了 Codex 这类编程 Agent，写代码是快了，但一个产品改进从发现问题到真正上线往往还是要拖一个月。  
  
原因在于写代码只占最后一步，前面大量的时间全耗在了怎么从海量埋点和用户录屏里找出真问题以及怎么把问题转化为可执行的技术方案上。  
  
Amplitude 为此做了一个叫 Wave 的主动式产品 Agent，核心思路就是把前端的看数据找痛点和后端的交给编程 Agent 写代码接起来，让软件自己发现短板、自己出方案并验证效果。  
  
顺着 Wave 的工作流，它的第一步是解决怎么在不靠人的情况下，自动从数据里抓出真问题。  
  
Wave 在后台把三个原本割裂的数据源接在了一起。用户的操作会话录屏、产品埋点统计和底层代码库。  
  
文章里举了 Amplitude 自己首页的一个真实改造案例：Wave 在扫数据时发现，首页放了一排引导用户跟 AI 聊天的话题建议卡片，但用户几乎不怎么点。  
  
它顺着会话记录往下查，发现是因为这些卡片对所有人都展示一模一样的通用问题。于是它提出了一个具体的改动方案，根据当前用户刚刚看过的图表、仪表盘或者跳转前的上一个页面，动态生成个性化的提示卡片。  
  
这个改动上线做完 A/B 测试后，通过首页卡片发起的对话量在一天之内直接涨了 160%。  
  
找到问题之后，第二步是怎么把分析结论直接给编程 Agent 去落地。如果只是甩出一句模糊的分析结论，写代码的 Agent 根本没法动手。  
  
Wave 的做法是在发现改进机会的同时，自动打包生成三样东西，用图像模型画出来的界面改动线框图、对应的代码级技术方案，以及明确的验收标准。  
  
到了执行环节则采用分级放行，如果是明确的 Bug 修复，这套打包好的方案和验收标准会直接转交给 Codex 等编程 Agent 自动改代码。  
  
如果是涉及新功能或大改动的实验，则先交由人工确认。在内测客户发起的实验和功能开关里，有四分之一在 Wave 发现机会的当天就直接上线了，一半以上在四天内跑完了从发现到交付的全流程。  
  
第三步是解决这套常驻系统怎么控制算力、怎么防止 agent 的跑偏的问题。  
  
如果让大模型天天去全量扫录屏和代码，不仅贵，而且极容易把正常的业务波动误报成产品问题。Amplitude 的思路是把不同环节拆给不同量级的模型，并用一套防误报指标做筛选。  
  
就是说对于扫代码库和跑常规小检查这种重复上百次的高频活，全部交给低延迟、低成本的轻量模型 GPT-6 Luna。  
  
而对于负责深挖原因的 Agent，他们主要是是专门考核五个工程指标，结论有没有多模型的审查、然后是假阳性误报、能否按照评估器反馈做修正，工具调用失败的话能不能恢复，以及结论与凭据轨迹的对应。  
  
对比下来，他们选了综合得分最高且单次任务成本只有 1.28 美元的 GPT-6.1 Sol。  
  
至于生成方案线框图，则单独按界面文字清晰度和产品还原度选了 GPT-Image-2.5 Flare。  
  
通过这种流程，把数据分析和代码交付拧成了一个闭环。思路是很值得参考，反正我是很心动了。
