# Ethan 恩宇 (@UPing123zzz)

很多人已经开始研究 Agent、RAG、MCP、Harness，甚至能借助 Codex 几个小时做出一套完整的 AI 应用。  
  
但真让他解释一下分类、回归、聚类、异常检测、强化学习到底有什么区别，可能反而说不清楚。  
  
更离谱的是，有些业务明明用一个简单的机器学习模型就能解决，非要接入一个大语言模型，再套一层 Agent，最后搞出一套成本更高、响应更慢、维护起来还特别麻烦的系统。  
  
这张 Machine Learning Algorithms 整理得挺不错，把传统机器学习的几个主要方向串了起来。  
  
首先是 Supervised Learning，监督学习。  
  
核心是利用带标签的数据学习输入和目标之间的关系。  
  
Classification 解决分类问题，比如识别垃圾邮件、判断客户是否可能流失、识别用户请求属于哪种类型。  
  
常见算法包括 Logistic Regression、Naive Bayes、KNN、SVM、Random Forest 和 Decision Tree。  
  
Regression 则主要用于预测连续数值，比如销量、价格、需求量。  
  
Linear Regression、Lasso Regression 等都属于这一方向。  
  
这里还有个挺有意思的细节：Logistic Regression 虽然名字里有 Regression，但通常被用来做分类任务。  
  
然后是 Unsupervised Learning，无监督学习。  
  
这类方法不依赖目标标签，主要从数据本身寻找结构和规律。  
  
比如 K-Means、DBSCAN 可以用于聚类，把相似的客户、行为或者内容划分到不同群组。  
  
Isolation Forest 可以用于异常检测，识别那些与正常数据明显不同的样本。  
  
Apriori、FP-Growth 则主要用于关联规则挖掘。  
  
不过原图有个分类不太准确的地方：PCA、ICA 不属于关联规则算法，更适合放在降维、特征提取或信号分解的范畴里。Z-score 也是统计方法，并不是一个完整的机器学习模型。  
  
再往下是 Semi-supervised Learning，半监督学习。  
  
它解决的是标注数据不足的问题。  
  
比如企业有十万份文档，但只有几百份经过人工准确分类。  
  
这时候可以研究 Self-Training、Co-Training 等方法，尝试结合少量已标注数据和大量未标注数据进行学习。  
  
最后是 Reinforcement Learning，强化学习。  
  
这类方法研究的是智能体如何通过与环境交互，根据奖励反馈学习行动策略。  
  
这里涉及 Model-Free、Model-Based，以及 Q-Learning、Policy Optimization 等不同方法。  
  
不过强化学习也不是简单地让模型多反思几次，更不是给 Agent 加个 Reward Prompt，就突然拥有了自主学习能力。  
  
它背后还涉及状态、动作、奖励、策略和环境反馈。  
  
把这些东西放在一起，你会发现一个很重要的问题。  
  
我们现在天天研究的大语言模型，只是整个 AI 技术体系中的一部分。  
  
真实的企业业务里，很多问题根本不需要上来就调用最先进的 LLM。  
  
比如识别 API 异常调用，可能传统异常检测方法就能解决。  
  
预测某个业务指标，可能回归模型更容易验证。  
  
对大量客户进行初步分群，可以先研究聚类。  
  
用户意图分类如果类别明确、样本充足，也完全值得比较传统分类器与大模型的成本和效果。  
  
当然，大模型在复杂语义理解、少样本任务和非结构化信息处理上有自己的优势。  
  
但这不代表所有问题都应该交给大模型。  
  
我觉得现在很多 AI 开发者特别容易犯的错误，就是先选择工具，再反过来寻找适合这个工具的业务问题。  
  
看到 Agent 火，就什么都想做成 Agent。  
  
看到 RAG 火，就什么数据都想扔进向量数据库。  
  
看到大模型能力越来越强，就觉得传统机器学习已经没有研究价值了。  
  
但真正做工程，应该反过来。  
  
先弄清楚你要解决的是分类、预测、聚类、异常检测，还是连续多步骤决策。  
  
再看数据有没有标签、样本是否足够、错误的代价有多大、对延迟和成本有什么要求。  
  
最后才决定采用什么算法、模型和系统架构。  
  
而且选对算法，也不代表项目就完成了。  
  
数据泄漏、过拟合、样本分布变化、评测指标选错，都可能让一个离线测试表现很好的模型，在真实业务环境里直接翻车。  
  
所以我越来越觉得，AI 时代真正值得积累的，不只是熟悉多少个模型、多少个框架。  
  
而是你能不能理解问题的本质，知道不同算法在解决什么问题，明白它们各自的假设和局限，再根据真实数据和业务要求做出合理取舍。  
  
AI 编程工具确实可以帮我们快速实现算法，甚至自动完成大量训练和调参代码。  
  
但它不会因为代码成功运行，就自动证明你的问题定义、数据和评测方式是正确的。  
  
别最后 Agent、MCP、LangGraph 全会用了，遇到一个简单的分类问题，却连为什么不直接使用 Logistic Regression 都解释不清楚。  
  
技术先进不等于方案合理。  
  
真正的 AI 工程能力，不是所有问题都使用最复杂的模型，而是面对不同问题，能够找到足够有效、成本合理、结果可验证的解决方式。
