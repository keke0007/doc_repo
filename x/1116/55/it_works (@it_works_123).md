# it_works (@it_works_123)

开发 PiBot 多端互联时，我一直在思考一个问题：  
  
Agent 的设备连接能力，应该由谁来掌控？  
  
如果 Agent 想要跨设备执行任务，就绕不开一个问题：设备之间如何通信？  
  
局域网直连很简单，但一旦设备处于不同网络、不同地区，NAT 和防火墙就会成为障碍。  
  
所以 PiBot 在设备连接上做了几种选择：  
  
🔹 官方中继：开箱即用，不需要用户自己搭建基础设施。  
  
🔹 自建中继：支持用户部署自己的中继服务，企业也可以掌控自己的通信基础设施。  
  
🔹 P2P 直连：支持局域网直连和 WebRTC 打洞，尽可能让设备之间直接通信。  
  
还有一个重要设计：聊天和文件传输采用端到端加密，即使经过中继，服务端也无法看到通信内容。  
  
我不希望 PiBot 的多端能力变成另一个云平台的附属功能。  
  
用户可以选择官方服务，也可以完全自建；可以使用局域网，也可以跨网络连接自己的设备。  
  
Agent 应该跟着用户走，而不是让用户跟着 Agent 的服务器走。  
  
这就是 PiBot 对多端互联的一点理解
