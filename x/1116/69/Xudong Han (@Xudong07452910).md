# Xudong Han (@Xudong07452910)

Agent 开始接长期目标之后，怎么划定它的工作范围就变得很关键。  
  
Harrison Chase 和 Actively AI 刚发了一篇《Goal Engineering》，核心观点很简单：提出了一个挺有启发的观点：按照人最容易提供反馈的方式，来划分 Agent 的工作范围。  
  
Agent 很多时候出错，是因为缺少上下文。文档、API 这些信息还好补，真正麻烦的是专家脑子里的隐性知识，比如品牌调性、销售策略该多激进，这些往往需要靠反复反馈来校准。  
  
Actively 做销售 Agent 的经历就很典型。  
  
最初他们为每个客户分配一个 Agent，结果销售需要在一堆 Agent 之间来回切换，在某个客户身上积累的经验，也很难复用到其他客户。  
  
后来改成按「Motion」划分，也就是让一个 Agent 专门负责一类工作，比如外联或早期销售推进。  
  
这样销售可以集中审核同类任务，一次反馈就能影响更多客户。客户资料则由后台 Agent 按需收集。  
  
文章最后还有个挺大胆的判断：「Prompt Engineering 和 Context Engineering 会消失，但 Goal Engineering 会留下来。」  
  
这个预测可以讨论，但我挺认同其中一点：Agent 的工作范围怎么划，直接决定了人类反馈能否被有效复用。  
  
对于长期运行的 Agent，这可能是个很值得重视的架构设计问题。
