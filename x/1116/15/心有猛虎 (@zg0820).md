# 心有猛虎 (@zg0820)

《三步搭出第一个真能干活的 Agent》｜44 万播放的 n8n 教程，换成中文可跑版本  
  
Jeff Su 的《The AI Agent Tutorial That Should've Been Your First》用 n8n 演示了三步搭 agent，44 万播放。原视频：[youtube.com/watch?v=GchXMR…](https://youtube.com/watch?v=GchXMRwuWxE)  
  
我按中文环境和自己跑过的工具链重排，保留「大脑 → 工具 → 行为约束」这个骨架，但每一步都给可替换的国内可用方案。  
  
**先说清它做什么**：一个订阅追踪 agent——你用自然语言说「我订了 X 服务，每月 30 号扣 99」，它自己解析、写进表格、下次能查。价值不在功能，在它演示了 agent 的最小完整结构。  
  
**Step 1：搭大脑（chat model + memory，对应 03:32）**  
两件套：一个能推理的模型，加一份记住历史的状态。没有 memory，每次对话都是失忆的，agent 无法承接上一轮的结果。  
- 原方案：n8n 里挂 ChatGPT/Claude 节点 + Simple Memory  
- 替换：本地用 Claude Agent SDK 起一个 20 行的最小 agent（模型 + 一个 messages 数组即可），或直接用支持会话状态的 API。**别一上来就上框架**，先徒手跑通「推理→工具→回填」循环，才知道框架替你做了什么。  
  
**Step 2：接工具（对应 08:21）**  
agent 的价值全在它能碰什么。原视频接 Google Sheets；中文环境可换成飞书多维表格、Notion API，或最朴素的本地 CSV 写入。  
关键设计：工具描述要写清「什么时候该用我」，模型靠描述选工具，描述含糊就会乱调。每个工具的入参尽量少、错误要显式返回，别让 agent 猜。  
  
**Step 3：写系统提示词（行为约束）**  
这是最多人省掉、也最不该省的一步。系统提示词不是「你是一个助手」，是三件事：能调哪些工具、什么情况必须停下来问人、输出落到哪里。  
可直接抄的骨架：  
`目标：<一句话> / 可用工具：<列表+触发条件> / 红线：<超出范围先询问> / 落盘：<结果写到哪> / 停止：<达成什么就不再循环>`  
  
**跑通之后的两个检查**  
① 故意给一句含糊输入，看它是乱调工具还是先追问——这决定它能不能上生产；② 数一轮任务烧了多少 token、调了几次工具，把「成本」也当成设计指标。  
  
**能带走的**：agent 不神秘，就是「一个会选工具的循环 + 一份不失效的上下文 + 一套明确的刹车」。三步各写二十行，比看十小时课程更扎实。
