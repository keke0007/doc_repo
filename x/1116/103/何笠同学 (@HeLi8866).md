# 何笠同学 (@HeLi8866)

Anthropic 刚发了篇技术指南，专门讲怎么搭 always-on agent！  
  
大家最容易搞错的一点是：always-on agent 并不是 24 小时不停地跑。它一天里几乎都在休眠，醒过来干一小轮，把状态存好，接着再睡。  
  
我整理出来 5 个关键模块👇：  
  
1. Event Inbox  
在 webhook 和 agent 之间加一张数据库表。webhook 要尽快回确认，按用户来，同一时刻只开一个在跑的 worker，避免任务互相撞上，短时间里连续进来的内容就合并处理。  
  
2. Timers  
定时器单独放一张表，不要跟 inbox 混在一起。拆成单次跟进，以及按周期重复的安排。后台有个轮询，到期了就塞到 inbox 里。  
  
3. Lean Memory + Dreaming  
只留下没法重新找回来的内容：用户的指令、用户的笔记、过往消息，还有任务进展。每次醒过来只先读一份简短索引，别把所有文件都塞进来。隔一段时间做 dreaming，清掉已经过时的内容。  
  
4. Unattended Permissions  
别把原始 API 密钥直接放进 agent 沙箱，通过外部 proxy 注入。遇到比较冒险的动作，用 Deferred Tool Calls 先停住等人批准，同时不把 worker 卡住。  
  
5. Outbox  
要发出去的回复先排进队列，让 agent 自己掌握推送的快慢，别在凌晨 3 点把人刷爆。
