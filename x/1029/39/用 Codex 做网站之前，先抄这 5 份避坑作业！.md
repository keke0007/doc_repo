# 用 Codex 做网站之前，先抄这 5 份避坑作业！

*By 大卫｜AI抄作业 (@AI_DVD6)*

![Banner](<用%20Codex%20做网站之前，先抄这%205%20份避坑作业！.assets/image-01.jpg>)

**用 Codex 做网站，最崩溃的不是写不出来，而是做出来了却没法用！😭**

折腾一下午，页面漂亮、按钮能点，感觉自己马上就能搞个出海项目了。结果一上线：**报错、白屏、手机排版乱套，网站还一股浓浓的「AI 味」……**

**AI 帮你省了写代码的时间，你却把时间全花在了填坑上。**

我整理了用 Codex 建站最容易翻车的 **5 个地方**。不讲复杂代码，只讲三件事：

① **哪里容易翻车、**② **怎么解决、**③ **有哪些现成工具可以直接用。**

准备靠 AI 做网站、搞副业的、出海的，建议先收藏。

## 01｜一上线就崩

Codex 是在你的电脑上干活的。它说「成功了」，意思是在你电脑上成功了。网站上线后跑在另一台机器上，那台机器只拿到你传上去的代码，你电脑里的设置和密钥它都没有。大部分部署问题都出在这里。

**一、最常见的 4 种翻车：**

① **一上线就报错「构建失败」**

线上环境比你的电脑严格，有时只是文件名大小写没对上就会卡住。把报错日志整段发给 Codex，让它查具体原因，别急着推倒重做。

![Image](<用%20Codex%20做网站之前，先抄这%205%20份避坑作业！.assets/image-02.jpg>)

② **页面能打开，但 AI 不回复、数据出不来**

多半是密钥等配置还留在你电脑里，没填到线上。让 Codex 列出要补哪些配置、去哪里填。填好后要重新部署，光刷新页面没用。

注意：密钥别贴进公开代码，也别出现在截图里。

![Image](<用%20Codex%20做网站之前，先抄这%205%20份避坑作业！.assets/image-03.jpg>)

③ **你能打开，别人打不开**

常见原因是代码里写死了 localhost，意思是「本机」。在你那里它指你的电脑，在别人那里就指别人的电脑。让 Codex 全局搜一遍 localhost，改成线上地址。

④ **绑了域名还是打不开，或者提示「不安全」**

域名设置改完要等一段时间才生效，安全证书也要等它签下来。先等一等再试；还不行，把域名后台的截图发给 Codex，让它帮你核对哪里填错了。

**二、学会这3 招，躲开大部分坑！**

1️⃣ **第一天就上线**  
功能还没写，先让 Codex 做一个只有网站名字的页面，传上去，用手机流量打开。之后每加一个功能就上线一次，哪一步出问题一眼就知道。

2️⃣ **上传前先在本地「模拟上线」一次**  
直接跟 Codex 说：「上传前先在本地跑一遍上线用的构建命令，确认没有报错。」

3️⃣ **展示类网站别自己买服务器**  
作品集、介绍页，用 Vercel 或 Cloudflare Pages，连上 GitHub 就自动上线。自己的服务器关个终端、重启一次，网站就可能没了。

![Image](<用%20Codex%20做网站之前，先抄这%205%20份避坑作业！.assets/image-04.jpg>)

**三、可以抄的作业**

**Vercel Templates**：[vercel.com/templates](https://vercel.com/templates)

里面有博客、作品集、产品介绍页等项目模板。挑一个接近自己需求的，先按说明部署，再让 Codex 改内容和功能。

第一版尽量选简单的。只是做个介绍页，就别挑带登录、数据库和支付的整套系统，配置越多，排查越费劲。

把模板链接交给 Codex，可以这样说：

```plaintext
帮我判断这个模板是否适合我的需求，需要注册哪些服务、填写哪些配置。先指导我把原版部署成功，再逐步修改。每次只做一个能检查的改动。
```

## 02｜一股 AI 味

你只说「做个好看的网站」，它就给你最常见的那种好看。它不知道你的用户是谁，只能取平均值；你不要求，它也不会拿手机看一眼效果。

**一、最常见的 3 种翻车**

① **一看就是模板**

紫蓝渐变、半透明卡片、emoji 图标、「高效·智能·安全」，灰色小字一大片。每处都没错，合起来就是模板，访客第一眼就不太信。别让它自由发挥，给它一个参照网站。

![Image](<用%20Codex%20做网站之前，先抄这%205%20份避坑作业！.assets/image-05.jpg>)

② **到了手机上就乱**

导航挤成好几行，卡片压成窄条，表格跑出屏幕。让 Codex 按手机宽度截图自查；它做不到的话，你用手机打开，截图发给它。

![Image](<用%20Codex%20做网站之前，先抄这%205%20份避坑作业！.assets/image-06.jpg>)

③ **越改越像另一个模板**

你说「整体再好看一点」，它就推翻重来。一次只改一处，话要具体：「标题再大一级，下面那行灰字删掉。」

**二、学会这3 招，让它少一点 AI 味！**

1️⃣ **给参照，别给形容词**  
「像某某官网首页那样克制」比「要有高级感」管用得多。

2️⃣ **写清楚不要什么**  
比如：不要渐变背景，只用一个主色，正文不小于 16px，不用 emoji 当图标。

3️⃣ **先定第一屏放什么，再调样式**  
访客一打开先看到什么、哪些可以删，想清楚了页面才有主次。

**三、可以抄的作业**

① **Lapa Ninja：找整站参考**：[lapa.ninja](https://www.lapa.ninja/)

可以按网站用途、风格和颜色浏览。做 AI 工具介绍页，就找相近的产品页面；做个人作品集，就看作品集。先选内容结构合适的，再看配色和动效。

② **Siteinspire：看排版和留白**：[siteinspire.com](https://www.siteinspire.com/)

想做得干净、克制，可以从 Minimal 等分类里找。重点看标题有多大、一屏放多少信息、段落之间留多少空白。

③ **Mobbin：看具体功能怎么排**：[mobbin.com](https://mobbin.com/)

做记账工具、管理后台时，光参考首页不够。登录、表单、设置、空白页面怎么安排，可以在这里看真实产品的页面和操作流程。完整访问有付费方案。

④ **Realtime Colors：把配色放进网页里试**：[realtimecolors.com](https://www.realtimecolors.com/)

几块颜色单独看挺好，放进网页却未必协调。这个工具能直接预览颜色和字体在页面上的效果，选好后再把配置交给 Codex。

最省事的用法：**找一个参考站，截下电脑和手机页面，指出具体想学哪里。** 别一次扔十张风格不同的图，让它自己猜。

可以直接复制：

```plaintext
请参考我提供的截图调整首页。
第一张参考排版和留白，第二张参考配色。保留我的内容与现有功能，图片和文案使用我自己的。
先说清楚标题、正文、按钮和内容区准备怎么安排，再开始修改。完成后检查电脑和手机效果，并实际点击导航、表单和弹窗。
```

## 03｜做的不是你要的

一句话需求里，大部分信息还在你脑子里。谁用、最常做什么、哪些不要，它只能猜，猜的依据是「同类网站一般都有什么」。

**一、最常见的 2 种翻车**

① **做多了**

你只想要一个随手记账的页面，它给你做了注册登录、饼图、月报。返工删功能，代码里留下一堆用不上的东西。开工前就告诉它「明确不做什么」。

② **越改越偏**

改到第五轮，它忘了你第一轮说过「不要数据库」，又给你加了一个。把这类长期规矩写进项目里的 AGENTS.md 文件，Codex 每次开工都会先读它。

**二、学会这3 招，让它少跑偏！**

1️⃣ **动手前写 5 行需求**  
比来回聊天省事，下面卡片就是一个例子。

2️⃣ **先让它复述、提问，再写代码**  
它问出来的，往往就是你漏写的。

3️⃣ **一轮只做一件事**  
先做「能记一笔」，确认没问题再做「本月合计」，跑偏也只偏一小步。

![Image](<用%20Codex%20做网站之前，先抄这%205%20份避坑作业！.assets/image-07.jpg>)

**三、可以抄的作业**

需求总跑偏，先抄这张需求单

① 小项目先不用安装新工具。把下面五行填好，交给 Codex：

谁用：  
最常做的一件事：  
第一版必须有：  
明确不做：  
做到什么程度算完成：

再补一句：

先别写代码。复述我的需求，把会影响实现方案的问题问清楚。确认后整理成项目文档，后续修改以这份文档为准。

② 项目复杂了，可以再看 **GitHub Spec Kit**：[github.com/github/spec-kit](https://github.com/github/spec-kit)

它提供围绕需求规格组织开发的工具和流程。只做一个小页面，先把上面五行写清楚就够了。

## 04｜功能跟不上需求

本地小工具默认只有你一个人用、电脑一直开着、数据就在旁边。想随时打开，或者发给别人用，这三件事就都不成立了。

**一、最常见的 4 种翻车**

① **上线后数据读不到、存不住**

表格和数据文件在你电脑上，线上读不到；Vercel 这类平台也不会保留写到本地的文件。让 Codex 把数据挪到线上存储（见下面炒作业部分）。

② **拿到网址的人都能进**

你的数据谁都能看，甚至能改。自己用就加一道访问密码；给别人用就要做登录。

③ **定时任务停了**

每天 8 点自动更新，靠的是你的电脑开着，合上笔记本就停了。让 Codex 改用 Vercel 的 Cron Jobs 或 GitHub Actions 定时跑。

④ **账单被人刷**

网页里调了 AI 接口，密钥写在前端代码里，被人扒走以后刷的是你的钱。让 Codex 把密钥挪到服务端，你再去接口平台后台设一个月度消费上限。

**二、先问一句：这东西到底谁用？**

1️⃣ **只有你，坐在电脑前用**  
不一定要上线。可以把它封装成 Codex 的 Skill 或一个固定命令，需要时调一次，上面 4 个坑都碰不到。

2️⃣ **你自己用，但要随时打开**  
上线，加访问密码，数据挪到云上。

3️⃣ **给别人用**  
登录、数据隔离、消费上限都要做，这时它已经算一个产品了。

![Image](<用%20Codex%20做网站之前，先抄这%205%20份避坑作业！.assets/image-08.jpg>)

**三、可以抄的作业**

要保存数据、注册登录，用现成服务

① **Supabase**：[supabase.com](https://supabase.com/)

它提供数据库、用户登录和文件存储等能力。做需要多设备同步、多人使用的小工具时，可以让 Codex 接入。

不过，接好登录还得检查数据权限。不能甲用户换个请求参数，就能看见乙用户的记录。

交给 Codex 时，把验收要求一起写上：

```plaintext
请先判断我的项目是否需要 Supabase，需要用到哪些功能。接入后，用两个测试账号检查：各自能保存、查看自己的数据，但不能读取或修改对方的数据。列出实际检查结果。
```

## 05｜做出来没人用

AI 把做网站变便宜了，找用户这件事它帮不上忙。很多人把时间都花在加功能、调样式上，留给「谁会用」的时间几乎是零。

**一、最常见的翻车**

网站上线，链接发出去，几个朋友说「挺好」，然后就没有然后了，访问量每天个位数。以前做不出来还能怪技术，现在一个周末就做完了，没人用就只剩一个问题：到底有没有人需要它。

**二、这3 招，先确认有人要！**

1️⃣ **先找人，再做功能**  
 动手前，能说出 3 个具体会用它的人，或者一个具体的群、一条具体的求助帖。

2️⃣ **第一版可以很丑**  
一个介绍页加一个表单，看有没有人留联系方式，比做完一整套系统更早知道答案。

3️⃣ **能手动的先手动**  
确定有人要了，再让 Codex 把这一步自动化。

**三、可以抄的作业**

不确定有没有人要，先收反馈，再加功能

① **Tally：做报名和反馈表单**：[tally.so](https://tally.so/)

先用表单收集需求、试用报名或联系方式。重点问对方现在怎么解决、哪里最麻烦、是否愿意试用，别只问「你觉得这个想法好吗」。

② **Microsoft Clarity：看访客卡在哪里**：[clarity.microsoft.com](https://clarity.microsoft.com/)

网站有了访客之后，可以用热力图和会话回放，观察他们点哪里、在哪里停住、有没有找到主要按钮。它会记录访客操作，网站隐私说明里要写清楚；有欧洲访客的话，还要先征得同意。

有人来却用不下去，再查页面和流程；还没人来，就先去找第一批愿意试的人。

## 最后：按这个顺序来就行了！

大多数人的顺序正好反了：先花很久调功能和样式，最后才上线，全弄完才想起来问谁会用。更省事的顺序是：

1. **写 5 行需求，想清楚谁用、用来干嘛。**
2. **第一天就上线一个空页面，手机能打开。**
3. **只做最核心的一个功能，做一点、上线一点。**
4. **功能稳了再调设计：找参照、写清楚不要什么、用手机看。**
5. **要长期用或给别人用，再处理数据、登录和消费上限。**
6. **找第一批用户从第 1 步就开始。**

5 份作业不用一次抄完，先用上一两个就够了。如果今天只做一件事：让 Codex 生成一个只写着网站名字的页面，传到 Vercel 或 Cloudflare Pages，用手机流量打开。这一步走通，后面再出问题，你至少知道该往哪里查。
