# 码良 (@cxjwin)

做过多 Agent 研究系统的 Anthropic，这次劝企业把不少子 Agent 并回主循环。他们的 Applied AI 团队在几家企业的部署里比过：带 Skill 的单 Agent，质量常常既好过一个大提示词，也好过拆成子 Agent，单任务的成本和延迟往往还更低。  
  
还值得拆的只剩三种情况：上下文塞得太满，效果出现了测得出来的下降；几件事要并行，各要一个用完就丢的干净上下文；单 Agent 选不对工具，或者系统提示词里的指令互相冲突。  
  
更常见的是照组织架构拆：一个团队一个子 Agent，最后几百个互相重叠、没人负责，每个团队往系统提示词里加一句，规则互相打架。一家客户把多 Agent 方案和单 Agent 循环一比，后者快了约一倍。  
  
并回来也有顺序：先建一套端到端评测，10 个标准样例就能起步；一次只并一个，子 Agent 的提示词改成 Skill，接口做成 MCP 工具，并完分数更差才留着。别只看总分。他们的客服样例并完以后延迟降了，主 Agent 却拿着查订单的工具自己回答，没去问物流子 Agent 要送达日期，这个错两次运行里只出现了一次。  
  
我九月那次一个主 Agent 带三个子 Agent 的实测，token 用到预算的 192 倍，复盘时说不清值不值，缺的就是同条件下的单 Agent 对照。拆不拆，先拿评测说话。
