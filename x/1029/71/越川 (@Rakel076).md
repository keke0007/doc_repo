# 越川 (@Rakel076)

Anthropic 前两天发了篇文章，劝大家少用子代理：好几家企业实测，一个主 agent 加 skills，效果比一堆子代理分工更好，有一家速度快了大概一倍。  
  
我去翻了原文，18 分钟的长文，转的大多只到这一句，后面几条更值得记：  
  
1、什么时候该留子代理，它只给了三条：主循环上下文塞太满、效果能测出来变差；几件事要并行，各开一个干净的上下文，干完就扔；工具太多或者规矩互相打架，一个 agent 选不对工具。三条都不沾，就别拆。  
  
2、工具定义超过 30 到 50 个，模型挑工具就开始变差。它建议按「用户想干什么」给工具归类，别一个接口一个工具，用不到的延后再加载。  
  
3、Claude Code 自己的系统提示词，给新模型用的版本砍掉了 80% 以上，很多内容改成用到哪个 skill 再读哪个。  
  
4、要合并，一次只并一个子代理，拿 10 个标准例子跑前后对比，分数没变差才留下。它举了个客服 agent 的例子：把物流专员并进去以后是快了，但问送达日期时，它直接拿查订单的工具回答，不再去问物流那边。  
  
做 agent 的可以先拿第 1 条对一下，三条都不沾的子代理，多半是白拆了。
