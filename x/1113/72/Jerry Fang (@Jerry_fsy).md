# Jerry Fang (@Jerry_fsy)

做Agent，我会看哪些运行数据？  
  
最近有两次排查让我体会到可观测性的价值。一次是看缓存命中率时，发现数据有一些奇怪，顺着异常查到了路由侧的一个bug。另一次是看模型的输出token数和单请求输出速率时，发现了推理侧的问题。我把那次的数据提供给了推理团队，作为优化的参考。Agent的回答看起来正常，运行数据里也可能已经有了问题的线索。  
  
如果只选一个tracing工具，我会推荐Langfuse。我用下来觉得它成熟，好用。每轮调用LLM，我会看传入了什么上下文，模型输出了什么，以及输入，输出和缓存命中率各有多少token，生成速度是多少。看整个Agent Loop时，我更关心工具调用了几次，上下文压缩了几次，以及上下文最长到了多少token。  
  
日常可以吧缓存命中率，生成速率这些关键指标汇总到飞书表格里看趋势，再接一个运维agent，发现异常时提醒我们。收到提醒后，就可以回到Langfuse，沿着相关的trace看具体是哪一步出了问题。
