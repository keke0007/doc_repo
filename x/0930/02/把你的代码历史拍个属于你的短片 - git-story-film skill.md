# 把你的代码历史拍个属于你的短片 - git-story-film skill

*By 海拉鲁编程客 (@hylarucoder)*

![Banner](<把你的代码历史拍个属于你的短片%20-%20git-story-film%20skill.assets/image-01.jpg>)

关注我的大部分朋友都是程序员，这个 skill 就是给你们，更准确是给我们写的。

维护代码仓库的人，**手里都有一部现成的 Git 纪录片：**第一次提交，第一个版本，最忙的那一天，半夜的回滚，改名，搬家，几万颗星。可这些都躺在 git log 里，新来的人只看 README。

git-story-film 是一个给 [raven](https://github.com/EverMind-AI/Raven) 做宣传视频时产出的创意 skill。你给它一个 GitHub 链接，Opus 5.5 就当导演：从几千次提交里挑出能讲故事的事实，给项目找一个主角，定一种画风，最后交给你一部两分钟左右的手绘动画短片。

你最后拿到的是：

- 一个 4K、60 帧的 MP4，配乐由代码实时合成；
- 一键生成，一镜到底，但也保留了源码可修改的空间，绝对不是那种快闪式的 AI Slop
- 主角第一人称的字幕，讲给第一次听说这个项目的人；
- 画面上真实的日期、commit hash 和提交次数，一次提交就是画面上的一颗珠子、一盏灯或一片叶子；
- 一个能在浏览器里拖着看的 Studio 页面，以及整部片的源代码。

这个 skill 不仅能帮你一键生成，也能让你扮演一个真正的导演，帮你提前订好提纲、分镜、脚本，每走一步都停下来给你看一样东西，你点头了才往下走。

# 七步视频法：以 Raven 为例

我把视频拆成了七部, 这七步不是凭空设计的, 是因为曹植七步成诗(并不)。2026年9月24日做 Raven 那天，还没有这套流程：先出整片，边看边改。第一次 4K 渲染在上午 11 点，带字的分镜到下午 3 点才有。一天里开了 13 次 4K 渲染，5 次半路叫停或崩溃。做完之后，我系统整理了一下, 整理成了七部 SOP，每一步都停下来给你看。

![Image](<把你的代码历史拍个属于你的短片%20-%20git-story-film%20skill.assets/image-11.jpg>)

## 第 1 步 · 提纲：先定讲什么故事

首先打开 claude code 或者 raven, 把你的代码地址丢进去, 并且使用这个skill, 这里需要注意的是, 如果你使用了 claude code, 务必需要使用 /effort max

「使用 git-story-film skill, 读取 xxxxx , 帮我设计一份影片」

你会看到一份 OUTLINE.md：一句话讲完整部片，用什么形式讲、为什么，主角是谁、字幕用谁的口吻，起承转合四句话，观众看完该记住哪几件事，还有片子依据的真实数字。

Raven 的第一版是夜空里一条累计提交的折线，数据都对，但没有故事。我要的是“一只黑色渡鸦的视角”，还要 “卡通形象，最好大眼睛”、“从破壳到都是遵循一个从左往右的前进路线”。于是提纲里写下了全片的铁律：一镜到底，只往右走。

![Image](<把你的代码历史拍个属于你的短片%20-%20git-story-film%20skill.assets/image-12.jpg>)

## 第 2 步 · 主角：表情和动作

你会看到一张角色设定表：6 到 12 个表情，走、跳、飞这些动作的关键姿势，每种画风下的样子，还有缩小以后还认不认得出来。

Raven 的设定表里，铅笔画的雏鸟有好奇、亮晶晶、怀疑、晕；上了墨的成鸟有吃惊、得意、专注、张开翅膀。主角在这一步定下来，后面每个镜头都用同一套代码画它。

![Image](<把你的代码历史拍个属于你的短片%20-%20git-story-film%20skill.assets/image-13.jpg>)

## 第 3 步 · 全片提纲：每一拍对上一个真实提交

你会看到约两分钟的完整提纲：分几幕、每幕什么画风、为什么；每一拍的时间、画面、功能和对应的提交；结尾；还有要再核对的说法。

Raven 视频在这一步改得最多。我会补充很多细节上的调整：“得介绍功能点啊，不然别人也不知道 raven 能给别人带来什么。” 于是右上角的日期换成了功能卡，片长从 90 秒改成 2 分钟，后半程用一个具体的委托串起四个内置 Agent：“帮我调研三家竞品，写个脚本抓数据，夜里盯着，最后做成一份 PPT。” 顺手核了事实：Raven 的预设里没有 ChatGPT，有的是 Codex；自进化的分数只标成“示意”。

![Image](<把你的代码历史拍个属于你的短片%20-%20git-story-film%20skill.assets/image-14.jpg>)

## 第 4 步 · 分镜：先看前 30 秒

接着预览分镜：前 30 秒每个镜头一张关键帧，关键帧用片子自己的角色和场景代码画出来，旁边写着时间、字幕和对应的提交。这 30 秒定下口吻、节奏和画风，后面照着走。

![Image](<把你的代码历史拍个属于你的短片%20-%20git-story-film%20skill.assets/image-15.jpg>)

## 第 5 步 · 详细编写：整部片动起来

写完剩下的镜头，把整部片做成动画，配乐也在这一步用代码合成。我很惊讶的是 opus 5.5 在音效和简单的配乐上做的这么好, 并且遇到新表情、新动作，先补进设定表给你看。做完先自己检查：把全片抽成一张帧网格，一眼看完节奏和构图。

这里我还用到了“两个时钟”策略, 默认 claude 会用 24帧来写, 但实际上在画面移动速度稍快的场景下, 很多细节会看不清楚, 于是我改了引擎的代码, 镜头、背景和文字按 60 帧走，角色的姿势照样一秒换 12 到 24 张，顺滑和手绘感分开处理。

![Image](<把你的代码历史拍个属于你的短片%20-%20git-story-film%20skill.assets/image-16.jpg>)

## 第 6 步 · Studio：在浏览器里看完整部片

在正式渲染钱, 打开片子开始预览。上面是画面；下面一条拖动条，每一幕一段色带，每个镜头一个编号格子，拖到哪停到哪，带着配乐从任意位置播放；再往下是每个镜头的分镜图，从当前代码实时画出来。这一步不走 4k 60fps 渲染。

如果你觉得 AI 这块需要注入自己的 taste, 需要针对细节作调整, 那么你一定很爱这个 skill 给你保留的灵活的空间. 

下图是 LobeHub 那部片的 Studio。

![Image](<把你的代码历史拍个属于你的短片%20-%20git-story-film%20skill.assets/image-17.jpg>)

## 第 7 步 · 成片：4K60

当你确。可以渲染之后, 直接告诉 Claude Code / Raven 可以渲染了。Agent 会打开浏览器一边画，一边把帧直接送进 ffmpeg，4 路并行，不在硬盘上堆上百 GB 的图。交付时导演会报告时长、分辨率和文件大小，完整解码一遍，再抽几帧亲眼看。片尾卡默认也写成第 0 帧，播放器和信息流会拿它当封面，这个细节也是 Raven 的用户提出来的。

## 背后的设计思想

七个步骤只是表面。真正让片子“像这个仓库”的，是下面八条规矩。

**1. 是导演，不是生成器。** Claude 自己拿主意的有三件事：用哪些数据、讲什么故事、用什么画风。你只需要看、点头、提意见。每一步结束，你手里都有一样看得见的东西。

**2. 纸上改最便宜，4K 上改最贵。** 改一句提纲几秒钟，重渲一部 4K 要几分钟。所以 Studio 点头之前不出 MP4。就算你说“一直做完”，导演也会停在 Studio 等你看过再渲染。

**3. 一一对应：一次提交就是一格。** 画面上的东西和 git 里的事一一对应：一次提交一颗珠子，一个版本一块铭牌，一次回滚一次挫折。每天挂几颗，就是那天真实的提交数。一个符号只代表一种数据：LobeHub 里星星就是星标，提交就只能画成火星。这样拍出来的才是这个仓库的故事，而不是换了名字的模板。

![Image](<把你的代码历史拍个属于你的短片%20-%20git-story-film%20skill.assets/image-18.jpg>)

Raven 最忙的一天：137 次提交，画面上就落下 137 颗珠子。

**4. 一部片只守一种镜头语法。** 旅程只往右走，从不切镜；生长待在原地，镜头往后退；Cherry Studio 的树只往上长，镜头也只往上。守住这一条，片子才是一个连贯的故事，而不是一串幻灯片。约束还会逼出好点子：镜头下不去，地下的重写就靠一面“地下放大镜”和一条往上追的新根线来讲，追上树梢那一刻就是全片最高点。

**5. 主角从官方图里长出来，最后变回 logo。** CC Switch 的小火花先量了官方图标，发现是 13 道光而不是 10 道，剧本跟着改。Cherry Studio 的小樱桃，叶和梗张成 logo 上那个 ✓。招牌表情要省着用：Lobe 吐舌头，只留给它变回 logo 的那一刻。

**6. 只说真话。** 画面上的哈希、日期、次数都来自仓库，估算的数字标明“估算”。LobeHub 的星标日期是按公开网站估的，脚本和原始数据都留在片子文件夹里。产品没有的能力不写：LobeHub 没有 Slack 集成，片子里就不出现 Slack。

**7. 两个时钟。** 位置每一帧都重新算，60 帧一帧不落；角色的姿势每秒只换 12 到 24 张，像手绘动画那样一张画停一两拍。动作顺，又有手绘味，60 帧下也不抖。

**8. 你的每一句反馈，都会变成下一部的规则。** 一次性的要求会写进长期记忆：片尾三行署名、每个日期都带年份、按项目真实的成长来讲、主角从官方图重画、招牌表情只在 logo 时刻用、星标日期按公开网站估。下一部片子的第一版就照着做了。

# 翻车和惊喜

比如我在制作视频的过程中遇到的 opus 5.5 把舌头绘制到嘴巴外面。

![Image](<把你的代码历史拍个属于你的短片%20-%20git-story-film%20skill.assets/image-19.jpg>)

吐舌头是官方图标上的招牌表情。第一版把它当成了默认嘴型，设定表、分镜、成片里到处都在吐舌头。改完之后，Lobe 平时闭嘴微笑，只在片尾变回官方图标的那一刻吐一次。招牌要省着用，用一次才有分量。

有个插曲：本来我想给 cindy 也做一个版本的，结果 opus 5.5 画的我都不敢发出来了。担心被 cindy 的开发拉黑哈哈哈哈。

![Image](<把你的代码历史拍个属于你的短片%20-%20git-story-film%20skill.assets/image-20.jpg>)

比如 cherry studio 上来就用了猫的形象，我做了一定调整 “我觉得主角应该是一只卡通版本的樱桃”

![Image](<把你的代码历史拍个属于你的短片%20-%20git-story-film%20skill.assets/image-21.jpg>)

提纲第一版的主角是一只园丁猫，致敬作者的网名“亢奋猫”。我改成樱桃， 十几分钟后，小樱桃的三页设定表就画好了：叶短梗长，张成 logo 上那个 ✓；梗能勾住树枝，所以它能跟着树一路往上。片尾三颗樱桃挂在 ✓ 下面，正好是官方图标。角色之争放在第 2 步用画来定，是最便宜的时候。

还有一些细枝末节的修改， 比如跨年的项目最好还是得加上年份，得益于提前做了预览 studio， 改完立马预览到了。

![Image](<把你的代码历史拍个属于你的短片%20-%20git-story-film%20skill.assets/image-22.jpg>)

甚至还有一些修改，是我临时想出来的，比如做 CC Switch：“这块是不是可以考虑有一个 2d 转 3d 的转场”，没想到整个转场做的意外的丝滑，要知道以前我做视频的时候真的就很想做这种效果，但是成本和时间都来不及。 

![Image](<把你的代码历史拍个属于你的短片%20-%20git-story-film%20skill.assets/image-23.jpg>)

我把转场挂在一个真实的日子上：v3.9.0 正式发布那天的天亮。字幕是“天一亮，我从纸上走了出来”，形式的变化本身成了剧情。这段 3D 是用 2D 引擎模拟透视画出来的，没有用 WebGL。

同一轮反馈里，用户还要“利好用户的视角”的文案。片子的签名从“拨一下，就换好”改成“你专心写代码，线我来接”；故障转移那张卡从“熔断 + 健康检查”改成“一家挂了，自动换下一家”。功能卡写你能得到什么，不写功能名。

# 怎么开始

三步就能开拍：

1. 安装：把下面的链接复制过去，粘贴到你的 claude code 中 帮我安装 [github.com/EverMind-AI/Raven/tree/main/skills/git-story-film](https://github.com/EverMind-AI/Raven/tree/main/skills/git-story-film) 
2. 开口：/git-story-film 帮我给做一个视频，先构思一下
3. 跟着七步走：每一步看一样东西，点头或者提意见。你不用会画画，也不用会剪辑。

需要的环境：Node 22 以上、Google Chrome、ffmpeg、Python 3.8 以上，如果你遇到任何环境问题都不是大问题，让 claude code 帮你解决。

要多久：最近三部片子，从给出链接到拿到 4K 成片都在三小时以内。CC Switch 约 2 小时，只渲染了一次；Cherry Studio 约 2 小时 45 分，多渲染了两次；LobeHub 不到 3 小时。

致谢：绘图和动画引擎改编自 Alexey Fateev 的 [hand-drawn-canvas-animation](https://github.com/alesha-pro/tools/tree/main/skills/hand-drawn-canvas-animation)（MIT 许可）。

**第一次提交那天，谁也不知道它会长成什么样。现在，把你的代码历史讲给第一次听说它的人。**
