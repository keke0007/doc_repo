# Jerry Fang (@Jerry_fsy)

我在用Langfuse做Trace时，发现Langfuse中，对于每一段信息允许的长度是有限制的，超过这个长度就会被截断。而这个截断有的时候会导致有效信息被剔除，影响我们定位问题。  
  
为了解决这个问题，我调研发现了一个通用方案，即使用“分层可观测性的设计”，具体结构从上到下为：  
  
1.Trace  
主要放：运行结构，包括父子关系、调用顺序、耗时、状态、关键属性（模型名、工具名、Token数、参数摘要、结果摘要、错误类型）、关键事件  
目的：可以告诉我们Agent一步步是如何执行的  
  
2.日志  
主要放：存高频、离散的文本记录（详细错误堆栈、状态流转、调试信息，以及指向大对象的 URI/引用）  
目的：可以告诉我们某一次Span在具体时刻发生了什么  
  
3.对象存储  
主要放：专门接住“重资产”（超长 Prompt、完整工具返回的大 JSON、长上下文、多模态文件）  
目的：避免上层的Trace和日志被较大的对象撑爆  
  
设计成三层是因为Agent 可观测性里的三类数据在抽象层级、体量、查询模式、保留周期和成本上差异太大。三层设计的本质是：让每一层只做自己擅长的事，再用 trace_id / span_id 把它们串起来，兼顾“可解释、可排障、成本可控”。
