# 山景城小路 (@Zen_with_AI)

读了 Prism-Shadow 的《Understanding RSI》，推荐给想系统了解"自进化"的朋友。RSI 这个词最近到处都是，但每个人嘴里的 RSI 常常不是同一件事。这篇文章给了一张坐标图：改什么，谁来改、什么时候改、凭什么留下，把五花八门的方法放进同一个框架里比较。  
  
先看骨架：  
  
A(t) -> 候选 -> 反馈 -> 留存 -> A(t+1)  
（当前系统 -> 生成改动 -> 评估改动 -> 决定留不留 -> 下一版系统）  
  
系统改了自己，留下了改动，再用改过的版本继续干活、继续改自己，这才算 RSI。各种方法的差别，就是这条环上每一步的选择不同。  
  
改什么。参数、上下文、记忆、技能、harness 代码，都可以是被改的对象。SEAL 让模型自己生成训练材料来微调权重，ReasoningBank 从成功和失败的轨迹里提炼策略存进记忆，DGM 直接改写编码智能体的代码。  
  
版本怎么连。链、树、图。A-MEM 是一条链，每次在当前记忆上修订。DGM 把历史版本存成档案，可以从任意旧版本分叉，是一棵树。Mendel Gödel Machine 会拿另一条谱系的执行轨迹来对照，新版本能继承多条谱系的信息，是图。  
  
谁来改。自己、教师、联合。SEAL 是自己改自己。GEPA 由一个反思优化器去改被评估系统的指令，是教师。DGM 先诊断，再由选中的智能体动手改，是联合。  
什么时候改。离线、在线、先离线后在线。DGM 在评估前搜索代码改动，A-MEM 和 ReasoningBank 边做任务边更新，Agent Workflow Memory 先离线归纳工作流，测试时继续补。触发更新的单位也有区别：一步、一个事件、一整条轨迹，或者一批轨迹。  
  
凭什么留下。反馈来自训练集、基准、环境、可执行验证器、LLM 或人，形式是分数或文字。最后的验收标准从严到松有好几档，最松的是不验证：ACE 和 A-MEM 就是把整理好的内容直接并进去。  
  
小路最喜欢的是，把这几个维度摆在一起，能看出方法设计里的矛盾。同一个团队的配套论文（arXiv 2610.14625）有个例子：智能体搜论文总是失败，它先改了自己的日志代码，这一轮分数没有变化，但新日志让它在下一轮发现日期格式不被接受，随后修好了。可如果验收标准是"总分必须超过当前版本"（Ecdysis 就是这样），第一步的日志改动当场就会被拒掉。  
  
换句话说，"改代码"这个选择，和"按即时分数验收"这个选择，互相拧着。论文给出的方向是，让验收标准也看一个改动对后续改进有没有帮助。  
  
简单总结一下就是：看一个 RSI 方法，别先问它强不强，先问五件事，改什么、版本怎么连、谁来改、什么时候改、凭什么留。五个答案凑在一起，就是这个方法在设计空间里的位置，也是它可能出问题的地方。
