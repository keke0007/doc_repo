# 确实，Memory 应该成为模型的原生能力。

*By 小盖 (@xiaogaifun)*

![Banner](<确实，Memory%20应该成为模型的原生能力。.assets/image-01.jpg>)

周末看了 Anthropic 关于 Agent Memory 的博客，写得相当精彩。里面提到了一个很有启发的观点：

**Memory can be a prediction about what the future will need.**

什么意思呢？

他们觉得，目前各种 Agent Memory 的核心难题，其实是判断到底什么信息值得放到长期记忆中。

而这个判断，应该更多地交给模型自己来做，而不是完全依赖外部的 Harness。模型需要根据当前的上下文，预测未来哪些信息可能用户还会再用到。

通过做实验，Anthropic 的研究员发现，模型的智能水准越强，在这方面的判断通常也会越准确。

所以，至少在 Anthropic 目前的记忆体系里，虽然记忆本身仍然保存在外部文件中，但决定哪些信息应该成为记忆，以及如何整理和维护这些记忆，已经越来越依赖模型自身的能力了。

这让我想起前段时间看过的另外一个项目，叫 MemT。它的思路和 Anthropic 有相似之处，但更激进，直接把记忆能力集成到基础模型的计算过程中。

其实关于 Agent Memory，我和不少行业内的朋友聊过。大家现在整体的思路，都是从人脑的工作方式中寻找灵感。

Hinton 前两年讲过一个观点。他认为，**人类甚至可以被看作一种大语言模型。**

这话我今天不展开啊，但确实觉得，人类这个生物太精妙了。比如具身智能领域，大家在探索机器人的精细控制时，也会参考人脑和小脑的机制。

记忆也是一样。

人脑经过漫长的演化，形成了复杂又简洁的记忆机制。

大家可以想下，我们在日常生活中，其实一直在不断形成新的记忆，同时，也在不断遗忘。海马体会帮助我们快速记录当下的经历。但人脑不会把每天发生的所有事情，都原封不动地永久保存下来。

在睡眠和休息的时候，大脑还会重新处理近期的经历，通过记忆重放等机制，把部分信息逐渐整合进更稳定的长期记忆。

我感觉 MemT 这个项目，在记忆的形成和使用上，和人脑的机制已经非常类似。

它直接把记忆能力集成到了模型里，在原来的 Transformer 中增加了一个专门处理记忆的模块。每轮会话结束后，这个模块都会根据刚刚的交流内容，通过写入、擦除和遗忘等操作，更新内部的记忆状态。

等到下一次交互时，模型可以读取过去积累的记忆，然后直接参与当前的计算。因为 Memory 是模型原生的模块，所以它不需要像其他 Agent Memory 那样，从外部检索相关记忆，再把这些内容 load 到 Context 当中。

![Image](<确实，Memory%20应该成为模型的原生能力。.assets/image-02.jpg>)

这些不是构想，已经有实际的落地。

刚我顺手搜了一下，发现他们和英伟达合作，以英伟达自研的 550B 参数模型 Nemotron 3 Ultra 为基础，在原有架构中加入 MemT-1.0 的原生记忆模块，推出了 MemT-1.0-Pro。

效果还不错。在相关的 Benchmark 中，MemT-1.0-Pro 排名第一。而且，它对模型整体智能的发挥基本没有什么影响。

论文我放到文末了。大家有时间可以读读。绝对会大开眼界。反正我个人是觉得 MemT 的思路是未来的大趋势。

接下来，我再说一下自己对这套技术的理解。

记忆参数化这个方向，其实也不止 MemT 一家在做。我之所以提到它，是因为人家已经是这个品类的头部了。

**很多人一听到记忆参数化，可能会有一个疑问：是不是模型每次和用户聊完天，更新记忆的时候，都需要重新修改基础模型的权重？**

不需要。

我给大家解释下就明白了。MemT 把记忆分成了两个部分。

一部分叫 Hyper Memory。

简单来说，它负责让模型学会怎么处理记忆，包括怎么写入、擦除、遗忘，以及怎么读取。

这部分能力是通过训练获得的，相关参数在训练完成之后，正常使用时就保持固定，不会因为和用户聊了一次天就重新修改。

这其实就有点像我们刚才讲的人脑记忆机制。

**我们不会把每天经历的所有事情都记下来，有些事情会逐渐遗忘，有些记忆则会随着新的经历不断更新。**

比如你原来觉得小盖这哥们长得很帅，后来见了一面，发现好像也就那么回事，那你对他的印象就需要更新了嘛。

另外一部分叫 Local Memory。

它负责保存模型在和用户交流过程中积累的具体记忆。

举个例子。

假设我今天和 AI 说，我喜欢喝美式咖啡，不喜欢拿铁。当这轮交流结束后，MemT 会通过 Hyper Memory 中学到的读写机制，把相关信息写进 Local Memory。

明天再和 AI 交流的时候，它就可以直接读取 Local Memory 中保存的信息，知道我喜欢喝什么咖啡。

**也就是说，Local Memory 保存的是随着交互不断积累和更新的信息。而且，不同用户有各自独立的 Local Memory，彼此之间不会互相干扰。大家共享同一个基础模型，但每个人积累的记忆完全隔离。**

![Image](<确实，Memory%20应该成为模型的原生能力。.assets/image-03.jpg>)

那到底他们是怎么判断哪些记忆应该遗忘，以及哪些信息应该进入长期记忆呢？

其实刚才也提到了，MemT 有一个叫 Hyper Memory 的模块，专门负责学习怎么处理记忆。因为它本身就在模型内部，所以可以直接通过训练，让模型逐渐学会哪些信息值得保留，哪些可以遗忘，以及怎么更新和读取记忆。

我翻了下论文，发现他们用的是我们非常熟悉的蒸馏方式。**确实，这种方式代价是最小的，可以让模型快速掌握原生的记忆能力，不需要重新训练整个大模型。**

用大白话解释一下他们的蒸馏方法。

假设我们给模型提供了一段很长的历史对话，里面有很多信息，比如用户的职业、兴趣、饮食偏好，还有各种无关紧要的闲聊。

训练的时候，会有两个模型。

一个是老师模型，可以看到完整的历史对话。另外一个是学生模型，也就是 MemT，它只能看到当前的输入，以及过去积累在 Local Memory 里的信息。

然后让它们回答同样一个问题。

假设问题是，这个用户平时喜欢喝什么咖啡？老师模型可以看到完整的历史记录，所以知道用户之前说过自己喜欢美式咖啡。

但学生模型如果之前没有把这条信息有效地保存下来，或者虽然保存了，却没有正确读取出来，就可能回答错误。

这时候怎么办呢？

训练系统会比较老师模型和学生模型的输出，根据两者的差距，反过来调整 MemT 记忆模块的参数。

注意，这里老师模型并不会直接告诉学生，你刚才忘了保存用户喜欢美式咖啡这件事。

它实际上是通过输出结果提供训练信号，让学生模型在大量这样的训练中，学会怎么保留重要信息、更新过去的记忆，以及在需要的时候准确读取。

![Image](<确实，Memory%20应该成为模型的原生能力。.assets/image-04.jpg>)

**我想了一下，从年初到现在，原生记忆这条技术路线的进展还是挺快的。**

MemT 论文最后做了一些测试，发现在 Coding Agent 的场景中，原生记忆已经能够取得和传统文本记忆相当的效果。

其实，我觉得，只要这套技术足够成熟，原生记忆相比现在的外挂记忆机制，肯定会有非常大的优势。这是毋庸置疑的。

因为它在实现上，更接近人脑形成、更新和使用记忆的方式。而且，不需要反复把记忆加载到上下文当中。

毕竟它的记忆是以内部状态的形式保存下来的，能够直接参与 Transformer 的计算。我觉得在效率和灵活性上，都有很大的想象空间。同时，模型还可以通过训练，不断提升自己保存、更新和读取记忆的能力。

当然，这套技术现在肯定还不够成熟。但我比较笃信这是下一代 Agent Memory 的主流技术路线。
