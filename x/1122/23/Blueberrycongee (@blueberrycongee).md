# Blueberrycongee (@blueberrycongee)

其实不只是程序员和非程序员之间对 Agent / LLM 的认知差距很大，哪怕同样都是程序员，彼此之间的认知差距现在也已经拉得非常大了。  
  
我一直很鼓励大家：一定要用当下最好的模型、开到最高的档位，而且尽可能把额度用完。倒不是为了硬烧 token，而是只有真的把最强能力拉满去干重活、干复杂任务，你才能建立起对“现在前沿到底走到哪了”的准确体感。如果平时只用便宜模型、默认档位，，你脑子里的能力基线很容易就卡在了上一代。  
  
举个最直观的例子。现在最前沿的地方，已经变成“PR 工厂”了。  
  
一旦你把工程基建搭好，比如完整的端到端测试、自动化检查，甚至连不同平台、不同机器上的真实运行和视觉验收都打通（自动构建、拉起真实应用、跑交互、截图检查 UI 有没有错位或回归，发现问题直接自己修），整个仓库在很大程度上其实就已经完全成了“许愿机”。你负责把想法、约束和边界条件说清楚，剩下的排查、实现、跑端到端测试、多机器视觉验收、修 bug、提 PR，Agent 可以一路闭环跑完。  
  
但把视线拉回来，现在还有很多程序员停留在“不习惯 Agent / ADE，还是得切回 VS Code 里逐行 review diff”的阶段。  
  
这背后其实藏着一个更底层的变化：现在“会什么”真的已经不重要了，重要的是“我要什么”，而且是真正清楚自己要什么。这是一个非常关键的能力。  
  
而且很重要的一点是：能知道自己想要什么的人，并不一定是会做的人。很多人一听这话就会反驳，说如果你自己都不会做，怎么知道自己想要什么？怎么判断做得好不好？  
  
换个赛道举个例子其实非常直观：很多美食家，本身并不一定是厨子。他们未必会颠勺，未必懂后厨每一步火候和刀工的做法，但菜一端上来，食材新不新鲜、调味失没失衡、火候到不到位，他们一口就能吃出来，也很清楚一道真正好的菜应该是什么样。  
  
现在很多人都在聊 taste，其实美食家和厨子的例子就特别好，这就是 taste 的本质含义。能把东西做出来，和能分辨好坏、清楚自己想要什么，本来就是两种不同的能力。“会做”是厨子的手艺，而 taste 是你见过足够多的好东西之后，长出来的判断力和标准：知道什么值得做、什么叫好、差的那一点到底差在哪。  
  
过去写软件，因为没有别的办法，你必须先当好厨子，才能决定端上桌的菜长什么样，所以程序员天然习惯抓住实现不放，习惯在 VS Code 里一行行看 diff。但今天 Agent 加上测试和验收基建，已经在把“做出来”这件事变成许愿机了。当执行越来越便宜，真正决定上限的，反而是你能不能像一个高水平的美食家一样，清楚地说出自己要什么，并在结果摆在面前时，准确判断它到底行不行。  
  
所以才一直说，别省那点额度和最高档位。只有先用最强的模型把当下的上限摸透，你才会切身感受到：比起继续证明自己“还会做什么”，尽早想明白自己“要什么”、把 taste 通过失败的尝试逼出来，才是最关键的事。
