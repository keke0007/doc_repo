# Agent 高频面试题合集：题单和 28 篇逐题详解

*By 码良 (@cxjwin)*

![Banner](<Agent%20高频面试题合集：题单和%2028%20篇逐题详解.assets/image-01.jpg>)

RAG 链路怎么讲？多 Agent 为什么要拆？上下文太长了怎么办？

我把牛客上两个月的 Agent 岗一手面经整理成了一份题单，再把高频题一题一篇展开写。这篇是系列目录。题单里的 29 道题已经全部写完：第 25 题并进了第 02 篇，其余一题一篇，一共 28 篇详解。

题单统计的是 2026 年 8 月 18 日到 10 月 18 日发的一手面经，收录了 171 位作者、332 场面试，涉及近 80 家公司（发布后复核过一次，剔掉了 11 篇不是面经的帖子）。排名按独立作者数算，同一个人发多篇只算一次。这是一段时间内的样本，不是所有公司的面试大纲。

## 先看总题单

29 道题按作者数排序，每题附常见问法、面经出处和详解链接。算法岗方向、低频题、面试结构和这两个月的变化也另有整理。想先看看哪些题问得多，从这里开始。

## 按主题读

题号大致按考频排。第一次系统看，可以按主题走：

- 先搞清 Agent 是什么：21 怎么理解 Agent → 09 Harness 和 Agent Loop → 27 Function Calling 原理 → 07 Skill、MCP、Function Calling 的边界 → 08 Skill 怎么设计 → 18 MCP 原理和传输协议
- 上下文、记忆和成本：05 上下文太长 → 06 记忆 → 12 Token 成本和缓存 → 26 System Prompt
- 架构怎么选：23 Workflow 和 Agent → 14 ReAct 和 Plan-and-Execute → 03 多 Agent → 17 意图识别和路由 → 10 LangGraph 和 LangChain
- 让输出靠得住：22 结构化输出 → 24 工具很多怎么选对 → 19 幻觉怎么减少
- 上线以后：11 工具调用失败 → 28 死循环怎么防 → 16 流式、延迟、并发 → 20 Agent 安全
- RAG：01 RAG 链路 → 15 RAG 效果排查
- 评测和迭代：04 评测 → 13 bad case 定位和回流
- 综合：02 AI Coding 工具 → 29 从零设计一个 Agent。29 题第五节把设计题讲完以后的追问对到了前面各题，可以当复习索引。

## 逐题详解

从离线解析、切分、向量化、建索引，到在线改写、召回、融合、重排和生成，逐环讲原理、取舍和面试官怎么追问。最后还有评测、更新、权限和两分钟答法。

面试官想听的不是工具清单，而是你怎么用、懂多少原理、怎么检查生成的代码。文章也讲 AI Coding 上机题怎么考、怎么追问 AI。题单第 25 题「怎么保证 AI 生成代码的质量」并在这一篇里。

单 Agent 调多个 Skill 也能并行，为什么还要多 Agent？先讲拆分的收益和成本，再讲任务怎么分、信息怎么传、结论冲突谁来处理，以及超时、权限、预算和评测。

评测集从哪来，谁来打分，指标怎么定，怎么证明新版本真的变好了。也讲多次运行、线上监控和面试里那些经不起追问的数字。

每一轮该放什么，快满了先清什么、怎么压缩，压完怎么验证有没有丢掉约束，以及哪些东西该移到窗口外面。

模型本身没有跨调用的记忆。记忆分几层，什么该记、什么时候取，用户偏好变了怎么更新，旧的该不该删，以及多 Agent、多用户怎么隔离。

Function Calling、MCP、Skill 各解决什么问题，MCP 和直接调用 API、CLI 怎么选，Skill 和系统提示词、脚本有什么区别，以及什么时候需要 Agent 和 Workflow。

围绕 Skill 的组成和按需加载，讲怎么把一类任务的做法整理成 Agent 可以使用的说明。

先分清三个词各管什么，再讲模型怎么决策、程序怎么执行、循环怎么停，Harness 要补哪些能力，以及 Runtime 的状态、隔离和崩溃恢复。

先讲清两者现在是什么关系，「LangChain 线性、LangGraph 能循环」的说法已经过时。再讲 LangGraph 的状态、节点、检查点和人工介入，恢复时节点会重跑的坑，为什么用框架、为什么不用，以及项目里的图怎么讲。

失败先分类，再看能不能重试、有没有副作用。参数出错怎么减少、怎么回给模型，超时怎么定，重试为什么只在一层做，超时之后怎么避免重复执行，以及并行、拦截和子 Agent 的容错。

先算账：一次请求按四种价钱算，命中率差几个点，钱差一倍。再讲什么会打断缓存、不同 Coding Agent 的命中率为什么不同，以及少送 Token、模型分层、语义缓存、预算和省下来的数字怎么证明。

用户说 Agent「很蠢」，先翻译成能查的问题。再讲 Trace 记什么、谁来记，线上怎么发现问题，怎么找第一处走偏、怎么确定是不是 Prompt 的问题，以及修和回流回到哪一层、哪些不该回流、修完怎么防退化。

两者的差别在下一步什么时候定。先讲各自的缺点，再讲怎么选、怎么组合，计划错了怎么办，长任务的计划放哪、怎么不跑偏，以及模型变强以后哪些计划还要留。

先分清问题出在知识库、召回、重排还是生成，再看分段指标、知识冲突和拒答。文章里还有一张排查表，可以按现象找到先查什么。

流式、延迟、并发先分开，各看各的指标。再顺着一次流式回答讲：后端推什么，SSE 和 WebSocket 怎么选，断了是重推还是续推，只收到一半 JSON 时工具要不要执行。最后讲延迟怎么拆、怎么降，长耗时步骤怎么异步，以及工具能不能并行、怎么限流、高并发怎么扛。

识别回答用户要什么，路由回答交给谁。先讲类别为什么按处理方式分、不按话题分，规则、小模型、大模型怎么选、怎么级联，口语、歧义、多意图和越界怎么处理；再讲要不要单独做一层意图识别，Skill 怎么被选中，怎么证明分得对，分错了怎么办，以及多模型路由和切换。

用一次步行路线查询，讲 Host、Client、Server 各管什么，模型怎么知道工具要填哪些参数，同一条 JSON-RPC 消息怎么经 stdio 或 Streamable HTTP 送到 Server，以及 Streamable HTTP 为什么也可以只回一个 JSON。再对照几版协议在握手、会话和断线上的差别，讲收不到进度时先查哪一段。

用一个查数 Agent 讲幻觉分哪几种、模型为什么不说「不知道」。工程上分三处下手：给依据，把能确定的步骤交给代码，在工具层和输出前校验。最后讲怎么发现幻觉，怎么用评测说明它确实少了。

用一个售后邮件助手，先分清越狱、提示词注入和越权，再讲注入为什么防不干净，拦不住时怎么限制它能做成什么，权限为什么要在工具和服务端判，子 Agent 怎么隔离，以及沙箱有几种强度。

拿一次线上 500 的排查，对比一次大模型调用和 Agent 各做了什么。Agent 的定义落在三个要素上：工具、循环、下一步由模型定。再讲它和 Chatbot、RAG 问答怎么分，最小的 Agent 要哪些模块，Agent 开发和传统前后端开发差在哪，以及什么时候不需要 Agent。

从一条工单里抽四个字段讲起：JSON 会坏成哪几种，提示词、JSON 模式和约束解码各保证什么，开了严格模式以后结果还要查什么，校验没过怎么带着错误重试。也讲流式时怎么解析，以及弱模型和自部署模型怎么办。

同一张退款申请，分别写成 Workflow 和 Agent，区别落在下一步由谁定。再讲怎么按步骤能不能列出、出错代价、延迟成本和审计要求来选，两样怎么拼，「受控」落在哪几处，以及 Workflow 改成 Agent 加 Skill 以后，什么时候再写回代码。

一个接了 120 个工具的企业助手，先是装不下，再是分不清。按代价从低到高讲：删和合并，改命名和描述，延迟加载和工具搜索，按领域分层和子 Agent。再讲 Skill 很多时怎么管，以及怎么用评测集找出最常混淆的两个工具。

拿一版退款客服的系统提示词，一节改一处：该放哪几部分，约束怎么写、哪些该交给程序，示例和思维链各管什么，怎么调、怎么证明改对了、版本怎么管，换了模型以后旧提示词怎么办。最后分清 Prompt Engineering、Context Engineering 和 Harness 各管什么。

用订单助手查一副耳机的物流，把前后几次请求和响应摆出来：工具定义怎么进了模型的输入，模型凭什么先调找订单的工具，它输出的到底是什么，谁来执行、结果怎么送回去，一次调几个、顺序谁定。

从一个修测试修不好的 Coding Agent 讲起：转圈有哪几种，终止条件和上限怎么设，没到上限时怎么发现它在重复，发现以后怎么提醒、封路、收尾，怎么从根上少转圈，以及几个 Agent 之间互相转圈怎么办。

面试官现场给一个需求，让你从零设计，按什么顺序答。用企业知识库问答走一遍：先问清什么，哪一段交给模型，数据、上下文、失败、权限、评测和成本各定什么；再换成 Coding Agent、智能客服和数据分析 Agent，看哪几步不一样。最后是设计讲完以后的追问，各对应系列里的哪一题。

第 25 题「怎么保证 AI 生成代码的质量」并进了第 02 篇，没有单独成篇。

如果你正在准备面试，可以先按题目想一遍自己的项目：实际怎么做，为什么这么选，出过什么问题，有没有数据。原理能讲清楚之后，这些细节通常才是面试官继续追问的地方。
