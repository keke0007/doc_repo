# Agent 高频题 29. 从零设计一个 Agent：场景题按什么顺序答

*By 码良 (@cxjwin)*

![Banner](<Agent%20高频题%2029.%20从零设计一个%20Agent：场景题按什么顺序答.assets/image-01.jpg>)

高斯信息技术一场 AI 开发工程师一面问，让你设计一个企业知识库，这条链路你怎么设计？下一问接着问重排有哪些策略，了解 RRF 吗，BM25 检索习惯用什么工具做。字节一场 AI 应用工程师一面出的是数据分析 Agent：老板经常问「为什么今天这个数据异常」，你会怎么设计？后面连追六问：Memory 怎么设计，上下文怎么管理，需要几个 Agent，业务表结构变了怎么处理，具体怎么落地，难点是什么。

同一个内部知识问答助手，员工问出差住酒店一晚能报多少，检索一次、生成一次就答完了；员工说 VPN 连不上，下一步查什么要看上一步查到了什么。这道题换一个场景就是一道新题，能提前准备的是回答的顺序：先问清需求，再判断哪一段要模型自己拿主意，然后一环一环做决定，最后讲怎么评、第一版上什么。

这是 Agent 高频面试题单第 29 题。原题单记了 11 位作者、11 场面试。这次重读了库里留有链接、还能看到正文的 515 篇面经，其中 29 位作者在 33 场面试里遇到了这道题。下表按作者数排序，一场面试可以问到几个方向。

![Image](<Agent%20高频题%2029.%20从零设计一个%20Agent：场景题按什么顺序答.assets/image-02.jpg>)

第二、四行是设计讲完以后接着追的问题，其余四行是题目让设计什么。业务 Agent 那一行的 18 场分在十来种业务上。按具体题目数，知识库和文档问答最多，有 6 场，Coding Agent 有 5 场，智能客服有 4 场。下面拿知识库问答当主例。

## 一、先别急着画架构，有几件事要问清

样本里的题目，给的条件有多有少。某小厂一场 AI Agent 技术面出的是金融领域的垂类 RAG，题目写明压缩包有 600GB 到 1TB，全是 PDF，电子版和扫描版都有。字节跳动一场后端一面的题目是从零设计云产品智能客服，后面点了四块：知识、资源、排障和转人工。高斯那场只有一句「设计一个企业知识库」。

题目给了的条件，方案里要逐条用上。几百 GB 的 PDF 里混着扫描版，解析和建库的成本就得先讲。题目没给的，开口问；面试官让你自己定，就把假设说出来再往下讲。要问的是这几件：

![Image](<Agent%20高频题%2029.%20从零设计一个%20Agent：场景题按什么顺序答.assets/image-03.jpg>)

药明康德一场 AI 数据方向二面的财务知识库，题目里就有制度文档和 Excel 报表两类文件，还问新旧版本的制度冲突导致答错怎么规避。OPPO 一场 IT 开发一面给的是一篇带图的 Word 文档，要求回答里同时有文字和图片。格式、版本和回答的形态，题目没给时都在要问的范围里。

下面假设面试官这样回答：公司三千人，全员在办公软件里用。资料是制度文档、IT 手册和历史工单，一万份上下，以 Word 和 PDF 为主，有少量扫描件，薪酬类文档只有 HR 能看。除了问制度，员工还想查年假余额、报 VPN 故障、申请系统权限。

## 二、要不要 Agent，哪一段要

Anthropic 2024 年 12 月的《Building effective agents》把这类系统统称 agentic 系统，再分成两种。Workflow 是模型和工具按预先写好的代码路径编排，Agent 是模型自己动态决定流程和工具怎么用。文章建议先找尽可能简单的方案，只在需要时才增加复杂度，这可能意味着根本不做 agentic 系统。它还说，对很多应用，把带检索和上下文示例的单次模型调用优化好，通常就够了。

把假设里的四种请求分开看：

![Image](<Agent%20高频题%2029.%20从零设计一个%20Agent：场景题按什么顺序答.assets/image-04.jpg>)

![Image](<Agent%20高频题%2029.%20从零设计一个%20Agent：场景题按什么顺序答.assets/image-05.jpg>)

四种里只有排障要循环。Anthropic 那篇文章说，Agent 可以用在步数难以预测、没法把路径写死的开放问题上。VPN 排障符合，查年假不符合。四条路前面还有一步分流，判断这句话该走哪条，做法在第 17 题。Workflow 和 Agent 怎么取舍在第 23 题。

科大讯飞一场 Java 线下一面的场景题是对接各国的海外博主，按报价和实时汇率算 CPM（千次曝光成本）。报价是一段文本，要用 AI 解析，题目说明 AI 接口不保证结果正确，要求讲整套流程和表设计。这套系统里只有解析报价这一步用模型，其余是汇率获取、计算和存储。模型放在哪一步、解析结果怎么校验，方案里要交代。

字节一场全栈二面让候选人把电商从搜索到下单的全流程改成和 Agent 交互完成，接着拿这位候选人实习做的多 Agent 研发平台来对比：两边都是相对固定的流程，为什么那边用多 Agent，这边用单 Agent，划分依据是什么？哪一段固定、哪一段放开、拆不拆多个 Agent，都要说得出依据。多 Agent 值不值得拆在第 3 题。

## 三、把知识库问答走一遍

每一环只讲这一步要定什么，细节在对应的题里。

**数据和工具。** 先定资料怎么进库。扫描件走 OCR，表格单独处理，每一块带上来源、版本和权限，后面的引用、版本过滤和权限过滤都靠这几个字段。取舍在建库成本：某小厂那场追问，TB 级文档全量做 Embedding 开销极大，初始化建库和增量更新怎么优化。可以先入问得多的资料，更新时按内容哈希只重算变了的文档。药明康德那场问的新旧版本冲突，做法是检索时按版本或生效时间过滤，默认只取最新版。解析、切分、召回、融合和重排在第 1 题第三、四节，高斯那场追的重排也在那里。

再定工具。查年假、查账号和设备状态是只读的，提交权限申请是写操作，每个工具先标清这一点。这里只有三四个工具，全部挂上就行，工具多了怎么让模型选对是第 24 题。

**上下文和记忆。** 每一轮放进窗口的有三样：系统提示词，检索到的几块资料，最近几轮对话。资料放多了贵、慢，还会带进干扰，所以重排后只留最相关的几块。员工接着问「那高铁呢」，要先把上一轮的出差报销补进问题，再去检索。跨会话的记忆先不做，部门和职级从 HR 系统查得到。系统提示词怎么写在第 26 题，每轮放什么、快满了怎么清在第 5 题，什么该进长期记忆在第 6 题。

**循环和失败。** 只有排障那条路会循环，要定三件事：最多走几步，什么情况停，停了交给谁。给循环设步数和花费的上限，到了上限就转给 IT 值班的人，并附上已经查过什么。检索那条路也要有出口：重排后的最高分低于阈值，就回答不知道，或者转人工。阈值定高了拒答多，定低了编得多。循环怎么写、怎么停在第 9 题，走一步看一步还是先列计划在第 14 题，工具超时和重试在第 11 题，原地打转怎么识别在第 28 题，幻觉怎么减少在第 19 题。

**权限和确认。** 权限过滤放在检索阶段，薪酬文档只在 HR 的检索范围里，没有权限的内容进不了上下文。工具用提问人的身份去调，年假只查得到自己的。提交权限申请前，把填好的申请单给员工看，点了确认才提交。OpenAI 的《A practical guide to building agents》建议按只读还是写、能否撤回、需要的账号权限和资金影响这类因素，给每个工具评低、中、高三档风险；敏感、不可逆或代价高的动作，在对 Agent 的可靠性有把握之前交给人把关。副作用怎么分级在第 11 题，越权和提示词注入在第 20 题。

**怎么评。** 先定一个主指标，比如答对并且出处正确的比例。再分段看：检索看召回，生成看答案有没有依据，另外单看该拒答的问题拒了多少。评测题从 HR 和 IT 的历史工单里找真实问题，几十条起步，里面要有知识库答不了的。排障和提申请这两条路，看任务最后完成了没有。评测集、打分和指标在第 4 题，RAG 的分段指标在第 1 题第五节，效果差从哪查在第 15 题。

**成本和延迟。** 定每一步用什么模型。OpenAI 那份指南的做法是，原型阶段每一步都用能力最强的模型，建立效果基线，再试着换成小模型，看结果还能不能接受。分流的请求短、类别固定，可以最先试小模型。报销标准这类高频问题可以缓存答案，缓存要跟着文档版本失效，也不能跨权限共用。流式输出能让第一个字早点出来，总时长不变。成本和缓存在第 12 题，延迟怎么拆在第 16 题。

## 四、换一道题，顺序不变，哪几步不一样

Coding Agent 和智能客服是样本里另外两类出得多的题，数据分析 Agent 用字节 AI 应用工程师那场的题。同一个顺序套上去，每一步的答案变成这样：

![Image](<Agent%20高频题%2029.%20从零设计一个%20Agent：场景题按什么顺序答.assets/image-07.jpg>)

![Image](<Agent%20高频题%2029.%20从零设计一个%20Agent：场景题按什么顺序答.assets/image-08.jpg>)

百度有两位秋招候选人，一面、二面各被问了一次从零设计。其中一位一面被问，做一个类似 cc 或者 code 的 Coding Agent 有什么思路（cc 是 Claude Code 的常见简称）；三天后的二面又被问，从零设计一个 Coding Agent 会怎么设计。Coding Agent 这一列的「怎么评」，Anthropic 那篇文章的附录有一段：代码方案可以用自动化测试验证，但测试验证的是功能，方案是否符合更大范围的系统要求，仍然要靠人工审查。网易互娱一场 AI 应用日常实习的二面，让候选人设计一套线上报错自动分析、自动修复并提交 Merge Request 的系统，后面十问顺着这套系统追代码质量、审查和测试，比如 AI 说单元测试全绿，能不能直接上线。AI 写的代码怎么把关在第 2 题第三节。

智能客服这一列，字节跳动后端那场的题目自己点了转人工。OpenAI 那份指南列了两种通常需要人工介入的情况：超过失败阈值，比如多次尝试后仍然没理解用户意图；以及高风险动作。阿里云一场一面指定了框架，问电商客服用 LangGraph 怎么设计工作流、节点和状态，这要用到第 10 题。

数据分析这一列，字节 AI 应用工程师那场追问业务表结构变了、加了新表怎么处理。表结构说明写死在提示词里，库一改就过期，要改成从库的元数据里现取。

网易一场 Agent 开发一面出的是全自动 AI 漫剧创作 Agent，问整体架构、核心节点和关键流程。这类生成题照样先问清：成片给谁看，谁验收，哪些节点要人看过才往下走。那场接着问的三件事也落在同一个顺序上。人物设定和画风怎么前后一致，是哪些设定要固定下来、每一步都带上；怎么设计实验验证效果，是评测；要快速上线 MVP 保留哪些功能，是第一版的范围。

不限场景的问法有 6 场。美团一场 Agent 开发一面问，设计一个 Agent 应用要从哪些方面整体规划。百度一场广告投放大模型研发二面问，没有 Codex、Claude Code 这些工具，手里只有模型 API 和 VS Code，怎么搭起一整套 Agent 应用。没给场景，就自己先定一个具体需求，再按同样的顺序讲。只有模型 API 时，循环、工具执行和上下文管理都要自己写，最小的版本是一个模型、几个工具加一个循环，写法在第 9 题第二节。

## 五、设计讲完，面试官接着往哪追

考频表第二、四行是设计讲完以后的追问：往架构和环节追的有 10 场，往效果、取舍和落地追的有 6 场。这些追问大多对得上系列里的某一题：

![Image](<Agent%20高频题%2029.%20从零设计一个%20Agent：场景题按什么顺序答.assets/image-09.jpg>)

效果、取舍和落地这一类里，有几个追问没有专门的一篇，各说一句。

字节全栈二面问用什么业务指标衡量。要答业务上看得见的数，知识库的例子里是转到 HR 和 IT 人工的工单少了多少，再配上抽检的答错率和单次成本做护栏。

药明康德那场问，财务知识库做到高精度要多长时间，要哪些硬件和技术条件。先问清「高精度」是多少、怎么量，再按阶段答：一小批文档加几十条评测题跑通要多久，全量入库看文档量和解析难度。硬件看模型是调 API 还是自己部署。

九方智投一场一面的最后一句是，员工不信任的时候怎么说服。能拿出来的有三样：回答带出处，点得回原文；办理类动作先保留人工确认，数据证明可靠了再放开；试点期间的评测和抽检结果。

## 六、时间怎么分，怎么收尾

33 场里至少有 5 场，这道题是帖子里记下的最后一个问题，美团 Agent 开发那场后面紧接着就是反问。下面的分法是建议，不是从面经里统计出来的。假设这道题有十分钟：

![Image](<Agent%20高频题%2029.%20从零设计一个%20Agent：场景题按什么顺序答.assets/image-10.jpg>)

面试官想听哪一环，会像第五节那样追下去，那时再展开。

收尾先讲第一版。网易 Agent 开发那场问的就是这个：要快速上线 MVP，保留哪些核心功能，怎么取舍。知识库的例子里，第一版只上制度问答和年假查询，两条路都是只读的，答案有出处可查。排障和提申请先转人工，同时记下转人工的问题，哪一类最多，下一版先做哪一类。OpenAI 那份指南在结尾建议从小处开始，用真实用户验证，再逐步扩大能力。灰度、回滚和 bad case 怎么回流在第 13 题。

再留一句给风险：这套方案里最没把握的是哪一环，打算用什么数据验证。字节 AI 应用工程师那场的最后一个追问就是「你觉得难点是什么」。

## 七、面试怎么答

**两分钟主线**

1. 先问清五件事：谁用、问什么，资料什么样，怎样算成功，量级和时限，能做哪些动作、哪些做了收不回。面试官不给，就说出自己的假设再往下讲。
2. 把请求分类，判断哪一类要模型自己定下一步。以企业知识库问答为例，问制度是检索加生成的固定链路，查年假是一次只读调用，提权限申请是固定步骤加确认，只有 VPN 排障要循环。
3. 数据和工具：资料解析后带着来源、版本和权限入库，检索默认只取最新版；每个工具先标清只读还是写。
4. 上下文、失败和权限：每轮只放系统提示词、检索结果和最近几轮对话；循环有步数和花费上限，检索分数太低就回答不知道或转人工；权限在检索阶段过滤，写操作等用户确认。
5. 评测和成本：定一个主指标，再分检索、生成和拒答三段看，评测题从真实工单里来。原型先用最强的模型建立基线，再把能换的步骤换成小模型。
6. 第一版只上只读的功能，其余先转人工，按转人工的记录决定下一版做什么。最后说出方案里最没把握的一环和打算怎么验证。

**准备自己的项目**

从自己做过的系统里挑一个，按这个顺序重讲一遍：当初问清了哪些条件，哪一条没问清、后来返了工；哪一段交给了模型，哪一段写成了固定流程，依据是什么；第一版砍掉了什么，后来按什么数据加回来。再准备一道没做过的题，把你的项目换成智能客服或者 Coding Agent，对着第四节的表说出哪几步的答案变了。

**容易答错的地方**

- 题目一出就画多 Agent 架构，没问用户、资料和成功标准。
- 把整个系统都叫 Agent，说不出哪一段是固定流程，哪一段才要循环。
- 题目给了数据量、文件格式这些条件，方案里没用上。
- 只讲正常路径，不讲检索不到、工具失败和循环到了上限怎么办。
- 写操作不设确认，或者权限只靠提示词约束。
- 没准备评测和第一版范围，被问到怎么证明有效、先上什么时现想。
