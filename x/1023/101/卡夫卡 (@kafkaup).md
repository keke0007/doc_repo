# 卡夫卡 (@kafkaup)

今年还在做Agent开发的人，应该都有感觉：岗位要求已经不是“会不会做”，而是“你做出来的东西到底能不能用”。  
  
去年学个LangChain、接几个Tool、搭个聊天助手，就算挺新了。今年完全不是这个节奏。  
  
通用Agent越来越难做出差异。去年大家喜欢做全能助手，什么都能聊一点。今年企业更愿意为具体问题买单：内部知识查询、客服处理、销售辅助、数据分析、研发提效。所以现在做Agent，  
  
第一步不是想能接多少工具，而是先把业务流程拆清楚。你连业务边界都说不清，后面工具越多越乱。  
  
RAG重新变得很关键。很多Agent项目最后都卡在同一个地方：模型能推理，但不知道公司内部的东西。这时候RAG就绕不过去。知识库、业务规则、历史文档、内部数据，检索质量不解决，Agent规划得再花哨，也是在错误信息上继续执行。所以RAG现在不是加分项，是基础能力。  
  
框架会用，已经拉不开差距。LangGraph、Dify、Coze都能帮你快速搭流程。但真实项目更看：Tool失败怎么兜底？任务中断怎么恢复？上下文太长怎么处理？模型输出不稳定怎么校验？人工什么时候接管？这些问题框架不会自动帮你解决。值钱的是工程判断，不是API熟练度。  
  
AI应用越来越像正常的软件系统。去年很多项目还停在Demo阶段，今年企业开始看部署、权限、日志、监控、成本和数据安全。FastAPI、Docker、Redis这些传统工程能力重新变得重要。有些项目还涉及私有化部署、本地模型和内部数据隔离。所以后端转AI，反而有天然优势。  
  
评估开始成为必修课。去年不少项目改完Prompt，人工试几个问题，觉得“好像变好了”就敢上线。今年不行了。RAG要看检索效果，Agent要看任务完成率、Tool成功率，线上还得盯延迟、Token成本和Bad Case。没有评估，优化就是凭感觉。  
  
MCP、多Agent可以学，但别追着热点跑。这些方向值得跟，但不是越早越好。一个Agent连RAG、Tool Calling、异常兜底都做不稳，过早上复杂架构只会把问题放大。  
  
今年Agent开发真正的变化，其实就一句话：从“会搭”转向“会交付”。模型、RAG、Agent只是能力组件，能不能把它们接进真实业务，做成稳定、可维护、能算清效果和成本的应用，才是真正拉开差距的地方。
