Felix 现在的日常工作  
· 团队约一周半做出 Claude Cowork；他现任 Claude 工程负责人，自称是「Claude 的传送带」；过去是挑一条崩溃丢给模型修；正确做法是让模型直接摸全部崩溃数据，自己决定修什么、不修什么。  
· 早晨有 agent 简报；日常多在原型：睡几天掂量想法 → 让 Claude 做多版 → 人做 critique。能做一千个原型，人的注意力一天大概只能认真看一个；好产品信号是少数人上手就「点亮」、能做以前做不到的事，按钮宜少不宜多。  
  
自动化 vs 增强  
· 自动化：砍掉烦人、贵、耗时的活，眼下经济价值最清楚。  
· 他更在意增强：补技能/方法/知识，让人做成以前做不到的事。真正拉开差距的，往往是改工作流与定义好坏，而不只是工具本身。  
  
知识工作怎么评「好」  
· 报天气：瞎猜温度碰巧对 = 不及格；差半度但定位、信源、路径靠谱 = 更好。过程与可验证性优先于「看起来对」。  
· 写作：别「Claude 把这段写好」；学优秀作者流程，放大论点、找最强反驳、按专业步骤走。许多创作者强调的是苦练出来的流程，不是玄学手感。  
· 动效/3D：Unlock 常是「用专业人士同款工具」（如让 Claude 用 Blender），而不只是空喊「像专业动画师」。  
  
防幻觉：对抗评审 + Judge  
· 实用招：同一产出（文章、PPT）开多条线程专攻「证明你错了」，事实、逻辑、误解；再开一条做 judge，筛哪些批评成立；成立的反馈可回原会话，原会话也可判断是否采纳。  
· 找茬往往比创造容易，对抗侧有时可用略弱模型。  
· 两类任务：自己完全不懂好坏 → 多砸 token/多轮 AI；自己能当「甲方」判断观感（如他不懂 Blender 但能判网站 3D 好不好）→ 观感即可。  
  
Agent、Skills、数据怎么摆  
· 偏刺的观点：行业对「Agent 角色扮演」过转；模型是强通才，DeepMind 定制数学银牌后，通才模型很快拿金。硬套「你是数据科学家」常限制用法；他多数任务不设人设。  
· 与其给每个 agent 切一小片数据，不如给全景业务视图 + 文档清楚的工具（需要业务数据就调业务工具，不必整库灌进上下文）。工具调用变强后，他不再优先做「该给谁哪片数据」的决策。  
· Skills：官方与他个人都劝慎用；半衰期极短，有时删掉 skill 输出更好；上一世代模型的规矩常会绑住新模型。  
· 换位成「模型体验」：你会要原始数据、一台电脑、装软件的权限、少被别人先下结论，而不是只听人转述。  
  
不信任什么  
· 问「还信不过 agent 做什么」时，他改答：更不信同一个会话自评；当前会话当自己工作的法官仍很不靠谱。尽量找外部信号（另一会话、真实指标）。  
· 事实核查一类：他敢信单线程（找一手来源、验来源质量）。  
· 反馈闭环：在 Slack/GitHub 等处给工具权限，让模型自己汇集反馈 → 压成原则 → 再挖「你以为信、实际未必信」的原则，用于后续评审；也可人机并排写反馈几轮再对齐。  
  
创业与软件  
· 一人/两人团队做大公司更可行，但秘诀没变：共情，对用户、场景、付钱的人是否真有价值。  
· 会消失的是「勉强凑合、没得选」的烂软件；真正好用的产品，多数人仍不会自己想出来。  
· 他爱去酒店前台等处看真实经济用的机子：大量仍是笨拙旧系统，垂直清理是机会；牙医诊所软件一类老笑话，关系与分发仍难。  
· 能力过剩（capability overhang）：顶尖智能 vs 多数人还在问「法国首都是哪」；Dario 的「天才数据中心」要落到可用，靠重想需求与可能性。个人层：少做「帮我润色邮件」，多把真正想要的结果交给模型，直到撞上当前天花板，那才吃得到下一代模型红利。  
  
给工程师与下一代  
· 工程师价值看用户是否愿意为结果付钱，不是背完整 React API。建议：做能摸到的真作品组合、证明共情与整合多系统的能力；背单一 API 贬值，把多系统捏在一起升值。  
· 招人看做过什么、是否在赢的团队上，胜过看学校学位。  
· 对女儿（尚幼）：早懂商业如何运转、如何协作、如何找价值；他推崇滑铁卢式多实习，懂怎么推想法、要资源、过法务，往往比纯 CS 理论更快上手。  
· 五年后：很难直觉跟上智能指数；能较有把握说的是，今天这些 AI 产品大概还处在智能手机之前的功能机阶段，形态会大变。他自己的建议也可能十周后就要改一版。
