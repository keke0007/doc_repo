理解 GBDT（Gradient Boosting Decision Tree，梯度提升决策树）的损失函数推导，最重要的是理解一个核心问题：

为什么每一轮训练都要计算损失函数的负梯度，并让新的决策树去拟合这个负梯度？

这也是 GBDT 中 Gradient（梯度）这个词的来源。

我们从最基本的数学原理开始，逐步推导到 GBDT 的训练公式。

## 一、先理解 GBDT 的整体思想

GBDT 属于 Boosting 集成学习。它不是独立训练多棵树再投票，而是让每一棵新树去修正当前模型的不足。

假设我们预测房价：

|   样本   |   真实房价 $y$   |   当前预测 $\hat y$   |   残差 $y-\hat y$   |
| --- | --- | --- | --- |
|   A   |   100   |   80   |   +20   |
|   B   |   200   |   220   |   -20   |
|   C   |   150   |   140   |   +10   |

当前模型对 A 低估了 20，对 B 高估了 20，对 C 低估了 10。

如果使用平方误差损失，新树就会学习如何修正这些预测误差。

整体模型可以表示为：

$$F_M(x)=F_0(x)+\sum_{m=1}^{M}\eta h_m(x)$$

其中：

* $F_0(x)$：初始模型。
* $h_m(x)$：第 $m$ 轮训练得到的决策树。
* $\eta$：学习率，用来控制每棵树的修正幅度。
* $M$：树的总数量。

注意：上面使用的是加法模型的简化表达。在实际算法中，每棵树还需要通过叶节点输出值的优化来确定具体的修正量。

## 二、第一步：定义损失函数

损失函数用于衡量预测结果与真实结果之间的差距。

对于回归问题，最常见的选择是平方误差损失：

$$L(y,F(x))=\frac{1}{2}(y-F(x))^2$$

这里：

* $y$：真实值。
* $F(x)$：当前模型的预测值。
* $L$：当前样本的损失。

为什么前面要乘 $\frac12$？

主要是为了求导时抵消平方项产生的系数 2，让公式更简洁。它不会改变最优预测结果。

对于 $N$ 个样本，整体损失为：

$$J(F)=\sum_{i=1}^{N}\frac12(y_i-F(x_i))^2$$

GBDT 的目标就是不断增加新的树，让整体损失 $J(F)$ 逐步降低。

## 三、第二步：对损失函数求导

这是整个推导的关键。

当前模型为 $F_{m-1}(x)$，对第 $i$ 个样本，其损失是：

$$L_i=\frac12(y_i-F_{m-1}(x_i))^2$$

我们把预测值 $F_{m-1}(x_i)$ 看作变量，对它求偏导：

$$\frac{\partial L_i}{\partial F_{m-1}(x_i)}$$

根据链式法则：

$$\begin{aligned} \frac{\partial L_i}{\partial F} &=\frac12\cdot 2(y_i-F)\cdot(-1)\\ &=-(y_i-F)\\ &=F-y_i \end{aligned}$$

所以：

$$\boxed{ \frac{\partial L_i}{\partial F}=F_{m-1}(x_i)-y_i }$$

这个导数表示什么？

* 导数大于 0：预测值倾向于过大，应该往下降的方向调整。
* 导数小于 0：预测值倾向于过小，应该往上升的方向调整。
* 导数等于 0：对于平方误差而言，当前预测值已经等于真实值。

### 为什么要取负梯度？

梯度下降的基本公式是：

$$\theta_{\text{new}} = \theta_{\text{old}}-\eta\nabla J(\theta)$$

这里的减号表示沿着损失下降的方向移动。

将同样的思想应用到 GBDT 的预测函数：

$$F_m(x)=F_{m-1}(x)-\eta \frac{\partial L}{\partial F}$$

代入刚才求出的导数：

$$\begin{aligned} F_m(x) &=F_{m-1}(x)-\eta(F_{m-1}(x)-y)\\ &=F_{m-1}(x)+\eta(y-F_{m-1}(x)) \end{aligned}$$

因此，我们发现：

$$\boxed{ -\frac{\partial L}{\partial F}=y-F }$$

对于平方误差损失，负梯度恰好等于残差。

这就是为什么经典 GBDT 回归算法可以通过拟合残差来训练下一棵树。

不过要注意：模型不能直接为每个样本单独添加一个修正值，因为我们希望学到的是一棵能够根据特征 $x$ 预测修正量的决策树。

## 四、第三步：为什么需要训练一棵新树？

前面算出了每个样本的负梯度：

$$r_{im}= -\left. \frac{\partial L(y_i,F(x_i))} {\partial F(x_i)} \right|_{F=F_{m-1}}$$

其中 $r_{im}$ 被称为 伪残差（Pseudo-residual）。

对于平方误差：

$$r_{im}=y_i-F_{m-1}(x_i)$$

接下来，我们用一棵新的决策树 $h_m(x)$ 去拟合这些伪残差：

$$\boxed{ h_m=\arg\min_h \sum_{i=1}^{N}(r_{im}-h(x_i))^2 }$$

为什么要这样做？

假设训练数据中：

* 房屋面积较小的样本，残差通常是 $+20$。
* 房屋面积中等的样本，残差通常是 $+5$。
* 房屋面积较大的样本，残差通常是 $-15$。

新树就可以通过房屋面积进行分裂，并在不同叶节点输出不同的修正量。

当前模型 $$F_{m-1}(x)$$

预测房价

计算负梯度 $$r_{im}$$

衡量每个样本应该修正的方向与程度

训练新决策树 $$h_m(x)$$

学习特征与预测误差之间的关系

更新模型

$$F_m(x)=F_{m-1}(x)+\eta h_m(x)$$

这就是 GBDT 的梯度提升机制：先通过损失函数计算每个样本应该如何修正，再让决策树学习这些修正规律。

这里有一个细节：负梯度只是给定的训练目标，决策树不一定能够完全拟合它。树的深度、叶节点划分和学习率都会影响最终的修正效果。

## 五、第四步：为什么拟合负梯度可以降低损失？

前面知道了如何计算负梯度，但还需要回答一个数学问题：

为什么沿着负梯度方向更新模型，损失就会下降？

这里用泰勒展开来理解。

设当前模型预测值为 $F$，我们准备增加一个修正量 $\epsilon h(x)$，那么新损失可以近似写成：

$$\begin{aligned} L(F+\epsilon h) \approx{}&L(F)\\ &+\epsilon\frac{\partial L}{\partial F}h\\ &+\frac{\epsilon^2}{2} \frac{\partial^2 L}{\partial F^2}h^2 \end{aligned}$$

暂时忽略二阶及更高阶影响，只看一阶项：

$$\Delta L\approx \epsilon\frac{\partial L}{\partial F}h$$

如果 $h$ 与负梯度方向一致，即：

$$h\approx-\frac{\partial L}{\partial F}$$

那么：

$$\Delta L\approx -\epsilon\left(\frac{\partial L}{\partial F}\right)^2$$

只要 $\epsilon>0$，并且梯度不为零，这个一阶近似就是负数，意味着损失下降。

实际中，决策树只能近似拟合负梯度，因此不保证每一次更新都必然降低损失。学习率、树的拟合质量以及叶节点的输出值都会影响更新效果。

## 六、推广到任意损失函数：不只是残差

前面的推导使用了平方误差。GBDT 更一般的形式是：

$$\boxed{ r_{im}= -\left. \frac{\partial L(y_i,F(x_i))} {\partial F(x_i)} \right|_{F=F_{m-1}} }$$

也就是说，GBDT 的核心不是必须拟合残差，而是拟合损失函数的负梯度。

下面对比三种情况。

|   任务   |   损失函数   |   负梯度（伪残差）   |
| --- | --- | --- |
|   回归   |   $$\frac12(y-F)^2$$   |   $$y-F$$   |
|   回归（绝对误差）   |   $$|y-F|$$   |   $\operatorname{sign}(y-F)$，在零点需用次梯度处理   |
|   二分类   |   $$-y\ln p-(1-y)\ln(1-p)$$   |   $y-p$，其中 $p=\sigma(F)$   |

对于二分类，定义：

$$p=\sigma(F)=\frac{1}{1+e^{-F}}$$

这里 $F$ 是模型输出的 logit，而不是概率本身。二元交叉熵对 $F$ 求导后得到：

$$\frac{\partial L}{\partial F}=p-y$$

因此：

$$\boxed{r=y-p}$$

例如，真实标签 $y=1$，模型预测概率 $p=0.3$，那么负梯度为：

$$r=1-0.3=0.7$$

模型需要提高这个样本的 logit，使其预测概率增大。

如果真实标签 $y=0$，预测概率 $p=0.8$，那么：

$$r=0-0.8=-0.8$$

模型就需要降低这个样本的 logit。

所以，即使在分类问题中，GBDT 仍然可以通过负梯度学习如何修正预测，只是此时的伪残差不再等于真实标签与预测值的普通残差。

## 七、最后一步：决策树的叶节点输出值如何确定？

前面推导了新树如何拟合负梯度。但严格来说，经典 Gradient Boosting 还需要确定树的实际更新幅度。

假设新树把样本划分成 $J$ 个叶节点，其结构记为 $h_m(x)$。在第 $m$ 轮，理论上可以直接优化：

$$\boxed{ \gamma_m= \arg\min_{\gamma} \sum_{i=1}^{N} L\left(y_i,F_{m-1}(x_i)+\gamma h_m(x_i)\right) }$$

其中 $\gamma_m$ 是本轮的步长。

实际算法中，也经常对每个叶节点 $R_{jm}$ 单独优化输出值：

$$\gamma_{jm} = \arg\min_{\gamma} \sum_{x_i\in R_{jm}} L\left(y_i,F_{m-1}(x_i)+\gamma\right)$$

这样每个叶节点都可以根据自己覆盖的样本，确定最合适的修正量。

最后更新模型：

$$\boxed{ F_m(x)=F_{m-1}(x)+ \eta\gamma_{jm},\quad x\in R_{jm} }$$

注意，某些经典 GBDT 实现会直接用拟合伪残差得到的叶节点均值作为输出；另一些实现会额外进行叶节点线搜索。XGBoost 等算法还会利用二阶梯度构造正则化目标，因此具体公式会有所不同。

## 八、把整个推导串起来

GBDT 每轮训练的数学过程

1. 定义损失
    
    $$J(F)=\sum_i L(y_i,F(x_i))$$
2. 计算负梯度
    
    $$r_{im}=-\frac{\partial L_i}{\partial F_i}$$
3. 训练决策树拟合伪残差
    
    $$h_m=\arg\min_h\sum_i(r_{im}-h(x_i))^2$$
4. 优化更新步长或叶节点输出
    
    $$\gamma_m=\arg\min_\gamma\sum_iL(y_i,F_{m-1}(x_i)+\gamma h_m(x_i))$$
5. 更新模型
    
    $$F_m=F_{m-1}+\eta\gamma_mh_m$$

记住这三个关键区别：

* 损失函数：衡量模型预测得有多差。
* 负梯度：告诉模型每个样本应该往什么方向修正。
* 决策树：学习如何根据输入特征预测这种修正量。

如果你继续学习 XGBoost，下一步最值得理解的是：为什么 XGBoost 不仅使用一阶梯度 $g_i$，还要引入二阶梯度 $h_i$，并最终推导出叶节点权重 $w_j=-G_j/(H_j+\lambda)$ 和分裂增益公式。 这可以直接从上面的泰勒展开继续推导。

# 半导体设备测量—加工闭环控制：算法选型与实施方案

针对你的场景，我建议采用 “传统工艺补偿 + XGBoost 预测 + 约束优化 + 设备控制器执行” 的混合方案，而不是直接让 XGBoost 根据测量偏差输出设备控制指令。

核心原因是：半导体制造中的测量结果与加工参数之间通常存在非线性关系，但也存在设备漂移、批次差异、工艺窗口限制和设备响应延迟。XGBoost 可以帮助建模这些复杂关系，却不能自动保证补偿方向正确、工艺稳定或设备安全。

建议先建设一个可追溯、可验证、可回滚的工程闭环，再逐步增加机器学习能力。

## 二、算法选型：XGBoost 应该承担什么角色？

第一层：传统补偿模型

基线方案

使用标定曲线、线性回归、比例补偿或经过验证的工艺公式，建立参数调整量与量测偏差的关系。

优势：容易解释、容易验证，适合作为安全基线。

第二层：XGBoost 质量预测模型

预测量测指标、下一片产品的偏差，或候选工艺参数对应的加工结果。

它特别适合表格型历史数据，能学习转速、功率、配方、腔体状态、耗材寿命等特征之间的非线性关系。

第三层：约束优化器

在设备允许范围和工艺窗口内，搜索能够让预测结果接近目标值的参数组合。

可以先用小范围网格搜索或坐标搜索；变量多、约束复杂时，再考虑更高级的优化方法。

第四层：设备控制与安全联锁

由设备控制器、工艺控制系统或经验证的控制服务检查参数边界、设备状态、配方权限和执行条件，再决定是否应用补偿。

模型只能提供候选建议，不能绕过设备控制器的限制。

### 算法对比

|   算法   |   适用角色   |   建议   |
| --- | --- | --- |
|   工艺补偿公式 / 线性回归   |   建立可解释的偏差—参数关系   |   必须作为基线评估   |
|   XGBoost Regressor   |   非线性质量预测   |   首选机器学习基线   |
|   Random Forest   |   非线性预测对照   |   可用于模型对比   |
|   Gaussian Process / 贝叶斯优化   |   小样本、带不确定性的优化   |   可作为后续探索方向   |
|   MPC   |   动态、多变量、带约束的闭环控制   |   需要动态模型与时序控制需求时考虑   |
|   PID   |   连续反馈控制   |   适合具有明确动态响应的控制回路，不直接替代工艺补偿模型   |

我的选型结论： 如果历史数据主要是“每片晶圆或每批产品的加工参数 + 最终量测结果”，先训练 XGBoost 回归模型。如果需要预测下一片晶圆的加工结果并选择参数，可以在此基础上增加约束优化。如果需要毫秒级连续控制，不能仅凭 XGBoost 回归模型实现，应单独设计实时控制方案。

## 三、数据设计：历史数据需要采集哪些字段？

这是项目能否成功的关键。对于闭环控制，最重要的不是数据量有多大，而是每一条量测结果能否准确关联到它对应的加工过程，以及实际执行过的设备参数。

建议将数据分为五类。

### 3.1 核心数据字段

|   数据类别   |   关键字段示例   |   用途   |
| --- | --- | --- |
|   产品与追溯   |   `wafer_id`、`lot_id`、`product_id`、`route_step`   |   关联加工与量测结果   |
|   加工设备   |   `equipment_id`、`chamber_id`、`recipe_id`、`recipe_version`   |   区分设备、腔体和工艺配方   |
|   实际加工参数   |   `power_actual`、`pressure_actual`、`gas_flow_actual`、`temperature_actual`、`process_time`   |   建立输入特征   |
|   量测结果   |   `metric_name`、`target_value`、`measured_value`、`measurement_site`   |   计算质量偏差与空间分布   |
|   设备与工艺状态   |   `consumable_age`、`maintenance_count`、`calibration_status`、`alarm_code`   |   识别漂移、异常和设备差异   |
|   控制执行记录   |   `previous_offset`、`proposed_offset`、`approved_offset`、`applied_offset`   |   追踪补偿策略及实际执行情况   |

其中几个字段必须特别区分：

* 设定值（setpoint）：配方要求设备达到什么值。
* 实际值（actual）：设备实际执行时达到什么值。
* 建议补偿值（proposed）：算法建议调整多少。
* 实际执行值（applied）：最终真正应用了多少。

只记录设定值是不够的。假如设备设定功率为 1000 W，但实际运行时因设备状态变化只达到 970 W，模型若不知道这个差异，就可能把设备执行偏差误认为工艺参数与产品质量之间的关系。

### 3.2 建议采用的逻辑数据模型

ProcessRun（加工记录）

一片晶圆、一次工艺步骤或一个明确的加工单元

`run_id · wafer_id · equipment_id · chamber_id · recipe_version · start_time · end_time`

ProcessParameter（加工参数）

通过 run_id 关联到加工过程

`parameter_name · setpoint · actual_value · unit · timestamp`

MetrologyResult（量测结果）

通过 wafer_id + route_step + measurement_site 等标识关联产品

`metric_name · target_value · measured_value · site_x · site_y · timestamp`

ControlAction（补偿记录）

记录建议、审批、执行和验证的完整过程

`model_version · proposed_value · approved_value · applied_value · status`

实际项目中，量测设备和加工设备不一定直接共享数据库。可以通过 MES、设备接口服务或制造数据平台完成关联。对于设备通信，可根据实际支持情况评估 SECS/GEM、EAP、厂商接口等方式。

### 3.3 标签怎么定义？

不要一开始就把所有字段直接丢给 XGBoost。先明确预测目标。

假设某项量测指标的目标值为 $y^*$，实际量测值为 $y$，定义：

$$e=y-y^*$$

这里规定：

* $e>0$：测量值高于目标。
* $e<0$：测量值低于目标。

可以先训练一个偏差预测模型：

$$\hat e=f_{\text{XGBoost}}(x)$$

其中 $x$ 包含加工参数、设备状态、产品类型和历史状态等特征。

但如果不同产品的规格目标不同，直接预测原始量测值可能让模型混淆产品差异。可以考虑预测经过合理归一化的偏差，或按产品、工艺步骤建立独立模型。

重要： 如果目标是预测加工后质量，特征只能使用在预测时刻已经可知的信息。不能把本次加工完成后才得到的量测值、事后确认的良率或未来发生的报警放进特征中，否则会发生数据泄漏。

## 四、XGBoost 模型训练方案

建议分为三个模型阶段，而不是一开始就直接训练“输入测量偏差，输出补偿量”的模型。

### 阶段 A：预测加工后的量测偏差

这是最容易验证的第一步。

输入：

$$x= [\text{工艺参数、设备状态、产品类型、历史状态}]$$

输出：

$$\hat e=f(x)$$

模型目标是预测最终量测偏差。使用 XGBoost 的 `reg:squarederror` 作为起点，若异常值很多，再比较 Huber 类鲁棒损失或其他稳健建模方式。

建议模型对照组：

1. 常数基线：预测历史平均偏差。
2. 线性回归：验证简单线性关系是否已经足够。
3. XGBoost Regressor：验证非线性模型是否带来实际提升。

如果 XGBoost 无法显著优于简单基线，应该先检查数据质量、工艺稳定性和特征信息量，而不是单纯增加树的数量或深度。

### 阶段 B：学习加工参数与量测偏差的关系

如果目标是主动调整加工参数，预测模型必须能够回答：

> 如果把某个允许调整的参数改成另一个值，预测的量测结果会怎样变化？

假设：

$$\hat e=f(x,u)$$

其中：

* $x$：产品、设备、腔体和当前工艺状态。
* $u$：可以被控制的加工参数。
* $\hat e$：预测的加工偏差。

然后通过优化寻找候选参数：

$$u^*=\arg\min_{u\in\mathcal U} \left[f(x,u)\right]^2$$

这里 $\mathcal U$ 是满足设备限制、工艺窗口和变更幅度限制的可行参数集合。

如果存在多个量测指标，还可以使用加权目标：

$$u^*=\arg\min_{u\in\mathcal U} \sum_{k=1}^{K}w_k \left(\hat e_k(x,u)\right)^2$$

其中 $w_k$ 表示不同质量指标的权重。不过，权重不能仅根据统计方便来定，必须由工艺目标、规格和质量风险共同确定。

这里存在一个非常容易忽略的问题：历史数据中的相关性不等于参数调整的因果效果。

例如，操作人员可能只在设备已经出现异常时才调整功率。模型可能因此学到“高功率与较差量测结果相关”，但这不代表降低功率会改善质量。

因此，阶段 B 需要结合工艺机理、设备标定、历史补偿记录，必要时在经过批准的实验设计或受控试验中验证参数影响。

### 阶段 C：建立受约束的闭环策略

当阶段 A 的预测能力和阶段 B 的参数影响关系经过验证后，再将模型用于候选参数搜索。

建议优化目标至少包含三项：

$$J(u)= \underbrace{\sum_k w_k\hat e_k^2}_{\text{质量偏差}} + \underbrace{\lambda\lVert u-u_0\rVert^2}_{\text{限制参数变化}} + \underbrace{\rho R(u)}_{\text{风险惩罚}}$$

其中：

* $u_0$：当前经过验证的工艺参数。
* $\lambda$：控制参数变化幅度。
* $R(u)$：对超出训练数据覆盖范围、模型不确定性较高或接近工艺边界的候选方案进行惩罚。
* $\rho$：风险惩罚权重。

这比简单地选择预测偏差最小的参数更合理，因为模型可能在历史上从未出现过的参数组合上产生不可靠的预测。

对于常规 XGBoost，可以通过多个随机种子训练的模型集合、分组验证误差或其他经过校准的不确定性估计，识别低可信度的预测。需要注意：模型间预测分歧只是风险信号，不是严格的置信区间保证。

## 五、如何训练和验证模型？

半导体生产数据具有明显的时间相关性。同一批晶圆、同一腔体连续加工的样本，往往比不同时间、不同设备的样本更相似。因此，不能简单地随机打乱全部记录后再切分训练集和测试集。

### 5.1 数据处理流程

历史数据抽取

MES / EAP / 量测系统 / 设备日志

数据关联与质量检查

检查 wafer_id、run_id、时间顺序、缺失值、单位与异常记录

特征与标签构造

构造量测偏差、设备状态、耗材年龄、前序加工历史等特征

按时间 / 批次 / 设备切分数据

训练集 → 验证集 → 独立测试集

模型评估与版本登记

与基线比较，记录模型、数据版本、适用工艺范围和验证结果

### 5.2 数据切分建议

举例：假设你有连续 6 个月的生产数据，可以考虑：

|   数据集   |   示例时间范围   |   作用   |
| --- | --- | --- |
|   训练集   |   第 1～4 个月   |   学习加工参数与量测结果的关系   |
|   验证集   |   第 5 个月   |   调整模型超参数、选择模型   |
|   测试集   |   第 6 个月   |   评估模型对未来数据的泛化能力   |

这只是示例，不是固定比例。应根据数据量、产品切换频率和工艺变化情况决定。

另外需要区分两个目标：

* 预测同一设备未来的表现： 重点进行时间外推验证。
* 部署到未参与训练的新设备或新腔体： 需要额外进行设备或腔体隔离验证。

如果同一片晶圆存在多个测量点，应避免把同一晶圆的部分测量点放在训练集、其余测量点放在测试集而造成信息泄漏。可以按晶圆、批次或工艺运行单元分组切分。

### 5.3 XGBoost 的初始训练配置

对于单个连续型量测指标，可以从以下参数范围开始做交叉验证或时间序列验证。

|   参数   |   建议起点   |   作用   |
| --- | --- | --- |
|   `objective`   |   `reg:squarederror`   |   回归预测   |
|   `n_estimators`   |   300～800   |   最大提升轮数，配合 early stopping   |
|   `max_depth`   |   3～6   |   控制树的复杂度   |
|   `learning_rate`   |   0.03～0.08   |   每轮提升的步长   |
|   `min_child_weight`   |   3～10   |   限制叶节点的过度细分   |
|   `subsample`   |   0.7～0.9   |   每轮使用的样本比例   |
|   `colsample_bytree`   |   0.7～0.9   |   每棵树使用的特征比例   |
|   `reg_lambda`   |   1～10   |   L2 正则化起点   |

这些只是实验起点，并非半导体设备的通用最优参数。最终配置应以验证结果、样本规模和数据分布为准。

### 5.4 评估指标

不能只看模型的 $R^2$ 或 RMSE。对于工艺补偿，更重要的是模型是否能够降低实际量测偏差，并且不增加超规格产品和工艺风险。

建议同时观察：

* MAE：平均预测误差。
* RMSE：对大误差更敏感。
* Mean Error：预测是否存在系统性偏差。
* 规格超限率：实际产品超出工艺规格的比例。
* 补偿后偏差：闭环执行前后的量测误差变化。
* 错误补偿率：补偿方向错误或补偿导致质量恶化的比例。
* 不同设备、腔体、产品和时间段上的表现。

对于 CD、Overlay、膜厚等指标，还要根据规格要求分别评估，不应仅通过总体平均指标掩盖某个腔体或某类产品的异常。

## 六、闭环系统架构：从历史训练到设备执行

建议把模型训练、在线预测、参数优化和设备控制拆开。不要让模型训练服务直接连接设备并修改配方。

设备层

前置加工设备 / 后置量测设备 / PLC / 设备控制器

数据采集与追溯层

EAP / SECS/GEM 或厂商接口 / MES / 数据质量校验

历史数据与特征层

加工记录、量测结果、配方版本、设备状态、补偿历史

模型服务层

XGBoost 推理服务、模型版本、适用范围检查

补偿决策层

基线补偿、候选参数搜索、边界约束、风险检查、审批策略

受控执行层

授权校验 → 参数下发 → 执行确认 → 后续量测验证

横向安全要求：身份权限、审计日志、超时处理、版本回滚、设备互锁和异常停用。

### 6.1 每次闭环执行应该经历什么？

1. 量测设备产生结果，系统校验量测状态、校准状态、产品标识及量测时间。
2. 根据产品、工艺步骤、加工设备和腔体，关联正确的加工记录与配方版本。
3. 计算当前偏差，并检查设备状态、工艺版本及数据是否在模型的适用范围内。
4. 模型预测偏差，补偿决策模块生成候选参数；与传统补偿方案进行比较。
5. 执行边界检查、变更幅度限制和权限校验。按控制模式决定自动执行、人工审批或拒绝执行。
6. 下发参数后确认设备是否接受、实际参数是否生效，并记录实际执行值。
7. 通过后续量测验证实际效果。出现异常时停止自动补偿，转入人工处理或既定回退策略。

### 6.2 半导体场景的关键工程问题

第一，量测结果可能晚于加工过程到达。 不能仅根据“最新测量结果”修改当前设备。必须明确这个结果适用于哪片晶圆、哪个批次，以及哪些尚未加工的产品。

第二，晶圆空间分布可能非常重要。 如果测量结果是多个 site 的数据，单纯预测一个平均值可能掩盖边缘与中心的差异。可以根据工艺需求预测均值、非均匀性指标或空间分布特征。

第三，不能无条件跨设备复用模型。 不同设备、腔体或量测工具可能存在系统性偏差。跨设备部署必须经过独立验证，必要时使用设备专属校准或模型。

第四，工艺版本变化会改变模型适用性。 配方、耗材、腔体清洁状态、设备改造或量测校准变化都可能导致数据分布漂移。系统应监测这些变化，而不是永久使用一个固定模型。

## 七、安全策略：怎样避免模型把工艺越调越差？

在半导体设备中，自动补偿不仅是机器学习问题，也是工艺控制和设备安全问题。建议建立以下控制规则。

|   风险   |   建议的保护措施   |
| --- | --- |
|   补偿方向错误   |   先通过工艺标定和受控实验确认参数影响方向   |
|   单次补偿过大   |   限制单次变化量、累计变化量及变化速率   |
|   模型预测失真   |   对异常输入、分布外样本和低可信度预测拒绝自动执行   |
|   数据关联错误   |   校验 wafer、lot、设备、腔体、工艺步骤和配方版本   |
|   重复执行补偿   |   为控制任务设置唯一 ID、版本和幂等处理   |
|   设备不在可执行状态   |   检查设备模式、互锁状态、配方锁定和授权状态   |
|   模型更新造成性能退化   |   模型版本审批、灰度验证、快速停用和回退机制   |
|   多个系统同时修改参数   |   设立唯一参数写入权威方，并进行版本冲突检测   |

还需要明确三个原则：

1. 工艺限制优先于模型预测。 即使模型认为某个参数组合可以降低预测偏差，只要它超出批准的工艺窗口，就不能执行。
2. 异常时默认停止自动补偿。 数据缺失、设备状态异常、模型版本不匹配或执行确认失败时，应转为安全定义的人工处理流程，而不是继续猜测参数。
3. 不要将普通机器学习服务作为安全联锁。 设备安全联锁和关键保护应由经过验证的设备控制与安全机制承担。模型服务失效不应导致设备失去原有保护能力。

另外，半导体工艺参数可能涉及工艺保密和质量追溯，建议保留完整的预测输入快照、模型版本、候选参数、审批人、实际执行值以及后续量测结果，以便复现每次补偿决策。

## 三、薄膜厚度与均匀性的标签设计

这是整个机器学习方案中最重要的部分之一。

不要只用一个“是否合格”的标签，也不要把厚度和均匀性直接合并成一个数。第一阶段建议建立两个独立的回归目标。

### 3.1 标签一：平均膜厚偏差

假设一片晶圆有 $N$ 个有效测量点，第 $i$ 个点的膜厚为 $t_i$。

平均膜厚：

$$\bar t=\frac{1}{N}\sum_{i=1}^{N}t_i$$

目标膜厚为 $t^*$，定义厚度偏差：

$$\boxed{e_t=\bar t-t^*}$$

例如：

* 目标膜厚：100 nm
* 实际平均膜厚：103 nm
* 厚度偏差：+3 nm

正值表示膜厚偏厚，负值表示膜厚偏薄。

推荐的第一个 XGBoost 标签：

$$\boxed{y_1=e_t}$$

也可以预测原始平均膜厚 $\bar t$，然后在控制模块计算偏差。对于不同目标膜厚的产品，预测偏差或经过合理归一化的偏差通常更方便，但必须保留产品和工艺目标信息。

### 3.2 标签二：片内均匀性

均匀性有不同定义，必须使用量测系统和工艺规范认可的定义。一个常见选择是归一化的 $3\sigma$ 均匀性：

$$U_{3\sigma}= \frac{3s_t}{\bar t}\times100\%$$

其中：

$$s_t= \sqrt{\frac{1}{N-1} \sum_{i=1}^{N}(t_i-\bar t)^2}$$

这里使用样本标准差；如果工艺规范使用其他算法，应以规范为准。部分工艺也采用 $(t_{\max}-t_{\min})/(2\bar t)$ 或其他定义，不能混用。

例如，假设：

* 平均膜厚：100 nm
* 测量点标准差：0.5 nm

则：

$$U_{3\sigma}=\frac{3\times0.5}{100}\times100\%=1.5\%$$

第二个标签可以定义为：

$$\boxed{y_2=U_{3\sigma}}$$

模型训练后分别预测：

$$\hat y_1=f_1(x,u)$$

$$\hat y_2=f_2(x,u)$$

其中：

* $x$：产品类型、设备状态、腔体状态、历史偏差等上下文特征。
* $u$：本次使用的 Recipe / Offset 参数。
* $\hat y_1$：预测的平均膜厚偏差。
* $\hat y_2$：预测的片内均匀性。

初期建议训练两个独立的 XGBoost 回归模型，方便诊断每个指标的预测能力。之后再根据实际需求考虑多输出模型。

### 3.3 第三个标签：质量约束，而不是单独的预测目标

假设工艺规格要求：

$$t_{\min}\leq \bar t\leq t_{\max}$$

并且：

$$U_{3\sigma}\leq U_{\max}$$

那么闭环控制必须同时满足厚度与均匀性约束。

即使预测平均厚度恰好达到目标，只要均匀性超过上限，该参数组合也不能被认为是合格的控制方案。

另外，平均值和标准差不足以描述所有空间缺陷。如果晶圆存在明显的中心—边缘差异、方向性梯度或局部异常点，还应增加空间分布指标，或保留测量点级数据用于进一步分析。

## 四、补偿数学公式：先建立基线，再使用 XGBoost 优化

建议采用两个层次的控制逻辑：先实现可解释的传统 R2R 控制，再让 XGBoost 改善非线性预测与参数选择。

### 4.1 第一层：传统 R2R 厚度补偿

假设沉积时间 $u$ 与平均膜厚在当前工艺窗口内近似线性：

$$\bar t \approx a+\beta u$$

其中：

* $a$：其他工艺条件对应的基准项。
* $\beta$：沉积时间变化对膜厚的影响灵敏度。
* $u$：沉积时间。

如果 $\beta>0$，增加沉积时间通常会增加膜厚。对于当前厚度偏差 $e_t$，可以采用：

$$\boxed{ u_{k+1}= u_k-\frac{K}{\beta}e_{t,k} }$$

其中：

* $u_k$：当前实际采用的沉积时间。
* $u_{k+1}$：下一次加工建议的沉积时间。
* $K$：补偿增益，$0<K\leq1$。
* $e_{t,k}$：当前晶圆或批次的平均膜厚偏差。

举个简化例子：

假设膜厚偏厚 3 nm，经过工艺标定得到灵敏度：

$$\beta=0.2\ \text{nm/s}$$

若取 $K=0.5$，则：

$$\Delta u=-\frac{0.5}{0.2}\times3=-7.5\ \text{s}$$

即候选沉积时间减少 7.5 秒。

注意：这只是数学示例，不是实际半导体设备的可执行参数。 实际灵敏度、补偿增益、允许变化幅度及其他工艺影响都必须通过对应设备和工艺的验证来确定。

如果膜厚与参数的关系明显非线性，或者多个参数共同影响结果，就不应该继续依赖单一线性公式，而应评估非线性模型或分段标定模型。

### 4.2 Offset 参数如何补偿？

如果 Offset 是经过工艺标定的直接厚度补偿量，并且它对最终量测结果的影响近似为：

$$e_t\approx e_{\text{process}}+c\cdot o$$

其中 $o$ 是 Offset，$c$ 是 Offset 到最终厚度的灵敏度，那么可以考虑：

$$\boxed{ o_{k+1}=o_k-K\frac{e_{t,k}}{c} }$$

但实际设备中，Offset 的定义可能是目标值偏移、传感器校正、工艺配方补偿，甚至是设备内部控制量。因此，不能仅凭参数名称推导其补偿方向。

必须先确认：

1. Offset 的物理或工艺含义。
2. 修改它是否真的改变最终薄膜厚度。
3. 它与 Recipe 参数是否作用于同一个控制环。
4. 是否存在设备内部自动补偿机制。

如果 Offset 只是量测校正值，而不是实际工艺控制参数，就不能将它作为膜厚补偿变量，否则可能只是把测量结果改得更接近目标，却没有改善真实薄膜质量。

### 4.3 第二层：XGBoost 预测与参数优化

对于非线性工艺，建议将预测模型写成：

$$\hat e_t=f_t(x,u)$$

$$\hat U=f_U(x,u)$$

其中 $u$ 可以包含经过批准、允许调整的 Recipe 参数与 Offset 参数。

下一次加工的参数可以通过以下优化问题确定：

$$\boxed{ u^*=\arg\min_{u\in\mathcal U} \left[ w_t\left(\frac{\hat e_t(x,u)}{S_t}\right)^2 + w_U\left(\frac{\hat U(x,u)}{S_U}\right)^2 + \lambda\left\|D^{-1}(u-u_0)\right\|_2^2 \right] }$$

约束条件为：

$$u_{\min}\leq u\leq u_{\max}$$

$$|\Delta u_j|\leq \delta_j$$

以及其他工艺限制。

这里：

* $u_0$：当前经过批准的参数。
* $S_t,S_U$：用于归一化误差的尺度。
* $w_t,w_U$：厚度与均匀性的目标权重。
* $D$：用于归一化各参数变化幅度的尺度矩阵。
* $\lambda$：惩罚不必要参数变化的权重。
* $\delta_j$：第 $j$ 个参数的单次调整上限。
* $\mathcal U$：所有允许的参数组合。

还需要增加预测质量与规格相关的约束，例如：

$$\hat U(x,u)\leq U_{\max}$$

以及经过工艺批准的厚度范围约束。

如果模型预测的不确定性较高，或者候选参数远离训练数据覆盖范围，应拒绝自动应用该候选方案，或者回退到经过验证的基线控制策略。

实际实现时，不必直接对 XGBoost 做复杂的梯度求导。可以在批准的参数范围内使用网格搜索、坐标搜索或其他受约束优化算法。XGBoost 的分段树结构也意味着预测函数并不处处可微。

### 4.4 为什么不直接让 XGBoost 学习补偿量？

可以训练一个模型：

$$\Delta u=g(e_t,U,\text{历史状态})$$

但它有一个风险：模型只是复现历史操作人员或旧控制策略的行为，不一定学到了正确的参数调整规律。

例如，操作人员可能总是在腔体老化时降低功率。模型可能学会“腔体老化时应该降低功率”，但这种关系是否真的适用于其他产品、设备或维护阶段，仍然需要验证。

所以更稳妥的路线是：

1. 先训练 $f(x,u)$，预测参数组合对应的加工结果。
2. 再在安全约束下寻找候选参数。
3. 将候选结果与传统补偿方法比较。
4. 经过受控试验验证后，再逐步开放自动执行。

这能让控制决策更容易审查和追溯。

## 五、训练方案：如何让 XGBoost 学到正确的工艺关系？

这里要区分两个任务：

* 任务 A：预测下一片晶圆的膜厚与均匀性。
* 任务 B：预测如果修改 Recipe / Offset，下一片晶圆的膜厚与均匀性会如何变化。

任务 A 是普通监督学习；任务 B 才直接服务于参数优化。任务 B 的难点不仅是训练模型，还在于历史数据是否覆盖了不同参数组合，以及参数变化是否受到其他工艺因素干扰。

### 5.1 训练数据结构

建议构造一张供模型训练使用的特征宽表，每行代表一个晶圆级加工运行。

示例训练样本（仅用于说明结构）

|   特征 / 标签   |   示例值   |
| --- | --- |
| 产品类型 | Product-A |
| 腔体 ID | CH-02 |
| 沉积时间 | 120 s |
| 实际功率 | 850 W |
| 腔体累计运行时间 | 240 h |
| 上一片厚度偏差 | +1.2 nm |
| 标签：平均厚度偏差 | +2.1 nm |
| 标签：均匀性 | 1.6% |

所有数值均为虚构示例，不代表真实设备参数或工艺规格。

建议每个模型输入至少包含：

* 产品与工艺：产品类型、工艺步骤、Recipe 版本。
* 设备与腔体：设备 ID、腔体 ID、维护状态。
* 实际工艺参数：沉积时间、功率、压力、温度、气体流量等适用字段。
* 历史状态：最近几片晶圆的有效厚度偏差、均匀性和已执行补偿。
* 控制参数：加工时实际使用的 Recipe / Offset 值。

对于任务 B，候选参数 $u$ 必须作为输入变量。否则，模型无法回答不同参数组合会造成什么结果。

### 5.2 数据清洗与特征工程

重点处理以下情况：

1. 量测失败、校准异常、重复测量和无效测量点。
2. 晶圆加工异常中断、配方版本变更、设备维修后的数据。
3. 实际执行参数与 Recipe 设定值不一致。
4. 晶圆空间测量点分布不一致，导致均匀性统计不可直接比较。
5. 同一批次中不同晶圆、不同腔体的差异。

不要简单删除所有异常数据。某些异常代表真实的设备退化，应该被识别并单独建模或用于异常监测；另一些异常是测量故障或错误记录，不适合用于普通工艺回归。

### 5.3 训练与测试集切分

建议采用时间切分和分组切分，而不是随机拆分每一条测量记录。

例如，使用前四个月训练、第五个月验证、第六个月测试；同时确保同一晶圆的多个测量点不会跨集合泄漏。

还要单独验证：

* 不同腔体的模型表现。
* 腔体清洁或 PM 前后的模型表现。
* 不同产品与 Recipe 版本的模型表现。
* 新时间段上的预测稳定性。

如果一个模型只在某个腔体上表现良好，不应直接认为它可以用于整条产线。

### 5.4 模型训练与评估

建议分别训练：

$$f_t(x,u)\rightarrow e_t$$

$$f_U(x,u)\rightarrow U_{3\sigma}$$

初期使用 XGBoost 的 `reg:squarederror` 作为基线，并与线性回归和传统工艺模型进行对照。

评估指标至少包括：

* 厚度偏差 MAE / RMSE。
* 均匀性 MAE / RMSE。
* 系统性预测偏差。
* 不同设备、产品和时间段的误差。
* 候选参数是否超出训练数据支持范围。
* 闭环补偿后的实际质量变化。

最重要的验收指标不是模型的 $$R^2$$，而是受控执行后，膜厚偏差与均匀性是否在满足工艺约束的前提下得到改善。

还应注意，普通 XGBoost 的预测误差很小，并不等于它准确知道“修改参数后”的因果效果。若历史参数几乎没有变化，模型可能无法可靠推断新的参数组合。必要时应通过经过工艺批准的实验设计，收集有代表性的参数变化数据。

## 六、Recipe 与 Offset 如何联合控制？

这部分需要特别谨慎，因为两个参数集合可能互相影响。

### 6.1 不要一开始同时开放全部参数

建议先将可调参数分成三类：

|   类别   |   控制策略   |
| --- | --- |
|   主效应明显且工艺机理明确的参数   |   优先作为首个补偿变量   |
|   与其他参数耦合明显的参数   |   先做受控试验，确认交互关系   |
|   涉及安全、设备保护或未经批准的工艺边界的参数   |   禁止模型自动修改   |

例如，如果沉积时间是经过验证的膜厚主控制参数，可以先只开放沉积时间的有限调整范围。等其效果稳定后，再评估是否需要引入其他 Recipe 参数。

### 6.2 为什么先控制一个参数更稳妥？

假设沉积时间和功率都能改变膜厚：

$$e_t\approx\beta_1u_1+\beta_2u_2$$

其中 $u_1$ 是沉积时间，$u_2$ 是功率。

如果历史数据中二者总是一起增加，模型就很难区分哪个参数真正产生了多少影响。这是参数可辨识性问题。

当两个参数同时自动调整时，即使厚度改善，也可能无法确定改善来自哪个参数，甚至可能恶化其他质量指标。

因此建议：

1. 先选择一个经过验证的主补偿变量。
2. 通过工艺标定或受控实验评估它对膜厚与均匀性的影响。
3. 固定其他参数，验证单变量补偿。
4. 再逐步引入第二个参数，并评估交互作用。
5. 最后才考虑 Recipe 与 Offset 的联合优化。

如果 Offset 是设备内部已经闭环控制的参数，不应在未明确控制权归属前，由外部模型重复补偿。

## 七、在线执行与设备约束

建议将在线闭环实现为一个明确的状态机，避免同一片晶圆的量测结果被重复使用，或在设备状态不适合时下发参数。

等待量测完成

校验量测有效性与晶圆追溯

预测质量并生成候选补偿

检查设备状态、配方权限、工艺窗口与变化幅度

验证通过

按授权模式审批或执行

验证失败

拒绝自动补偿并告警

确认参数已生效并等待下一次量测验证

至少要有以下执行约束：

* 参数必须位于批准的最小值与最大值之间。
* 每次变化量和累计变化量必须受限。
* 只允许在指定产品、设备、腔体、工艺步骤和 Recipe 版本上执行。
* 设备必须处于允许修改参数的状态。
* 参数下发失败、超时或状态不明时，不能盲目重复执行。
* 任何参数修改都必须具有唯一控制任务 ID 和完整审计记录。
* 若预测超出适用范围或数据质量不合格，应退回经过验证的基线策略。
* 当后续量测恶化或质量指标超限时，应停止自动补偿并触发既定异常处理流程。

回退策略也必须区分两件事：停止继续自动修改，以及把参数恢复到上一个批准值。后者并不总是安全，因为设备可能已经加工了部分产品，或者当前 Recipe 版本已经发生变化。恢复操作需要根据设备状态和工艺规则单独定义。

## 八、建议的工程实施顺序与验收标准

为了降低上线风险，可以将项目拆成四个交付阶段。

|   阶段   |   主要工作   |   验收条件   |
| --- | --- | --- |
|   1. 数据基建   |   关联晶圆、加工记录、Recipe、量测点和 Offset 变更记录   |   能完整追溯量测结果对应的加工过程   |
|   2. 离线建模   |   训练厚度偏差与均匀性模型，对比传统基线   |   独立测试集表现达到预先定义的预测要求   |
|   3. 影子运行   |   在线生成补偿建议，但不自动下发   |   能记录建议、基线对照、拒绝原因及后续实际结果   |
|   4. 有限自动闭环   |   对指定产品、设备及参数开放受控执行   |   实际量测改善，工艺规格、稳定性和安全要求均满足   |

每个阶段都应由工艺、设备、量测、自动化和软件团队共同验收。具体阈值不能凭空设定，应根据工艺规格、基线表现和批准的风险标准确定。

### 建议的第一版技术栈

结合你现有的 Java / Spring Boot / 工业设备接入背景，可以这样分工：

* Java / Spring Boot： 加工与量测数据关联、R2R 任务编排、参数审批、设备接口、执行状态和审计。
* Python + XGBoost： 离线训练、模型评估和在线预测。
* 数据库： 保存加工记录、量测结果、参数版本、补偿决策和执行审计。已有制造数据平台可以继续使用，不必为模型单独重建整套数据基础设施。
* 设备接口： 根据设备能力使用 EAP、SECS/GEM 或厂商接口完成数据读取和受控参数修改。
* 控制器： 保留设备原有的工艺限制、互锁和安全保护。

模型训练服务和设备执行服务应分开部署。预测模型不应该拥有绕过审批、互锁或参数边界的权限。

## 九、最终推荐的控制策略

对于你的场景，我建议采用下面这条路线：

第一步：建立传统 R2R 基线

先验证厚度偏差与主要补偿参数之间的关系，明确补偿方向、灵敏度和允许调整范围。

第二步：训练两个 XGBoost 模型

分别预测平均膜厚偏差与片内均匀性，检验非线性模型是否优于传统基线。

第三步：先开放一个主补偿变量

先控制经过验证的 Recipe 或 Offset 参数之一，避免多个参数同时变化造成难以归因的质量波动。

第四步：再增加受约束优化

只有在模型预测可靠、参数影响得到验证、工艺约束明确后，才考虑联合优化 Recipe 与 Offset。

有一个关键问题会直接决定模型应该怎样训练：你的历史数据中，Recipe / Offset 参数是否曾经发生过变化，并且每次变化之后都有对应的薄膜厚度和均匀性量测结果？

如果有，这些记录可以帮助建立参数—结果模型，但仍需处理历史操作策略带来的偏差；如果从未变化，就需要先通过工艺标定或经过批准的实验设计获得参数影响信息，不能指望 XGBoost 单靠静态历史数据推断出可靠的补偿规律。
