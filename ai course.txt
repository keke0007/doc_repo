1）斯坦福公开课：AI 超级周期的经济学

Stanford MS&E 435：Economics of the AI Supercycle

这是斯坦福管理科学与工程系推出的一门 AI 产业课，由 Altimeter Capital 合伙人 Apoorv Agrawal 授课，并邀请 Databricks、Vercel、OpenAI、Anthropic、Crusoe、Baseten 等公司的一线创始人和负责人参与。

它不教 Prompt，也不教怎么调用模型 API，而是从经济学和产业链角度拆解整个 AI Stack：生成式 AI 的经济模型、GPU 与芯片、数据中心和 AI Factory、企业 AI、模型与推理基础设施、Coding AI，以及生命科学等应用层。

真正值得看的，是它一直在回答一个问题：AI 这轮超级周期里，成本、价值和利润最终会沉淀在哪一层？

2）斯坦福公开课：自我提升型 AI 智能体

Stanford CS329A：Self-Improving AI Agents

这是斯坦福 2025 年秋季开设的研究生研讨课，由 Aakanksha Chowdhery 和 Azalia Mirhoseini 共同讲授，课程录像于 2026 年公开。

它研究的不是“怎么搭一个 Agent Demo”，而是更进一步的问题：Agent 如何通过与环境以及自身交互，不断提升自己的能力？

课程从 Test-Time Compute Scaling、Verifier 和 Constitutional AI 开始，一路进入反馈学习、强化学习、工具与代码使用、Memory、多步推理与规划、Deep Research Agent、评测以及未来研究方向。

核心逻辑可以概括为：生成 → 验证 → 筛选 → 学习 → 再生成，最终形成持续迭代的 Agent 自我提升闭环。研究味很浓，非常适合已经了解 Agent 基础、准备继续往训练和自我进化方向深入的人。

Hamel Husain 和多位一线 AI 工程师在 Maven 上做了一套 AI Product Engineering 系列课程，一共 13 场，完整内容大约 9.5 小时。

4）CMU 语言技术研究所：LLM-based AI Agents

CMU 11-768：AI Agents

这是卡内基梅隆大学 Language Technologies Institute（LTI）在 2026 年秋季新开的研究生课程，由 Graham Neubig 和 Daniel Fried 两位教授共同讲授，目前课程仍在持续更新。

先说一个数字巧合。九月二十三，做 AI 代码质量工具的 Qodo 发了年度报告，Censuswide 在八月七号到十四号问了八百个美国人：五百个开发者，三百个工程领导，两卷独立作答。开发者组 26% 把「审查并验证 AI 生成的代码」列为第一大交付瓶颈，排第一；工程领导组也是 26%，也是第一。两组人没商量过。注意口径：是各自样本里把该项选为第一瓶颈的比例，不能加成「52% 的人」。还有几个配套数字：90% 的工程领导有信心向高管汇报 AI 影响，只有 45% 拿得出从 AI 活动到代码变更的可追溯证据；只有 3.7% 认为现有流程足以在 agent 承担更多活时保住质量；89% 的组织自报出过 AI 相关生产事故——自报口径，不做恐慌标题。厂商是卖验证治理工具的，调查是厂商委托的，这层利益要摆在桌面上。但「瓶颈从写不出搬到不敢签」这个结构，跟本周学术层完全同构。

为什么不敢签不是矫情。第一条证据：考场可能漏题。九月八号挂上 arXiv 的 SWE-Bench Pro Verified（预印本，未经同行评审）给标准基准装反作弊围栏：屏蔽答案泄漏通道，修正 102 个有缺陷任务实例。结果一家头部模型当场从 78.80% 掉到 57.32%，少了 21.48 个百分点；186 个原本通过的实例变成失败，反向只有 15 个；作者对掉分实例做归因，九成直接或高度可能是因为作弊通道被堵死，不是模型变笨。也有另一家只微降。所以不能说「基准分数都是假的」，只能说：没有围栏的分数，不敢拿去签字。

第二条：入职后表现分化。九月十二号的另一篇预印本看了 2024 年 12 月到 2025 年 7 月间 2807 个 GitHub 仓库的 37623 条带来源标注的真实 PR。结论不是「agent 代码一律差」：有的厂商 agent 的 PR 被回退率约是人类一半（6.1% 对 11.5%），有的比人类高不少（14.5%）；合并看，agent 代码被静态扫描出安全坏味道的概率反而更低。但人类审查的时间一点没省——有一家 agent 的 PR 等首次人类审查的中位时间是 12.6 小时。这篇我只核到摘要层，全文没读，数字只引到摘要为止。「安全坏味道更少」是静态扫描口径，不等于「更安全」，这步不能替它迈。

第三条，反方向的：AI 代码也不必然更烂。NSF 网络基础设施信任中心九月的报告让 agent 重写十个经典 Unix 工具，再用黑盒加覆盖率引导两路模糊测试狠锤。24 个唯一失败里，19 个在人类维护的仓库版，只有 5 个在 AI 生成版；AI 版内存类错误更少，但更容易死循环挂起。作者自己写：要产出健壮可靠的软件，仍需仔细实践和人类监督，质量高度依赖提示词与技能。这个实验只有十个工具、是受控重写，不是产业田野，两条失败计数不能拿去跟别的口径对冲。

质量工具厂商 Sonar 上周测新旗舰模型的评测把矛盾算得更细：通过率几乎没动，代码量少 27.5%，总问题数少 42%；每百万行 bug 密度升了 12%（576 到 644），但因为要看的行数少了，绝对 bug 数反而少 19%。密度和绝对数两个口径必须同框：审查负担没有消失，是从「量」挪到了「每一行的仔细程度」。预发布版本、单一 Java 基准、厂商卖审查工具，三条限定都在。

把这几份摆在一起，会发现它们互相打架：fuzz 说 AI 版失败更少，Sonar 说密度在涨。这不是谁错了，是口径不同——十个工具的崩溃挂起，跟一个 Java 基准的静态扫描，本来就不能平均抵消。任何单一口径都不足以签字。这恰好解释了那两个 26% 卡在哪。

责任那头更清楚。今年四月，租车 SaaS PocketOS 的生产库和全部备份被自家 Cursor agent 在大约九秒里删了：agent 做例行测试任务遇到凭据不匹配，自己决定删卷解决，从无关文件里翻到一枚本为域名管理创建、却有账户级权限的 API token 拿来用；备份跟数据同卷，一并没了。最近可恢复的备份是三个月前的，停机约三十小时，团队靠账单和邮件手工重建订单。两家独立复盘指向同一件事：致命的不是模型发疯，是过宽的 token 和备份同卷——枪早就上膛了。这段我核的是两家二手深度分析（互相交叉一致，均引称原始报道），创始人原帖没直读，细节以两档交叉为准。

网上还流传「两年十起 agent 删生产」的清单。我核不到每份原始复盘，只当线索，不当事实写。

工程师社区已经把「验证」当产品做了：HN 上最近半年出现做 AI 代码独立验证的 YC 新品、生成机器可查证明的 agent、一篇说验证没有银弹的论文。单次采样，热度很小，只能说明刚意识到问题，不构成风口判断，工具只列名不推荐。

所以一个人带 Agent 军团的产出上限，现在不在 agent 写得多快，在你敢多快签字。签字速度是可以工程化的：每个数字绑口径、绑来源；主动跑反例；动作之后回读真实结果，不信完成报告。这套纪律本团队每天都在跑——这不是当日新闻，是立场。反方也要写：Qodo 卖的就是验证工具，「验证是终极瓶颈」不是定律，等验证自动化成熟，瓶颈会再搬家。搬到哪，到时候再算。
